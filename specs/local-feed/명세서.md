- 장면 (02·기능_배정의 장면 한 줄, 사용자가 맞다고 한 것 또는 고친 말): 근처의 도서관을 찾고 방문하고 싶어 하는 사람이, 가기 전에 집에서뿐 아니라 밖에서도 "이 도서관엔 어떤 이웃이 어떤 책을 읽나" 미리 구경할 때 연다. 찾는 시간을 줄인다("찾는 시간을 절약할 수 있지요"). 광장을 닫을 때는 읽을 책이 정해져 있으면 되고, 도서관은 나중에 고른다("불편할 건 없지. 나중에 가고 싶을 때 가겠지 그럼"). 지금은 네이버·구글 같은 검색창에서 찾는다("검색해서 찾지").

## 4. 결정 기록

### 결정 1. 광장 카드의 글자 양: 이미지만 (채택)
- 고른 것: 이미지만 — Pinterest처럼 카드에 글자를 얹지 않는다 (Claude 추천은 '이미지 + 책 제목 한 줄'이었음)
- 이유: "이미지만으로도 충분히 책 표지이기 때문에 무슨 책인지 알 수 있고, 그게 더 깔끔해요"
- 포기한 것: 무슨 책인지는 카드를 눌러 봐야 안다
- 겹침일 때 따른 쪽과 이유: Pinterest 쪽 — 깔끔해서
- 이미지가 책 표지가 아닐 때(직접 찍은 사진·단색): 카드에는 책 제목을 붙이지 않고, 눌러서 상세에서 책을 안다 (Claude 추천과 같음 — 이유: "눌러 보지 않아도 어차피 이미지만 봐도 알 수 있으니까요" — 책이 안 보이는 사진·단색이면 궁금한 사람은 카드를 눌러서 본다. 포기한 것: 한 번 더 눌러야 한다 / 얻는 것: 광장이 깔끔하게 남는다) (D가 2026-11-12에 "피드 카드는 제목 없이"로 정해서 다시 물음. 앞 결정은 '이전 버전')

### 결정 2. 단색 배경 카드의 글자: 좋은 문장을 가운데에 크게 (채택)
- 고른 것: Fable처럼 단색 배경 가운데에 좋은 문장을 크게 쓴다 (Claude 추천과 같음)
- 이유: "눈에 더 잘 들어와요" (광장을 구경할 때)
- 포기한 것: 긴 문장은 카드에서 잘린다
- 겹침일 때 따른 쪽과 이유: 겹침 아님 (Fable에만 있음)
- 2026-11-12 D가 DESIGN.md(C-48)에서 '글자는 이미지 안, 15px 굵게, 이미지 색에 맞춰 자동 대비'로 정했다. '크게'는 이 크기 안에서 가운데에 두는 것으로 읽는다(세부에서 시안으로 확인).

### 결정 3. 카드에 쓴 사람: D가 정함 (작게 보임)
- 2026-11-12 D가 "작성자만 작게 보인다"로 정했다(C-46 D6, 기능_배정.md). 사용자가 고른 '안 보임'은 '이전 버전'에 남겼다.
- ⚠ 같은 날 DESIGN.md(C-48)는 게시물 카드에서 '제목·하트·작성자 줄이 있는 카드'를 탈락시켰다. D 문서끼리 다르므로 D가 정한다(사용자의 원래 선택 '안 보임'은 DESIGN.md와 같다).

### 결정 4. 카드에 공감 수: 안 보임 (채택)
- 고른 것: 광장 카드에는 공감 수를 보이지 않고, 눌러서 상세를 볼 때 보인다 (Claude 추천과 같음)
- 이유: 공감이 0인 글이 카드에 '0'으로 보이면 쓴 사람은 "기분이 좋지는 않겠죠"
- 포기한 것: 인기 있는 글을 카드만 보고 한눈에 알기 어렵다
- 겹침일 때 따른 쪽과 이유: Pinterest 쪽 — 공감 0이 드러나지 않아서
- 2026-11-12 D도 "좋아요 수는 상세에 둔다"로 정했다(C-46 D6). 사용자 결정과 같다.

### 결정 5. 글 쓰는 순서: 사진부터 (채택)
- 고른 것: 사진·표지·단색 고르기 → 글자 → 감상 → 책·도서관 (Claude 추천은 '책부터'였음)
- 이유: "직관적으로 보기 좋아서요" — 장면: 책을 검색하는 단계가 맨 앞에 없어서 시작이 가볍다
- 포기한 것: 표지는 책을 고른 뒤에야 나온다
- 겹침일 때 따른 쪽과 이유: 레퍼런스 없음

## 6. 다른 기능과 닿는 곳

<!-- 기능_배정.md의 'D가 정한 것'을 그대로 옮기고, 다른 기능과 주고받는 것을 적는다. 계약은 D가 정한다. -->

**D가 정한 것** (`../team/기능_배정.md` B절 원문, 2026-11-12 판)
- 게시물은 올리기를 눌러야 공개된다. 철회하면 바로 목록·직접 주소에서 안 보인다. 신고·운영자 숨김이 생기기 전(M1)에는 파일럿 참여자에게만 보인다.
- 게시물 이미지는 직접 찍은 사진 / 책 표지 / 단색 중 하나이고 글자를 얹을 수 있다. 본문(감상·좋았던 문장)은 선택이며 **제목·본문 없이 이미지만으로도 올릴 수 있다.** 사진의 위치 정보는 올리기 전에 지운다.
- 표지가 없으면 제목·저자 표지를 만들거나 사진·단색으로 대신한다. 표지는 네이버 책 검색 API로 ISBN을 조회한다(Q-39, 한도·이용 조건은 Q-41에서 D가 확인).
- 광장은 방문 페이지의 피드이며 도서관별 2열 메이슨리, 최신순이 기본이고 인기순은 공감 수가 신호다(집계 기준은 Q-31). M1 카드는 게시물 카드만이다(방명록·모임·방문 기록 카드는 M2). 빈 광장에는 가짜 게시물을 만들지 않는다.
- **피드 카드는 제목 없이 이미지 중심**이고 작성자만 작게 보인다. 좋아요 수는 상세에 둔다(C-46 D6, 02 LOCAL-03). 책 제목 정보나 이미지 위 글자 넣기를 없앤다는 뜻은 아니다.
- 목록에서 **길게 누르기(웹은 호버 시 점 세 개)** 메뉴: 책 제목 검색 / 저자로 검색 / 공유 / 좋아요 / 북마크(개정 명세 §1·§2). 책 제목 검색 자리는 '도서 없음(구매 링크)'로 바꾸기로 했고 의미는 미결이다(C-46 D1·§8-4). 공유는 시스템 공유창, 쓸 수 없으면 링크 복사(D2). 북마크는 카드 밖에 상시 버튼을 두지 않고, 상세에는 별도 북마크 버튼을 둔다. 북마크·좋아요 **모음**(내 정보 3탭)과 팔로우는 별도 작업이고 담당 미배정이다(C-46 F4).
- 상세의 넓은 화면은 왼쪽 큰 이미지, 오른쪽 반응·작성자·본문·댓글 영역을 목표로 한다(사용자 첨부 C-28, 개정 명세 §2). 모바일 배치는 시안에서 정한다.
- **글쓰기 버튼은 SNS 안의 +/연필**이다(하단 탭에 없음). 형태·위치는 세부 명세에서 정하고, 실제 시안을 사용자에게 보여 주는 검토가 필수다(C-46 F3). 헤더 오른쪽 연필은 추천안일 뿐 확정이 아니다.
- D3~D6(방문 기록 북마크·정렬·재공개 표현·카드 표현) 화면도 시안 검토가 필수 관문이다.
- **게시물 상세는 핀터레스트 방식**이다: 누르면 그 게시물의 본문이 펼쳐지고 그 주변에 다른 피드가 이어진다. 상세에서 대여 경로(소장·대출 가능 조회)가 구매보다 먼저 나오고, 구매는 예스24로 연결한다(예스24 Open API 확인됨, 구매 링크 생성 방식은 Q-41). 대출 가능은 "어제 기준"처럼 기준일과 함께 보여 준다.
- 같은 책 이어 읽기: 상세에서 같은 책을 다룬 다른 공개 게시물(다른 도서관 포함)로 이어진다. 다른 도서관 게시물을 열어도 방문 중인 도서관의 화면 느낌을 유지한다.
- 공감은 게시물당 한 번이고 취소할 수 있다. 비공개 기록·대출은 인기글·추천 집계에 쓰지 않는다.

**다른 기능과 주고받는 것**
