## 1. 이 세부에서 정한 결정

<!-- 확인 목록에서 '확인'이 된 것만. 이유는 사용자의 말을 그대로. 장면 + 얻는 것 + 포기한 것이 모두 있으면 완료. -->

### 결정 1. "도서관 찾기"를 누르면 열리는 화면: 위에서 내려오는 반쪽 창 (후보 A)
- 고른 것 (사용자 말): "난 A위에서 내려오는게 좋다고 생각해". 창 색은 "검색창 검정색은 좀 아닌거같아" → 초록빛 회색(fill3)으로 바꿨다가, 다시 보고 "일단 여기서 선 있어야하고 하얀색이여야 한다 생각" → 하얀 창(paper) + 입력칸 테두리 선. 결과 줄 앞 핀 그림은 "여기 핀버튼 없애줄래?" → 뺌
- 이유 (사용자 말): "굳이 화면을 바꿔가며 해야할까?"
- 포기한 것 (반영 후 "불편해지는 점", 사용자 말): 없음(사용자). 장면(제주시 처음, "연동" 입력)으로 한 번 더 물었을 때: "B나 C보던 덜 불편하면 된거 아닐까"
- 차선: 차선 없음 (사용자: "C가 제일 별로였던거같아"). 탈락: B 다른 색 전체 화면(Claude 추천이었음) — 사용자: "B는페이지 넘어가는게 불편하고", C 지도 위에서 바로 찾기 — 사용자: "C는 그냥도 별로고 검색했을때 검색어가 덜나와서 완전 불편할거같아"
- 유저 플로우: "도서관 찾기"를 누르면 → 하얀 창이 위에서 반쯤 내려오고 아래 지도는 흐리게 남음 → 지역·도서관 이름을 치면 창 안에 맞는 목록 → 하나를 누르면 창이 올라가고 지도가 그곳으로 옮겨감(고른 도서관 핀은 테두리) → 지도 아래 "현재 위치로"로 돌아옴. 창 밖 흐린 지도를 누르면 창이 닫힘. 사용자는 지도 화면을 떠나지 않고 다른 지역을 찾는다

### 결정 2. 위치도 못 쓰고 지도도 안 뜰 때: 지도 홈 모양 그대로, 지도 자리에 도서관 목록 (후보 C)
- 고른 것 (사용자 말): "C가 좀전 화면과 비슷하고"
- 이유 (사용자 말): "장점만 남은느낌이라"
- 이유 더함 (사용자 말): "A와B에 비해 덜 복잡해보인다"
- 포기한 것 (반영 후 "불편해지는 점", 사용자 말): 없음(사용자) — "아무래도 전에 말했던 이유와 비슷할수밖에없어 덜복잡하니 덜어렵지". 후보에 적힌 포기(목록 칸이 조금 좁음, 지역을 바꾸려면 글자를 쳐야 함)는 사용자가 따로 말하지 않음
- 차선: 차선 없음. 탈락: A 위에 지역 고르는 칸 + 목록, B 지역부터 고르고 목록
- 유저 플로우: 위치도 지도도 못 쓰면 → 맨 위 검색창·"도서관 찾기"는 그대로, 지도 자리에 "지도를 불러오지 못했어요 · 다시 해 보기"와 시작 지역 도서관 목록(이름 · 동 · 오늘 운영시간/휴관) → 다른 지역은 "도서관 찾기" 하얀 창에서 찾아 누르면 목록이 바뀜 → 도서관을 누르면 방문 페이지 → "다시 해 보기"로 지도가 뜨면 지도 홈. 아래 가운데 "위치 허용하기"는 계속 보임

### 결정 3. 가까운 곳에 도서관 핀이 많아 겹칠 때: 몰린 곳은 숫자 동그라미 하나로 (후보 A)
- 고른 것 (사용자 말): "A가"
- 이유 (사용자 말): "아무래도 지금 지도앱들과 비슷해서 사람들이 익숙할거같아"
- 포기한 것 (반영 후 "불편해지는 점", 사용자 말): 몰린 곳은 한 번 더 눌러야 어떤 도서관인지 앎 — "잘못눌러서 잘못확인하는 경우떄문에 조금 번거롭더라도 확실하게 하는방법이 좋다 생각해"
- 차선: 차선 없음. 탈락: B 가까운 2곳만 이름표·나머지 작은 핀, C 작은 핀 + 아래 도서관 카드 줄
- 값: 동그라미 지름 38px, fill1 + paper 테두리 3px, 안에 개수(15px), 아래 "도서관 n곳" 이름표. 혼자 떨어진 도서관은 평소 핀(이름 + 거리)
- 유저 플로우: 앱을 켬 → 몰린 곳은 숫자 동그라미 → 동그라미를 누르면 지도가 그곳으로 커지며 핀이 이름·거리를 달고 나뉨 → 핀을 누르면 방문 페이지. 지도를 멀리 볼수록 더 크게 묶이고, 가까이 볼수록 풀림

## 2. 유저 플로우 (정상 흐름)

<!-- 결정대로 Claude가 쓴다. 한 줄에 한 동작. 모든 문장에 누가(주어)와 무엇을(목적어). 시안 맨 아래 '처음부터 끝까지 이렇게 써요'와 같아야 한다. -->

1. 사용자가 앱을 켜면 동네한권이 현재 위치 주변의 지도와 도서관 핀(이름·거리)을 보여 준다.
2. 사용자가 핀을 누르면 동네한권이 그 도서관 방문 페이지(B의 화면)로 화면을 바꾼다. 방문 페이지가 아직 없으면 계약서 모양의 빈 화면 + `TODO(연결): B`.
2-1. 도서관이 몰려 핀이 겹치면 동네한권이 그 핀들을 숫자 동그라미(몇 곳인지) 하나로 묶어 보여 준다.
2-2. 사용자가 숫자 동그라미를 누르면 동네한권이 지도를 그곳으로 크게 보여 주고, 핀을 이름·거리와 함께 나눠 보여 준다.
3. 사용자가 맨 위 검색창을 누르면 동네한권이 책 검색 화면을 연다(C `book-search`).
4. 사용자가 지도를 끌어 옮기면 동네한권이 "이 지역에서 다시 찾기" 버튼을 보여 주고, 사용자가 누르면 그 지역 도서관 핀을 다시 보여 준다.
5. 사용자가 "도서관 찾기"를 누르면 동네한권이 지도 위로 하얀 창을 반쯤 내려 보이고, 아래 지도는 흐리게 남긴다.
6. 사용자가 지역이나 도서관 이름을 치면 동네한권이 맞는 지역·도서관을 창 안 목록으로 보여 준다.
7. 사용자가 목록에서 하나를 누르면 동네한권이 창을 올리고 지도를 그곳으로 옮긴다(고른 도서관 핀은 테두리).
8. 사용자가 창 밖 흐린 지도를 누르면 동네한권이 창을 닫는다.
9. 위치도 못 쓰고 지도 그림도 안 뜨면 동네한권이 맨 위 검색창과 "도서관 찾기"는 그대로 두고, 지도 자리에 "지도를 불러오지 못했어요 · 다시 해 보기" 한 줄과 시작 지역(시·군·구)의 도서관 목록(이름 · 동 · 오늘 운영시간)을 보여 준다.
10. 사용자가 "도서관 찾기" 창에서 다른 지역을 누르면 동네한권이 목록을 그 지역 도서관으로 바꾼다.
11. 사용자가 목록의 도서관을 누르면 동네한권이 그 도서관 방문 페이지로 화면을 바꾼다.
12. 사용자가 "다시 해 보기"를 눌러 지도가 뜨면 동네한권이 지도 홈으로 돌아간다.
13. 보는 위치가 바뀐 동안 동네한권이 지도 아래 가운데에 "현재 위치로" 버튼을 보여 주고, 사용자가 누르면 현재 위치 주변으로 돌아온다.

## 6. 다른 기능과 닿는 곳

- 지도는 카카오맵(앱 WebView+JS SDK, 웹 JS SDK 직접). 데포르메 구현 방식은 미정(Q-30). 지도가 안 뜰 때는 도서관 목록으로 같은 여정.

- 위치를 쓸 수 없을 때의 임시 시작 위치: 기본 도서관이 있으면 그 주변, 없으면 파일럿 지역 중심(D, Q-17 임시).
- 시군구 도서관 목록은 06 #10의 `dtl_region`을 쓴다(D 결정 12).
- 맨 위 검색창을 누르면 C(`book-search`)의 책 검색 화면. 검색 진입 화면은 항상 전국 기준(D 결정 10 영향).
- 핀을 누른 뒤의 전환·방문 페이지·도서관 기본값·방문 멘트 카드는 B(`local-feed`, VISIT-2)가 정한다(C-61, D 결정 1.2·1.2-1). 큰 틀의 결정 14·15는 'B로 인계'.
- 정확한 위치·집 주소·보는 위치는 저장하지 않는다.
- 다른 도서관이나 지역으로 옮길 때 이전 요청의 늦은 응답이 화면을 덮지 않는다(AC-RACE).
