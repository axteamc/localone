# 버그 리포트

> 상태: **운영 문서 — 집계 표만 유지**. 담당: 발견자가 이슈로 올리고 D가 표를 갱신한다. 버그 원본은 GitHub 이슈(`bug` 라벨, 양식 `.github/ISSUE_TEMPLATE/bug_report.yml`)이고 이 문서에는 **집계와 마일스톤 검수 결과**만 남긴다. 사용자 결정이 필요한 버그가 아니면 담당자에게 `to:<역할>` 이슈로 바로 보낸다(팀 규칙 10절).

## 작성 규칙

1. 버그 하나 = 이슈 하나. 제목은 `[버그] <화면·기능>: <한 줄 증상>`.
2. 반드시 적는다: 어디서(화면·`파일:줄`), 기대(근거: 02의 AC·요구사항 ID 또는 명세서 문구), 실제(실제 출력·화면 캡처), 재현 순서, 환경(웹·Android·iOS와 OS·앱 버전), 심각도.
3. 심각도: **치명**(남의 데이터 노출·데이터 손실·로그인 불가) / **높음**(핵심 여정 중단) / **보통**(우회 가능) / **낮음**(문구·여백).
4. 남의 데이터가 보이는 문제(A↔B 격리), 철회·숨김 후 공개 노출은 항상 **치명**이다.
5. 고친 뒤에는 그 버그를 잡는 테스트가 있는지 적고 이슈를 닫는다. 테스트가 없으면 이유를 적는다.
