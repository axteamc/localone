## 1. 작업자와 기록 근거

작업일지는 사람이 따로 쓰지 않고 **git 커밋과 PR 기록**에서 뽑는다. 작성자 계정으로 작업자를 나눴다. 이 저장소는 공개라서 실명은 쓰지 않고 역할과 계정만 쓴다.

| 역할 | GitHub 계정 | 담당 기능 | 구분 근거 |
| --- | --- | --- | --- |
| A | jaehyeon02 | 도서관 방문 `library-visit` | `spec/library-visit` 브랜치·PR #2 |
| B | cybp12-rgb | 지역 SNS `local-feed` | `spec/local-feed` 브랜치(PR 아직 없음) |
| C | AXLeeTaekyung | 도서 탐색 `book-search` → 반납 비서 | `spec/book-search` 브랜치·PR #17 |
| D | Hunseokc | 기반·계정·계약·통합 `core` | 기능 배정표, PR #1~#18 |

- 역할은 "그 계정이 실제로 하고 있는 기능" 기준이다. 정해진 사람별 역할과 B·C가 어긋나 있다는 점을 2026-11-12에 확인했지만, 역할 교체는 **하지 않기로 했다**(교체 이슈 #19·#20은 닫음). 계정과 역할이 다르면 이 표만 고치면 집계를 다시 뽑을 수 있다.
- 시각은 모두 KST다. "저장소 기록 없음"은 일을 안 했다는 뜻이 아니라 git에 남은 기록이 없다는 뜻이다(회의·시안 보기 등).

## 5. 갱신 방법

- 하루가 끝나면 Claude에게 "작업일지 갱신해줘"라고 한다. Claude가 아래 두 명령으로 그날의 커밋·PR을 뽑아 §2·§3에 한 칸을 추가하고 §4의 칸을 채운다.
  - `git log --branches --remotes --no-merges --since=<날짜> --format='%ad|%an|%s' --date=format:'%m-%d %H:%M'`
  - `gh pr list --repo axteamc/localone --state all --json number,title,author,createdAt,mergedAt`
- 커밋 메시지에 없는 일(회의, 시안 확인, 막힌 점)은 §4의 칸에 사람이 한 줄 적는다.
- 새 PR·머지·막힘이 생기면 §3 "열려 있는 PR" 표도 맞춘다.
