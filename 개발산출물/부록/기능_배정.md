D의 결과 알림 뒤에도 실제 착수 관문을 확인한다. 기존 발행 Step은 재제출하지 않는다.

## A — 홈 화면 `library-visit` (파사드 홈 + 홈 하단 창)

> **2026-11-17 홈 시안 C(사용자 결정, 코드 레포 C-65):** 홈에서 지도를 뺐다. 홈은 현재 위치 `+` 기점을 가운데 두고 주변 도서관을 방향별 블록으로 보인다. 아래 줄 중 지도·핀·지도 끌기·"이 지역에서 다시 찾기"·지도가 안 뜰 때 목록은 **이전 기준**이고, 지금 기준은 `contracts/library-visit.md` VISIT-1(파사드 판)이다. 위치·"도서관 찾기"·"현재 위치로"·"위치 허용하기"·누르면 방문 페이지·하단 창은 그대로다.

> 2026-11-16(C-61): 도서관 방문 페이지는 B로 옮겼다. A는 방문 페이지의 머리·전환·피드 자리·빈 피드·도서관 기본값·방문 멘트를 **기획하지도 만들지도 않는다.** 사용자가 방문 페이지 이야기를 꺼내면 "그 화면은 다른 담당이 맡아요" 한 줄로 넘기고 홈 화면 질문으로 돌아간다. VISIT-1 명세서에 이미 적힌 방문 페이지 쪽 결정(도서관 기본값의 ⋯ 메뉴 자리, 방문 멘트 카드)은 지우지 않고 그대로 두며, B가 이어받아 쓴다(다시 묻지 않는다). 방문 페이지에 대해 D가 정한 것은 B절로 옮겼다.

**D가 정한 것**
- 지도는 데포르메된 미니멀 지도이고 거리 표기 수준의 정적 안내다. 길 안내를 하지 않는다. **지도 제공자는 카카오맵**이다(앱은 WebView+JS SDK, 웹은 JS SDK 직접, 2026-11-12, Q-12). 데포르메 구현 방식은 아직 미정(Q-30)이며 지도가 안 뜰 때는 도서관 목록으로 같은 여정을 제공한다.
- 도서관 핀을 누르면 **그 도서관의 방문 페이지(B의 화면)로 화면이 바뀐다.** 지도 위 시트나 미리보기 카드가 아니라 페이지 전환이다. A는 핀을 누르면 넘어가는 것까지 만들고, 방문 페이지가 아직 없으면 계약서 모양의 빈 화면 + `TODO(연결): B`로 둔다. 다른 도서관을 고르거나 전체 동네로 돌아갈 때 이전 요청의 늦은 응답이 화면을 덮지 않는다(AC-RACE).
- **홈 하단 창(VISIT-1b, 2026-11-16 D 결정으로 M2에서 당김)**: 지도 아래에서 위로 올려 보는 창이다. "자주 방문하는 도서관의 피드", "인기 도서 목록" 같은 것으로 채운다(D의 말, 예시). 무엇을 넣을지·순서·배치·올리는 동작은 기획에서 레퍼런스를 받아 정한다. 여기 보이는 게시물 카드의 **모양은 B가 정한 것을 그대로 쓴다**(새로 디자인하지 않는다). 카드를 누르면 B의 게시물 상세로, 책을 누르면 C의 책 상세로 넘어간다. 게시물·인기 도서·방문 횟수 값은 계약서 모양의 가짜 값 + `TODO(연결)`로 먼저 만든다. "내 최근 독서 기록"(02 VISIT-06의 한 갈래)은 독서 기록(M2)이 없어 이번에 넣지 않는다. 빈 가짜 화면을 만들지 않는다.
- **지도 기준은 항상 현재 위치**다. 집·동네를 저장해 고정하지 않는다(2026-11-13, C-54). 위치를 쓸 수 없으면 동네를 묻지 않고 임시 시작 위치에 지도를 열고 지도 아래에 "위치 허용하기" 버튼을 둔다. 지도를 끌어 옮긴 뒤 "이 지역에서 다시 찾기"나 도서관 검색으로 보는 위치를 잠깐 바꿀 수 있고, 저장하지 않으며 앱을 다시 켜면 현재 위치다. 정확한 위치·집 주소·보는 위치는 저장하지 않는다.
- 색·곡률은 `디자인_기준.md`의 토큰으로 쓴다. 지도의 핀 색은 M1에서 기본 색이다.
- 지도에 어떤 도서관까지 보여 줄지(내 주변 반경과의 관계)는 D가 정한다(Q-51).
- **하단 탭은 홈 / 독서 기록 / 대출·반납 / 내 정보** 네 개를 이 순서로 둔다. 글쓰기는 하단 탭에 없고 SNS(방문 페이지 피드) 안의 +/연필 버튼이다(형태·위치는 B의 세부 명세에서 정함). 내 발자취는 독서 기록의 도서관별 보기로 통합하므로 홈·방문 페이지에 만들지 않는다(개정 명세 §4, Q-44 해소). **하단 탭 틀은 D가 만든다(2026-11-16 D 결정, `contracts/core.md` K13). M1에는 홈·대출·반납·내 정보 세 개만 보이고, 독서 기록 탭은 독서 기록(M2)을 시작할 때 두 번째 자리에 넣는다.**
- 방문 페이지(머리·전환·피드·카드·상세·글쓰기)는 전부 B가 정하고 만든다. 방문 페이지에는 검색창을 두지 않는다(B절). 책 검색 입구는 지도 홈 맨 위의 검색창 하나다: 평소에는 항상 책 검색(C의 검색 화면)이고, 특정 버튼을 눌렀을 때만 도서관 검색이며 그 화면은 책 검색과 확연히 다르게 보인다. 그 버튼의 위치·모양은 D가 시안으로 정하는 중이다(2026-11-13, C-54). 도서관별 추천(C-46 E3)은 M1에 여는 화면이 없어 쓰지 않는다.

**기획에서 정할 것**
- 지도에 어떤 랜드마크·도로를 보여 줄지 (VISIT-1)
- 홈 하단 창에 무엇을 넣을지와 순서(자주 방문하는 도서관의 피드, 인기 도서 목록 등) (VISIT-1b)
- 홈 하단 창이 평소에 얼마나 보이고, 위로 올리면 어디까지 올라오며 지도는 어떻게 되는지 (VISIT-1b)
- 내용이 없을 때(방문한 도서관이 없음·게시물 없음·로그인 안 함) 그 자리에 무엇을 보여 줄지 (VISIT-1b)

## B — 도서관 방문 페이지(SNS 화면) 전체 `local-feed`

> 2026-11-16(C-61): 방문 페이지의 틀(VISIT-2)을 A에게서 받았다. 핀을 눌러 들어온 뒤 보이는 것은 머리부터 피드·상세·글쓰기까지 전부 B다.

**D가 정한 것**
- **방문 페이지의 틀(VISIT-2)**: 아래 네 줄은 2026-11-16에 A절에서 옮겨 온 것이다(내용은 그대로). 자세한 값은 코드 레포 `개발산출물/명세/VISIT_LOCAL_D결정.md` 1.1(결정 3·7·8 보완, 결정 10)·1.2·1.2-1. 이미 정해진 것은 다시 묻지 않는다.
- 방문 페이지에 들어오는 모습: 바뀐 것을 알아볼 수 있어야 한다(옆으로 밀림 + 배경·헤더 변화 + 방문 멘트 카드). **방문 멘트 카드**: 들어오면 화면 아래 가운데에 버튼 없는 작은 카드 한 줄이 떴다 사라진다. **첫 방문·연속 방문 주기(3·7·14·30일째, 그 뒤 100일마다)·오랜만(30일 이상 만에)일 때만 뜨고, 그 밖의 방문에는 뜨지 않는다** — "처음으로 ○○도서관에 방문했어요!", "일주일 동안 매일 방문했어요!" 등. "N번째 방문이에요"처럼 횟수만 알리는 글자는 쓰지 않는다. 방문은 기기에만 저장하고 도서관마다 하루 한 번 센다(2026-11-13 D 결정, "입장했어요" 한 줄을 바꿈). 문이 열리는 식의 연출은 쓰지 않는다.
- 방문 페이지의 위쪽은 핀터레스트형 피드(LOCAL)다. **M1에는 피드만 만든다.** 책장(오늘의 서가)·방명록·스탬프·룩은 M2이므로 만들지 않지만, 책장이 나중에 화면 아래에 붙을 수 있게 레이아웃을 열어 둔다. 빈 가짜 화면을 만들지 않는다.
- 방문 스탬프·방명록·게시물은 대출·위치·실제 방문의 증거가 아니다. 인증 배지를 만들지 않는다.
- **도서관 기본값**: 켜면 다음 실행에서 지도 없이 그 도서관 방문 페이지가 열리고, 다른 도서관이 있는 곳으로 가면 풀린다. 기기에만 저장한다(도서관 하나). 켜고 끄는 자리는 머리 오른쪽 **⋯ 메뉴**("앱을 켜면 여기부터 열기" ↔ "바로 열기 끄기")이고, 같은 도서관의 **누적 세 번째 방문 때 카드로 한 번 물어본다**("네, 여기부터"·"아니요", 도서관마다 한 번만). **3일 연속 방문은 연속 멘트로 처리하고, 누적 세 번째 방문의 질문 카드와 겹치면 누적 질문을 우선한다.** 이름 옆 별·머리의 스위치·집 모양 버튼은 쓰지 않는다(2026-11-13 D 결정). 앱을 켤 때 지도를 건너뛰는 분기와 풀렸을 때 지도 홈에 잠깐 뜨는 한 줄은 홈에 닿으므로 D가 계약서에서 누가 만들지 정한다.
- 머리에는 도서관 이름·거리·오늘 운영시간을 보여 준다(운영시간을 못 받으면 "정보 없음"). 왼쪽 위 굵은 "‹"와 화면 왼쪽 끝에서 밀기로 지도로 돌아간다. ⋯ 버튼은 머리의 도서관 정보 줄 오른쪽이다(A 큰 틀 명세서 결정 7·8·14에서 사용자 말로 확인된 것).
- **방문 페이지에는 검색창을 두지 않는다.** 대신 피드 카드 메뉴에서 책 제목·저자로 검색한다.
- 빈 피드에는 가짜 게시물을 만들지 않고 "아직 게시물이 없어요" 같은 안내만 보여 준다. 화면 모양은 기획에서 정한다.
- 게시물은 올리기를 눌러야 공개된다. 철회하면 바로 목록·직접 주소에서 안 보인다. 신고·운영자 숨김이 생기기 전(M1)에는 파일럿 참여자에게만 보인다.
- 게시물 이미지는 직접 찍은 사진 / 책 표지 / 단색 중 하나이고 글자를 얹을 수 있다. 본문(감상·좋았던 문장)은 선택이며 **제목·본문 없이 이미지만으로도 올릴 수 있다.** 사진의 위치 정보는 올리기 전에 지운다.
- 표지가 없으면 제목·저자 표지를 만들거나 사진·단색으로 대신한다. 표지는 카카오 책 검색 API로 ISBN을 조회한다(Q-39, 2026-11-18 네이버에서 바꿈 — C-66. 한도·이용 조건은 Q-41에서 D가 확인).
- 방문 페이지 피드는 도서관별 2열 메이슨리이며("광장" 명칭은 쓰지 않는다, 2026-11-17 사용자 결정), 최신순이 기본이고 인기순은 공감 수가 신호다(집계 기준은 Q-31). M1 카드는 게시물 카드만이다(방명록·모임·방문 기록 카드는 M2). 빈 피드에는 가짜 게시물을 만들지 않는다.
- **피드 카드는 제목·작성자 줄 없이 이미지만**이다(글자는 이미지 안, C-48). 작성자와 좋아요 수는 상세에 둔다(02 LOCAL-03, 2026-11-13 C-54로 "작성자만 작게"를 정리). 책 제목 정보나 이미지 위 글자 넣기를 없앤다는 뜻은 아니다.
- 목록에서 **길게 누르기(웹은 호버 시 점 세 개)** 작은 창(2026-11-17 D 시안 후보 A 확정): 상단 아이콘 3개 한 줄(`좋아요`·`북마크`·`공유`) + 하단 책 제목 검색 / 저자로 검색 2줄. 도서 없음(C-46 D1)은 M1에서 `'도서 없음 (예스24 구매 ↗)'` 버튼만 나오게 하고 예스24 API 구현·연결은 M2로 넘긴다. 공유는 시스템 공유창, 쓸 수 없으면 링크 복사(D2). 북마크는 카드 밖에 상시 버튼을 두지 않고, 상세에는 별도 북마크 버튼을 둔다. 북마크·좋아요 **모음**(내 정보 3탭)과 팔로우는 별도 작업이고 담당 미배정이다(C-46 F4).
- 상세의 넓은 화면은 왼쪽 큰 이미지, 오른쪽 반응·작성자·본문 영역을 목표로 한다(사용자 첨부 C-28, 개정 명세 §2, M1 댓글 제외 Q-57). 모바일은 세로 1열(이미지 → 상단 반응/저장 바 → 작성자·도서관 → 1순위 대여 큰 버튼·아래 예스24 구매 보조 버튼 → 본문 → 같은 책 다른 글 2열 → 이 도서관 다른 글 2열)로 확정했다(2026-11-17 D 시안 후보 A).
- **글쓰기 버튼은 SNS 안의 +/연필**이다(하단 탭에 없음). 형태·위치는 방문 페이지 오른쪽 아래 떠 있는 둥근 `"+"`로 확정됐다(LOCAL-1 결정 1, C-46 F3 시안 검토 완료).
- D3~D6(방문 기록 북마크·정렬·재공개 표현·카드 표현) 화면도 시안 검토가 필수 관문이다.
- **게시물 상세는 핀터레스트 방식**이다: 누르면 그 게시물의 본문이 펼쳐지고 그 주변에 다른 피드가 이어진다. 상세에서 대여 경로(소장·대출 가능 조회)가 구매보다 먼저 나오고, 구매 버튼(`예스24에서 구매 ↗`)은 M1에서 버튼만 표시하고 예스24 API 구현·연결은 M2로 넘긴다(2026-11-17 사용자 결정, Q-41). 대출 가능은 "어제 기준"처럼 기준일과 함께 보여 준다.
- 같은 책 이어 읽기: 상세에서 같은 책을 다룬 다른 공개 게시물(다른 도서관 포함)로 이어진다. 다른 도서관 게시물을 열어도 방문 중인 도서관의 화면 느낌을 유지한다.
- 공감은 게시물당 한 번이고 취소할 수 있다. 비공개 기록·대출은 인기글·추천 집계에 쓰지 않는다.

**기획에서 정할 것**

- 피드를 위로 올렸을 때 머리가 어떻게 바뀌는지 (VISIT-2, 기본값: 접혀서 "‹ 이름" 한 줄)

## C — 도서 탐색 `book-search` (먼저) → 반납 비서 `loan-assistant` (이어서)

### 도서 탐색 (LIB)

**진행 순서(2026-11-17 D 확정)**: LIB-1 구현이 `origin/main`(`ebcb70b`)에 머지 완료됐고, `book-search.md`(LIB-2·LIB-3)·`loan-assistant.md`(LOAN-1~3) 전 Step이 D+C 확정판으로 발행됐다. **D가 정한 것**
- 소장·대출 정보는 D의 조회 엔진으로만 받는다. 상태는 세 갈래(`있음/없음/알 수 없음`, `가능/불가/알 수 없음`)이고, 답을 못 받으면 '알 수 없음 + 다시 시도'를 보여 준다.
- 대출 가능 정보는 전날 기준이다. **"지금 바로 대출 가능" 같은 문구를 쓰지 않고 "어제 기준 · 대출 가능"처럼 기준일을 함께 보여 준다.** '실시간', '방금 반납'이라고 쓰지 않는다.
- 도서관마다 **"실시간 확인"**이 있다. 누르면 그 도서관 사이트의 해당 책 검색 결과(주소 규칙을 아는 도서관) 또는 도서관 홈페이지로 간다. 외부로 이동함을 보여 주고, 주소는 D가 주는 것을 쓴다(Q-48).
- 지도 전체에 조건 없는 '대출 가능' 표시를 하지 않는다. 고른 책 + 고른 도서관 조합에만 보여 준다.
- **내 주변**은 기본 반경 3km, 설정에서 5km로 넓힐 수 있다. 내 주변 책 검색은 기본으로 이 반경 안의 도서관만 대상이다. 검색 화면에 "현재 도시 내 모든 도서관 검색" 버튼이 있고, 기본 범위에서 못 찾으면 빈 결과 자리에 "현재 도시 내 모든 도서관 기준 재검색"을 보여 준다. "찾지 못했어요"라고 쓰고 없다고 단정하지 않는다. "도시"의 범위와 호출 방식은 D가 정한다(Q-51).
- 다른 도서관이나 책을 고르면, 앞서 물어본 것의 늦은 답이 지금 화면을 덮지 않는다(AC-RACE).
- 빌릴 예정은 본인만 보는 메모이고 도서관 예약이 아니다. 예약 성공처럼 보이는 문구를 쓰지 않는다. 같은 책·도서관의 빌릴 예정은 하나만 둔다.
- 위치를 거부하면 지역·도서관 목록으로 같은 탐색을 할 수 있다. 정확한 위치는 저장하지 않는다.
- **검색 진입 화면**(02 LIB-01, C-46 E1~E5): 검색창을 누르면 키보드와 함께 열리고, 추천 도서·최근 본 도서가 키보드 위 영역에서 스크롤된다. 추천은 범위별 활성 테마(노출 기간 안, 동시에 하나)가 있으면 테마, 없거나 책이 비면 인기 도서다. 조회 실패는 오류·다시 시도. 도서관 안은 그 도서관, 밖은 전국 인기 도서(최근 한 달, 없으면 전국으로 대체하고 기준 표시). 최근 본 도서는 검색 결과에서 상세를 연 책만, 계정별 20권·다시 본 책은 맨 앞·개별/전체 삭제, 비로그인은 이 기기에만 저장한다. 기간·도서관별 제공 가능 여부는 구현 전에 D가 실측한다.

**기획에서 정할 것**
- 검색어 입력 중 추천어를 보여 줄지, 결과를 번호로 넘길지 계속 내리게 할지
- 도서관 목록 순서(가까운 순 vs 빌릴 수 있는 곳 먼저)
- 도서관 카드에 보여 줄 정보(주소·전화·휴관일)와 "실시간 확인"을 어디에 둘지
- 도시 전체 검색 버튼의 위치와 빈 결과 화면의 모양
- 빌릴 예정 목록을 어디서 보고 어떻게 지우는지

### 반납 비서 (LOAN)

**D가 정한 것**
- **흐름(C-11)**: 책 확인 때 "빌릴 예정" → 실제로 빌린 뒤 "빌렸어요" → 그 시점부터 D-day 타이머와 알림 → "반납했어요". 도서관 쪽 정보 변화로 대출을 추정하거나 자동 등록하지 않는다.
- 날짜는 서버 KST 날짜(`Asia/Seoul`). 대출일은 "빌렸어요"를 누른 날이고, 반납 예정일은 대출일보다 빠를 수 없다.
- 기본 '오늘 + 14일'은 추정이라고 표시하고 날짜 선택으로 고칠 수 있다. 도서관별 공식 기간이라고 단정하지 않는다.
- 상태는 `대출중/반납완료` 두 가지. 연체는 날짜로 계산해 보여 주는 표시다.

- 알림은 D-3 · D-1 · 당일이며 **앱이 기기에 직접 예약**한다(서버 알림 작업자·알림함·푸시 구독 없음). 이미 지난 차수는 예약하지 않는다. 반납·기한 수정 때 이전 예약을 지우고 다시 건다. 알림이 오지 않아도 앱의 내 대출에서 D-day를 볼 수 있다. 도착을 약속하지 않는다. 로그아웃하면 예약을 모두 지운다.

**기획에서 정할 것**
