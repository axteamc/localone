# 06. 기능·API 정의서

> 상태: **골격 — 미작성**. 담당: D(통합), 기능별 계약서 작성 후 취합. 선행: 기능별 명세서 승인 → `../team/contracts/<기능>.md`. 갱신 시점: 계약서가 확정·변경될 때. 계약서가 원본이고 이 문서는 취합본이다(같은 내용을 따로 고치지 않는다).
> 입력: `../team/contracts/*`, [02 요구사항](02_요구사항_정의서.md), [05 DB 설계서](05_ERD_및_DB설계서.md).

## 작성할 내용

1. **공통 규칙**: 버전 경로, 인증(JWT 검증 항목), 오류 응답 `{"error": {"code","message","detail"}}`, 서울 날짜 기준, 페이지 크기
2. **엔드포인트 목록**: 메서드·경로·담당 Feature·인증 필요 여부·계약서 링크
3. **요청·응답 예시**: 실제 호출 결과(성공·실패), 필드 표
4. **화면 목록과 API 연결**: 화면 ↔ 엔드포인트 ↔ 명세서 결정·예외
5. **오류 코드 표**: 코드·HTTP 상태·화면 문구·DB 무변경 보장
6. **플랫폼 분기 표 취합**: 계약서 §3.3의 지점과 공통 화면 부품 위치
7. **OpenAPI 문서 위치**: 서버가 생성하는 문서와 이 문서의 관계(자동 생성본이 있으면 링크)
