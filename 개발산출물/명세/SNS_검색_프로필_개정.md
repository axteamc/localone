# SNS·검색·내 정보 개정 결정

> **최신 결정: [상세 결정 C-46](SNS_검색_프로필_상세결정.md).** 아래 C-26~43 결정과 충돌하면 C-46을 우선한다. 특히 프로필 3탭·팔로우 버튼·기간제 패널티·앱 알림 목록·미정 일정 처리·북마크 복원 정책이 갱신됐다.
> 2026-11-11 사용자 요청 1~7(C-26). 상태: 확정 동작 기록 / 세부 결정 진행 중 / 앱 미구현.
> 새 요청의 적용 단계는 별도 결정한다. 기존 M1 동결을 임의 해제하거나 새 요구를 M2로 확정하지 않는다. API·DB 계약은 아직 정하지 않는다.

## 1. 피드 메뉴

- 모바일은 피드를 길게 누르면 메뉴를 연다. 웹은 호버 시 피드 오른쪽에 점 세 개 버튼을 표시하고, 누르면 같은 메뉴를 연다.
- 메뉴 항목: **책의 제목 검색 / 저자로 검색 / 공유 / 좋아요 / 북마크**.
- 추가 확인: 책 정보가 없는 카드, 여러 저자의 검색 대상, 공유 방식, 길게 누르기 시간·스크롤 시 취소. 북마크 위치는 §2의 확정 결정을 따른다.

## 2. 북마크와 SNS 필터

- SNS 필터 **이웃의 기록 / 방명록 / 모임**에 **북마크**를 추가한다.
- 피드 북마크와 좋아요는 별도 기능이다. 하나를 변경해도 다른 기능이 자동 변경되지 않는다.
- **목록에서는 길게 누르기·웹 점 세 개 메뉴 안에서 북마크**한다. 카드 바깥에 북마크 버튼을 상시 표시하지 않는다.
- **피드 상세에 들어가면 별도 북마크 버튼**이 있다. 상세 참조 이미지의 우측 상단 ‘저장’ 버튼에 해당하는 역할이다. 메뉴와 상세 버튼은 같은 피드 북마크를 조작한다.
- **이웃의 기록·방명록·모임 모두 북마크할 수 있다**(사용자 선택: “1 - 모두”). 내 정보의 북마크 모음에서도 이 세 종류를 다시 볼 수 있다.
- **SNS의 북마크 필터는 현재 도서관에서 저장한 피드만** 보여 준다. **내 정보의 북마크 탭에서는 모든 도서관에서 저장한 피드**를 모아 본다(사용자 선택: 1).
- **삭제·공개 철회・운영 숨김 등으로 조회할 수 없어진 피드는 좋아요·북마크 모음에서 숨긴다**(사용자 선택: 1). SNS 북마크 필터와 내 정보의 두 모음에 동일하게 적용하고, 원문·이미지·자리표시 카드를 노출하지 않는다. 직접 주소로도 원문을 읽을 수 없다는 기존 공개 차단 기준을 유지한다.
- 이 결정은 목록 표시 정책이다. 좋아요·북마크 연결 데이터의 영구 삭제 여부와 재공개 시 복원 여부는 아직 정하지 않는다.
- **북마크한 피드는 목록 메뉴와 상세 버튼을 ‘북마크 해제’ 상태로 표시**한다. 다시 누르면 **확인창 없이 해제**한다(사용자 선택: 1). 두 진입점은 같은 저장 상태를 반영하고 해제 후 북마크 필터·내 정보 모음에서도 해당 피드를 제외한다. 통신 실패를 해제 성공으로 표시하지 않는다.
- 추가 확인: 방문 기록(다녀왔어요) 카드의 포함 여부, SNS 북마크 필터의 정렬, 해제 후 다시 저장할 때의 순서, 재공개 시 복원 여부.

### 상세 피드 참조(사용자 첨부, 2026-11-11)

- 사용자의 말: “2와 3. 2는 밖에서, 피드 상세 화면 들어가면 북마크 버튼이 있음(첨부 파일 그대로 상세 피드 내용 나오는게 목표)”.
- 넓은 화면은 첨부처럼 왼쪽에 큰 이미지, 오른쪽에 반응·작성자·본문·댓글 영역을 두는 구성을 목표로 한다. 이미지 안의 글자와 작성자가 쓴 본문은 구분한다.
- 상세 상단은 좋아요·댓글·공유·더보기와 별도 저장(북마크) 버튼을 참조한다. 작성자·본문·댓글 입력 영역을 함께 설계한다. 본문이 없는 게시물도 이 구조로 열 수 있다.
- 기존 도서 연결(대여 우선·구매), 주변 피드 이어 보기와 도서관 룩은 유지하며 이 상세 구성에 배치한다. 모바일의 세로 배치와 정확한 버튼·본문 위치는 시안에서 확인한다.
- 첨부의 ‘컬러’ 선택, 이미지 검색·확대, 이모지·스티커·이미지 댓글 등은 기능 채택 여부가 정해지지 않았다. 참조에 있다는 이유만으로 별도 기능을 확정하지 않는다.

## 3. 내 정보 프로필

- 인스타그램 프로필 화면의 구성과 이미지 격자 탐색 방식을 참조한다.
- 내 정보에서도 좋아요한 피드와 북마크한 피드를 모아서 본다. 수집 탭은 **왼쪽 좋아요 / 오른쪽 북마크**다.
- 첨부 사진의 원래 격자·태그 기능이 아닌 사용자가 지정한 의미로 사용한다.
- **좋아요 모음과 북마크 모음은 둘 다 본인만 조회**한다(사용자 선택: 1). 타인의 프로필·직접 주소·조회 요청에서도 다른 사람의 모음을 제공하지 않는다. 계정을 바꾸면 이전 계정의 모음과 진행 중인 조회 결과를 남기지 않는다.
- 이 결정은 개인 수집 목록의 공개 범위다. 피드의 전체 좋아요 수나 좋아요한 사람 목록의 노출 정책까지 결정한 것은 아니다.
- **내 정보의 좋아요 모음은 최근 좋아요한 순서, 북마크 모음은 최근 저장한 순서**로 보여 준다(사용자 선택: 1). 피드 작성일이 아니라 각 모음에 추가한 시점의 내림차순이다. 같은 시각의 안정적인 순서 기준은 후속 계약에서 정한다.
- 추가 확인: 상단 표시 정보, 내 게시물 진입 위치, 처음 열리는 탭. 팔로우·팔로워 기능은 참조만으로 추가하지 않는다.

## 4. 하단 이동

- **글쓰기를 하단 탭에서 제거한다.** SNS 섹션 안의 + 또는 연필 버튼으로 제공한다. 두 버튼 중 최종 형태·위치는 미결이다.
- 하단 탭은 **홈 / 독서 기록 / 대출·반납 / 내 정보** 네 개를 이 순서로 둔다(사용자 확정).
- **내 발자취는 독서 기록의 도서관별 보기로 통합**한다. 별도 하단 탭·사이드바 메뉴를 두지 않는다(Q-44 해소).
- 이전 안: 발자취를 별도 최상위 이동처로 두는 구성을 검토했으나, 독서 기록과 기능이 겹쳐 통합했다.

## 5. 검색 진입 화면

- 검색창을 누르면 키보드만 띄우지 않고 별도 검색 탐색 화면처럼 보이게 한다. **추천 도서 / 최근 검색 도서**를 보여 준다.
- 첨부 지도 앱의 검색창 아래 카테고리~광고 영역은 도서 탐색 콘텐츠를 배치하는 구조 참조다. 광고 도입 결정은 아니다.
- **최근 검색 도서는 검색 결과에서 눌러 상세를 본 책**이다(사용자 선택: 1). 표지·제목으로 표시하고 선택하면 해당 책 상세를 다시 연다. 검색어 입력·검색 실행만으로는 책을 이 목록에 추가하지 않으며, 검색 결과에 단순 노출된 책도 추가하지 않는다.
- **검색 진입 화면의 추천 영역은 운영자가 설정한 테마가 있으면 테마 추천 도서, 없으면 공공 데이터의 인기 도서**를 보여 준다(사용자 선택: “3 - 테마 설정이 되어있다면 테마, 아니면 인기 도서”). 테마와 인기를 항상 두 영역으로 나누어 동시에 보여 주는 구성은 아니다.
- **도서관 안에서 검색하면 방문 중인 도서관의 테마, 도서관 밖에서는 공통 테마**를 보여 준다(사용자 선택: 2). 검색을 연 화면의 도서관 컨텍스트를 기준으로 한다.
- 해당 범위에 테마가 없으면 인기 도서를 표시한다는 앞선 결정을 따른다. 도서관별 테마가 없을 때 공통 테마를 중간 대안으로 사용하는 단계는 이번 결정에 추가하지 않는다.
- 활성 테마 판단·여러 테마 우선순위, 테마가 있어도 책이 비어 있거나 조회에 실패한 경우의 처리는 추가 확인한다. 인기 도서의 집계 지역·기간·갱신 규칙도 후속 명세에서 정한다. 기존 방문 페이지 책장 구성과 Q-47 전체를 이 결정으로 확정하지 않는다.
- 추가 확인: 최근 도서의 저장 위치·기간·삭제·중복 처리·정렬, 비로그인 처리, 키보드가 열린 상태의 배치.

## 6. 피드 기본 표현

- 피드는 **제목을 별도로 표시하지 않는 형태가 기본**이다. 핀터레스트의 미니멀한 구성을 최대한 참조한다.
- 책 제목 정보 삭제나 이미지 위 글자 넣기 기능 제거를 뜻하지 않는다.
- 추가 확인: 작성자·좋아요 수 등 보조 정보, 방명록·모임 카드에도 같은 규칙을 적용할지, 모임 식별 정보 표시.

## 7. 작은 모임

- **기본은 만든 사람이 장소·시간을 정해 올리되, 최초에 시간·장소 미정으로 게시할 수도 있다.** 참가자들의 의견을 댓글로 의논하고 만든 사람이 상단의 장소·시작/종료 시간 정보를 반영할 수 있게 한다(C-43). 미정 시각으로 종료 알림을 예약하지 않으며 확정·변경 후 알림 반영의 세부 규칙은 후속 계약에서 정한다.
- **모임에 참가** 버튼을 누르면 **만든 사람의 별도 승인 없이 바로 참가 등록**한다(사용자 선택: 1, C-41). 첫 모임과 다음 모임에 동일하게 적용한다. 참가 요청·승인 대기 단계를 두지 않는다. 모임은 SNS 피드에서 발견한다.
- 같은 사용자의 반복 클릭·통신 재시도로 참가가 중복 등록되지 않아야 하며, 등록 실패를 참가 완료로 표시하지 않는다. 로그인·모집 마감·정원 등 등록 가능 조건은 후속 결정과 계약에서 정한다.
- **모임 하나는 한 번 만나는 약속**이다. 다만 이전 모임을 바탕으로 다음 모임을 간단히 만들어 계속 이어 갈 수 있게 설계한다(사용자 결정).
- **등록된 종료 시각에 모임을 만든 사람과 참가자 모두에게 종료 알림**을 보낸다. “모임이 완료되었습니다. 이번 모임은 어떠셨나요?” 같은 문구로 **모임 기록·후기 작성**을 유도하고 모임 기록 화면으로 이어진다(사용자 결정 C-39). 문구는 예시이며 최종 문안은 시안에서 정한다.
- **‘다음 모임을 만들까요?’라는 적극적인 제안은 모임을 만든 사람에게만** 보여 준다. 종료 안내·후기 유도와 다음 모임 생성 제안은 수신 대상을 구분한다. 알림 하나에 어떻게 배치할지 또는 기록 화면에서 제안할지는 시안에서 정한다.
- **다른 참가자도 모임 기록 화면의 별도 ‘이 모임으로 다음 모임 만들기’ 진입점으로 다음 약속을 만들 수 있다.** 복잡한 권한 양도나 별도 승인 절차를 기본 흐름으로 추가하지 않고 간단한 버튼으로 제공한다. 모임 비참가자의 생성 허용 여부는 아직 정하지 않는다.
- 종료 시각과 알림 연동을 채택하되 참가 등록·종료 시각 도달을 실제 참석 증거로 취급하지 않는다.
- 다음 모임 작성 시 **이전 모임 입력값을 기본으로 가져오고 시간·장소 정도만 새로 입력**해 새 약속을 등록할 수 있게 한다. 이전 회차의 기록을 덮어쓰지 않는다. 별도 상시 회원제 모임 공간을 기본 단위로 삼던 이전 안은 이 회차별 약속 흐름으로 대체한다.
- 다음 모임은 사용자가 생성 흐름을 직접 시작한다. **새 모임 등록 후 이전 참가자에게 안내하고, 각자가 바뀐 시간·장소를 확인한 뒤 다시 ‘모임에 참가’를 눌러야 등록**된다(사용자 선택: 1). 이전 참가자를 자동으로 참가 등록하지 않는다. 안내 수신만으로 참가 의사를 기록하지 않는다.
- 복사할 상세 항목, 새 모임 안내의 전달 방식과 취소자 포함 여부, 여러 참가자가 각각 다음 모임을 만드는 경우의 처리는 추가 확인한다.
- 종료 알림 거부·미도착 시에도 기록 화면에서 다음 모임 작성으로 이어질 수 있어야 한다. 알림 구현 방식·중복 방지·종료 시각 변경 및 모임 취소 시 예약 처리는 후속 명세·계약에서 정한다.
- **참가 취소는 모임 시작 전까지만 가능**하다(사용자 선택: 1, C-42). 시작 시각부터 종료 후까지 참가자 본인의 취소 조작은 허용하지 않는다. 기존 참가 등록 기록과 실제 참석 여부는 구분한다. 시간 변경·모임 자체 취소는 별도 규칙으로 정한다.
- **모임 댓글은 참가 여부와 관계없이 누구나 작성**할 수 있다(C-43). 로그인 필요 여부는 기존 쓰기 권한(02 §2)을 따르며, 비로그인 작성까지 허용한다는 뜻으로 확장하지 않는다.
- 불쾌한 댓글에 대해 **만든 사람이 특정 댓글의 삭제를 요청하고, 관리자가 승인하면 댓글 삭제 및 작성자의 해당 모임 참가 방지가 가능**하도록 한다. 만든 사람에게 즉시 삭제·차단 권한을 주거나 모든 모임에 차단을 확대하지 않는다. 요청·승인·처리 사유는 운영 기록으로 남긴다.
- 관리자 승인 전에는 요청만으로 댓글을 삭제하거나 참가를 제한하지 않는다. 승인 시 삭제와 제한을 각각 선택하는지, 이미 참가한 작성자의 처리·제한 기간·해제 등 세부 정책은 미결로 남긴다.
- **후기는 본인 비공개 기록이 기본**이며, 원할 때 별도 올리기 동작으로 SNS에 공유한다(C-43). 종료 안내나 후기 작성만으로 공개하지 않는다.
- 남은 세부: 복사 항목, 실제 참석 확인·기록, 미정 일정의 참가 취소 기준, 운영 승인 세부. 반납용 기기 예약 알림만으로 댓글·일정 변경 알림이 해결된다고 가정하지 않는다.

## 8. 진행과 검증 경계

Q-44 하단 탭 구성·발자취 통합은 해소했다. 북마크 위치는 목록 메뉴 + 상세 별도 버튼으로 확정했다. 북마크 대상은 이웃의 기록·방명록·모임 모두로 확정했다. SNS 북마크는 현재 도서관 범위, 내 정보 북마크는 모든 도서관 범위로 확정했다. 좋아요·북마크 모음은 둘 다 본인만 조회하도록 확정했다. 삭제·공개 철회·운영 숨김된 피드는 두 모음에서 숨기도록 확정했다. 북마크 해제는 메뉴·상세 버튼에서 확인창 없이 바로 처리하도록 확정했다. 내 정보 모음은 각각 최근 좋아요·저장한 순서로 확정했다. 최근 검색 도서는 검색 결과에서 눌러 상세를 본 책으로 확정했다. 검색 진입 추천은 설정된 테마 우선, 없으면 인기 도서로 확정했다. 검색 진입 테마는 도서관 안에서는 해당 도서관별, 밖에서는 공통 테마로 확정했다. 작은 모임은 회차별 약속으로 만들되 기록·종료 알림에서 이전 입력값을 가져와 다음 모임을 간단히 만드는 흐름으로 확정했다. 종료 안내·기록/후기 유도는 만든 사람과 참가자 모두에게, 다음 모임 생성 제안은 만든 사람에게만 제공한다. 다른 참가자는 기록 화면의 별도 버튼으로 다음 모임을 만들 수 있다. 다음 모임은 이전 참가자에게 안내 후 각자가 다시 참가를 선택하도록 확정했다. 참가는 만든 사람의 승인 없이 즉시 등록하도록 확정했다. 참가 취소는 시작 전까지만 허용하도록 확정했다. 최종 확인 C-43으로 일정 미정 게시·공개 댓글·관리자 승인 기반 댓글 삭제/참가 방지·비공개 후기를 채택했다. 나머지 미결 사항도 한 번에 하나씩 확인하고 결정 즉시 갱신한다.

실행 앱 없이 문서·기존 HTML 시안만 있는 상태다. 이번 반영은 문서 기록이며 실제 저장·검색·공유·알림·화면 동작은 미구현이다. 기존 HTML도 C-26 반영 전이다.


## 9. 최종 확인과 후속 미결(C-43)

사용자가 마무리 제안을 수정·채택했다. 시간·장소는 만든 사람이 정하되 미정 게시와 댓글 협의 후 변경을 허용한다. 댓글은 누구나 작성 가능하며 만든 사람의 삭제 요청·관리자 승인에 따른 댓글 삭제 및 해당 모임 참가 방지를 제공한다. 후기는 비공개 기본·별도 SNS 공유다. 이전 제안의 ‘참가자만 댓글 작성’은 폐기했다.

프로필 세부 배치·글쓰기 버튼 형태 등은 시안 검토 때, 저장 기간·정원·알림 구현·예외 정책 등은 구현 명세 작성 때 추가 결정이 필요하다. 특히 시간이 미정인 모임의 참가 취소 마감, 운영 승인에 따른 기존 참가자 처리·제한 해제 정책은 임의로 정하지 않는다. 확정 동작은 이번 PR의 문서 반영 범위이고 앱 구현은 별도 작업이다.
