## 1. core M2-0에 반영할 Z7·Z8 초안

| 결정 | 대체 문안 |
| --- | --- |
| Z7 서가 테마 | 운영자가 공통(`library_id IS NULL`) 또는 도서관 전용 테마를 기간과 함께 등록한다. 공통 테마당 1~`RECOMMENDATION_MAX_BOOKS`(현재 20)권, 전용은 1~3권이다. `priority`는 1~3이며 작은 값이 먼저다. 동일 범위·동일 우선순위에서 서울 날짜 기준 기간 양 끝을 포함해 겹치는 테마는 등록할 수 없다. 서로 다른 범위에는 같은 우선순위를 사용할 수 있다. |
| Z8 책장 `#31` | 조회 도서관의 오늘 활성 테마를 전용 → 공통 순으로, 각 범위 안에서 `priority ASC, id ASC` 순으로 평가한다. 후보는 해당 도서관의 유효한 소장 기록이 있는 ISBN만 센다. 전용은 1권 이상, 공통은 2권 이상 확인된 첫 테마 한 장을 고르고, 그 테마의 등록 순서로 최대 4권을 반환한다. 전용이 기준에 못 미치면 다음 전용, 이어 공통을 평가한다. 어느 테마도 기준을 충족하지 않으면 `theme` 페이지를 생략한다. 최근 읽은 책·인기 도서도 최대 4권이다. 인기 도서는 §5의 제외 정책을 적용한다. 서버 응답 순서는 현행을 따른다. |

- 예시. 전용 테마에 확인된 1권이 있으면 공통 1순위에 확인된 4권이 있어도 전용 1권이 먼저다. 전용이 없고 공통 1순위에 1권, 2순위의 4·7·9·10·14번째 책에 소장이 확인되면 2순위의 4·7·9·10번째 책을 반환한다.
- 날짜 범위는 `starts_on <= today_kst() <= ends_on`. 도서관 지역이 없거나 소장 데이터가 미적재·만료됐으면 그 책은 매칭에 포함하지 않는다. 다른 유효한 테마·페이지가 있으면 보여 주고, 모든 페이지가 비면 `200 {"pages":[]}`와 기존 빈 책장 문구가 적용된다. 이 기능은 빈 책장을 줄이는 것이 목표이며 전 도서관 채움은 후보 및 제공자 데이터 커버리지에 달려 있다.
- `#31` 인증 없음. `pages: ShelfPage[]`(0~3개), 각 `ShelfPage`는 `kind`(`recent_reads|popular|theme`), `title`(문자열), `basis_label`(문자열 또는 `null`, 테마는 `null`), `books`(1~4개) 모두 필수. `Book`의 필수 키와 타입은 `isbn13`(ISBN-13 문자열)·`title`(문자열)·`author`(문자열 또는 `null`)·`cover_url`(HTTPS 문자열 또는 `null`)이다. 없는 도서관은 `404 NOT_FOUND`, 경로 정수 범위 오류는 `422 VALIDATION_ERROR`. 페이지·책 DTO 추가 없음. 소장 근거는 대출 가능 표시로 쓰지 않는다.
- `#9 /books/recommendations`는 현행 `server/app/routers/books.py:87-100`에서 인기 도서만 조회한다. 02 §3과 LIB-0의 미래 테마 연결 규칙 때문에 테마 테이블의 새 다중 활성 정책을 이후 `#9`에 적용하려면 별도 계약 결정이 필요하다. 이번 계약 제안은 방문 책장에만 적용한다.
- 발행 시 core SRV-0 C2의 P3 세부(`core.md:60-62`)와 M2-0 C1·C2·C3·C5·C6·P2·P4·P5를 함께 맞춘다. LIB-0 제공자 인터페이스·테스트에 소장 목록 작업을 연결한다. VISIT-3 V3-1·V3-5·C2·C3·P2·P5에 네 권 상한, 화면 배치, 담당 파일 및 검증을 반영한다. 대상 Step과 무관한 발행 계약 본문은 원본대로 보존한다.

## 3. 마이그레이션과 조회 설계

기존 `0014` 이후 새 Alembic 리비전을 추가한다. 기존 테마에 `priority SMALLINT NOT NULL DEFAULT 1 CHECK (priority BETWEEN 1 AND 3)`를 적용한다. `shelf_theme_books.position`의 기존 CHECK를 1~20으로 교체하고, 기존 PK(`theme_id, position`)·FK를 보존한다. 범위별 권수 제한과 기간 겹침은 기존 운영 경로의 검증·잠금으로 보장한다. 배치는 테마를 쓰지 않는다. 겹침 조회에 `(library_id, priority, starts_on, ends_on)` 인덱스를 후보로 두고 실제 쿼리 계획을 본다.

| 표·열 | 타입·null | 키·제약·의미 |
| --- | --- | --- |
| `library_holdings_snapshots.book_id` | bigint NOT NULL | FK `books(id)`(기본 NO ACTION), 복합 PK의 첫 열. |
| `library_holdings_snapshots.region_code` | text NOT NULL | 복합 PK의 둘째 열, 2자리 제공자 광역 코드. |

| `popular_books_cache.provider_class_name` | text NULL | 정보나루 `class_nm`의 공백 정리 값. 기존 행과 미분류 응답은 NULL. 제공자·캐시 갱신 결과에서 ISBN별로 연결하며 공개 응답에 포함하지 않는다. |

두 새 표에 RLS 활성화·정책 0개. 개인 식별자, `loanable`, 대출 원장, `availability_observations` 연동 없음. 쿼리는 현재 도서관의 광역 코드와 동일한, 만료되지 않은 스냅샷의 양성 행만 사용한다. 순차 수집 중 공통 후보 ISBN이 여럿 같은 날에 등록돼도 이미 확인된 권수를 기준으로 선택한다. 데이터 보충에 따라 우선순위가 높은 테마가 다음 조회부터 채택될 수 있다.

- 한 SELECT에서 활성 테마 → 유효 소장 조인 → 테마별 확인 권수 계산 → 충족한 테마 정렬·하나 선택 → 등록 순서대로 최대 4권을 가져온다. `shelf_book`으로 반환하고 기존 `theme_page(conn, library_id, today)` 진입점을 사용한다. 만료 비교 시각은 쿼리당 한 번 고정한다. 외부 소장 호출은 요청 경로에 없다.
- 기존 테마 기간·책·순서가 보존되는지 upgrade를 확인한다. 다운그레이드 전에는 position 4 이상 행 및 기간이 겹치는 동일 범위 테마가 있는지 검사하고, 있으면 운영자가 별도 승인으로 정리하거나 호환성 있는 선행 버전으로만 되돌린다. 자동 삭제나 테마 재배치는 하지 않는다. 새 테이블 삭제는 캐시 재수집이 필요한 별도 롤백 단계다.
- 운영 전환 순서 제안. 스키마 및 배치 적용 → 기존/예정 테마 소장 사전 적재와 커버리지 확인 → 새 필터 읽기 트래픽 전환 → 구 리비전 테마 쓰기 호출이 종료된 뒤 20권·다중 우선순위 등록을 시작한다. 구 서버는 확장 테마를 상위 4권으로 안전하게 자르지 않으므로 기능 사용 뒤 구 리비전에 단순 롤백하면 응답 상한이나 소장 필터가 깨질 수 있다.

| 매핑과 저장 | 전체 페이지를 받은 뒤 `libCode`와 `libraries.provider_lib_code`를 동일 광역 코드 안에서 대응한다. 미등록·코드 불일치 건수는 로그에 남기고 도서관 행을 생성하거나 주소·이름으로 추정 매핑하지 않는다. 한 DB 트랜잭션에서 더 최근 수집이 저장됐는지 검사하며 스냅샷 upsert와 기존 ISBN·지역 매핑 전체 교체를 원자 처리한다. 실패·한도 도달 시 앞서 완료한 조합의 커밋은 보존하고 실패한 조합의 이전 결과는 유지한다. |
| 갱신과 재실행 | 시연 전에는 미처리·실패·만료 조합을 수시로 이어서 적재한다. 스냅샷은 72시간 만료이며 시연 이후 정기 실행 주기를 정한다. 실패 후에도 기존 72시간 이내 양성만 사용한다. 재실행은 완료한 조합을 재사용하고 미완료 조합을 첫 페이지부터 다시 읽는다. 지역이 새로 등록될 경우 새 코드에 대한 첫 수집, 같은 지역 안 신규 도서관은 다음 갱신 때 반영한다. |
| 결과 | 실행 종료 `0` 전체 처리(기존 유효 결과·대상 없음 포함), `1` 부분/실패(제공자 오류·공유 쿼터·배치 상한·저장 오류), `2` 인자 오류. 지역별 대상·갱신·0건·기존 유효·실패·미처리·미매핑 수와 실제 예약 요청 수를 남긴다. 키·DB 연결 문자열·원문 URL은 기록하지 않는다. |

예를 들어 등록된 광역 지역이 17곳이고 공통 테마 3개에 서로 다른 ISBN이 총 60개면 첫 페이지만 1,020회다. 예정 테마가 추가되거나 결과가 여러 페이지면 호출 수가 더 늘어난다. 지역별 미처리 건수와 완료율을 보고 읽기 트래픽을 전환한다.

승인된 소장 판정은 배치 자료를 사용한다. 요청 시 기존 `bookExist`를 쓴다면 미확인 후보에 한해 짧은 응답 시간과 별도 호출 수 한도·동일 키 중복 억제·별도의 소장 근거 출처 정의가 필요하다. 최대 60개 공통 후보를 진입마다 조회하면 인기 조회와 일일 한도를 공유하고, 작은 호출 상한으로는 20권 중 앞부분만 확인해 우선순위 판정이 불완전할 수 있다. 첫 적재 뒤 전체 등록 도서관을 분모로 1·2·3·4권 이상 매칭 비율을 집계하고, 광역 코드 없음·적재 공백·제공자 실패·수집 완료 후 기준 미달을 구분한다.

### 인기 도서 제외 규칙

1. 정보나루 v20260620 §9 pp.28–30의 응답 표에는 `class_no`·`class_nm`·`vol`이 있다. 현재 파서(`server/app/services/provider_engine.py:284-316`)와 캐시 조립(`:933-990`)에는 해당 필드가 없다. 출처 분류명 `class_nm`을 nullable `popular_books_cache.provider_class_name`에 보존하고, 새 응답과 캐시에서 똑같이 ISBN으로 연결한다. 분류명이 비어 있거나 없으면 확인 불가로 처리한다. [정보나루 공식 매뉴얼](https://www.data4library.kr/downloadApiManual)
2. 실측에서 확인된 정확한 만화 분류명과 운영자가 검토한 정확한 ISBN 또는 시리즈명으로 제외한다. 시리즈명은 Unicode NFKC·공백 정리·영문 대소문자 접기 후 제목 전체 또는 시작의 완전한 이름 경계에 맞는 경우에만 적용한다. 예를 들어 해당 이름 뒤의 공백·구분 문장부호·권호 숫자를 경계로 본다. `vol`과 제목 숫자는 단독 제외 조건으로 사용하지 않는다.
3. D가 서버 정책의 제외 목록을 관리한다. 첨부 예시의 ‘빨간내복야코’와 ‘백앤아’는 초기 등록 대상으로 삼고 시연 후보의 실제 제목·ISBN을 대조해 별칭을 채운다. 분류명이 없는 구 캐시에도 제외 목록을 적용한다. 미분류 도서는 순위를 유지하므로 알려지지 않은 시리즈는 운영 목록 보완 대상이다.
4. `#31`의 도서관별 인기 장에서만 기존 상위 20개를 순위대로 검사해 적격 도서 최대 4권을 고른다. 1~3권이면 있는 만큼, 0권이면 인기 장을 생략한다. 전국 결과로 대체하지 않는다. `#9`의 결과·순위와 원본 인기 순위를 유지한다. 화면 요청에 분류 목적의 외부 호출을 추가하지 않는다.
