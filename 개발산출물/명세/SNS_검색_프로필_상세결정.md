# SNS·검색·프로필 상세 결정 — 묶음 답변 반영

> 2026-11-12, C-46. A1~F4 묶음 질문에 대한 사용자 답변을 기록한다. [기존 개정 명세](SNS_검색_프로필_개정.md)와 충돌하면 이 문서의 최신 결정을 우선한다.
> 문서 반영이며 앱·API·DB 구현 완료가 아니다. 미결 질문은 §8에 모았고, **C-47(§9)로 알림함 채택·불참 패널티 단계가 정해지고 나머지는 세부 명세로 넘어갔다.**

## 1. 모임 일정·참가·출석(A)

| 항목 | 확정 결정 |
| --- | --- |
| A1 | 시간·장소 미정이어도 참가 등록 가능. 확정되면 참가자에게 **앱 알림** |
| A2 | 시작 시각 미정이면 언제든 참가 취소 가능. 확정 후에는 시작 전까지 |
| A3 | 참가자가 생겨도 만든 사람이 시간·장소 변경 가능. 참가자에게 안내하며 재승인은 받지 않음 |
| A4 | 시작 후 시작 시각 변경 금지. 장소·종료 시각 수정 가능 |
| A5 | 정원은 선택 입력, 미입력 시 제한 없음. 시작 시 자동 모집 마감, 만든 사람이 조기 마감 가능 |
| A6 | 만든 사람은 종료 전 모임 취소 가능. 이유 입력·참가자 안내·종료 알림 해제, 취소 기록 유지 |
| A7 | 본인의 참석 기록과 함께 **만든 사람의 출석 확인**을 제공. 사용자 표현: “미참가인데 참가한 사람 체크 => 참가 신청하고 불참하는 사람 패널티를 위해”. 실제로 체크하려는 상태·불참 판정·패널티 조건은 §8에서 확인 |

참가 신청·실제 참석·불참 판정은 구분한다. 만든 사람이 참석 여부를 확인한다는 이유만으로 패널티를 자동 부과하거나 확인되지 않은 불참을 확정하지 않는다. 시작 시각이 변경되었을 때 기존 참가자의 취소 기회가 사라지는 예외는 후속 명세에서 명시한다.

## 2. 댓글 운영과 기간제 패널티(B)

| 항목 | 확정 결정 |
| --- | --- |
| B1 | 관리자는 **댓글 삭제만 / 삭제와 참가 제한** 중 선택 |
| B2 | 참가 제한 대상이 이미 참가 중이면 명단에서도 제외하고 재참가 차단. 본인에게 사유 안내 |
| B3 | 제한은 회차 1개로만 끝내는 대신 **일정 기간의 패널티**로 운영. 기간·적용 모임 범위는 미결 |
| B4 | 해당 패널티 기간에는 댓글 작성도 제한. 적용 모임 범위는 B3와 함께 확인 |
| B5 | 본인이 운영자에게 재검토 요청 가능. 운영자만 해제 가능 |
| B6 | 관리자 승인 전 댓글은 기존처럼 표시. 관리자 화면에는 검토 대기, 같은 요청 중복 방지 |

이전의 ‘해당 회차에만 제한, 다음 회차로 확대 안 함’은 B3·B4로 변경됐다. 기간제 정책의 범위가 정해지기 전 전체 서비스 차단이나 특정 일수를 임의로 적용하지 않는다. 댓글 문제에 대한 관리자 승인 패널티와 불참 패널티는 별도 사유로 구분한다.

## 3. 기록·다음 모임·알림(C)

| 항목 | 확정 결정 |
| --- | --- |
| C1 | 기록에는 날짜·장소·책·소개·본인 참가/참석 여부·후기. 개인 후기는 비공개 기본, 원하면 **공개 SNS 피드 한 건으로 게시** |
| C2 | 다음 모임에 이름·소개·책·도서관을 복사. 장소는 이전 값으로 채우되 수정 가능. 날짜·시간은 새로 선택 |
| C3 | 여러 참가자가 각각 다음 모임 생성 가능. 이미 만들어진 다음 모임을 먼저 보여 주고 별도 생성 허용 |
| C4 | 이전 회차 종료 시 참가자로 남아 있던 사람에게 다음 모임 안내. 취소·참가 제한된 사람 제외 |
| C5 | 기기 알림 외에 **앱 안 알림 목록** 제공. 기기 알림 거부 시에도 변경·취소·다음 모임 안내를 확인 |
| C6 | 공개 SNS 후기와 원본 개인 후기는 별도로 관리. 공유 시 공개 글을 만들고 이후 각각 수정 |

종료 알림은 만든 사람과 참가자 모두에게 기록·후기를 유도한다. 적극적인 다음 모임 생성 제안은 만든 사람에게만 제공하고, 다른 참가자는 기록 화면의 별도 버튼으로 생성한다. 이전 참가자는 자동 참가하지 않고 다시 참가를 선택한다.

앱 안 알림 목록은 이번에 채택한 범위다. 기존 C-11의 반납 기기 알림만 제공·알림함 제외라는 규칙을 모임의 변경·취소·운영 처리 안내에 그대로 적용하지 않는다. 반납 알림을 서버 푸시로 전환한 것은 아니다. 예약·이벤트 알림의 실제 전달 방식은 후속 계약에서 정한다.

## 4. 피드·공유·북마크(D)

| 항목 | 확정 결정 |
| --- | --- |
| D1 | 사용자 지시: 제목 연결 버튼을 **‘도서 없음(구매 링크)’**로 변경해 처리. 어떤 결손 상태에서 어떤 책의 구매 링크로 보내는지는 §8에서 확인. 기존의 ‘책이 없으면 검색 숨김’ 추천안으로 확정하지 않음 |
| D2 | 일반 앱의 **시스템 공유창**처럼 연결 앱 목록을 표시하고 공개 피드 링크를 공유. 공유창을 사용할 수 없으면 링크 복사 |
| D3 | ‘다녀왔어요’ 방문 기록 카드도 북마크 대상에 포함 |
| D4 | SNS 북마크도 최근 저장순. 해제 후 재저장하면 맨 앞으로 |
| D5 | 철회·운영 숨김 후 재공개되면 다시 표시하되 원래 저장 순서 유지. 완전 삭제는 복원하지 않음 |
| D6 | 일반 게시물은 제목 없는 이미지 중심·작성자만 작게 표시, 좋아요 수는 상세에 표시. 모임은 이름·일정·미정 여부 등 식별 정보를 유지 |

좋아요·북마크 모음은 여전히 본인만 조회한다. 웹 목록의 메뉴·상세 별도 저장 버튼과 SNS 현재 도서관/내 정보 전체 도서관 범위도 유지한다. 여러 저자가 연결된 경우의 저자 선택 추천은 D1의 의미 확인 때 함께 정리한다.

**D3~D6는 실제 시안을 사용자에게 보여 주고 검토받는 것을 필수 관문으로 한다.** 문서 채택·자동 검사·개발자 판단만으로 화면 승인 완료로 처리하지 않는다.

## 5. 검색 추천·최근 도서(E)

| 항목 | 확정 결정 |
| --- | --- |
| E1 | 검색 추천 범위별 활성 테마는 동시에 하나. 운영자가 노출 기간 지정, 기간 밖이면 인기 도서 |
| E2 | 책이 없는 테마는 인기 도서로 대체. 조회 실패는 오류·재시도를 표시하고 인기 도서 별도 탐색 제공 |
| E3 | 도서관 안은 해당 도서관 인기 도서, 밖은 전국 인기 도서. 최근 한 달 기준. 해당 데이터가 없으면 전국으로 대체하고 기준 표시 |
| E4 | 로그인 계정별 최근 20권, 다시 본 책은 맨 앞으로. 개별·전체 삭제 제공. 비로그인은 현재 기기에만 저장 |
| E5 | 검색 진입 화면과 키보드를 함께 표시. 추천·최근 도서는 키보드 위 영역에서 스크롤 가능 |

최근 도서는 검색 결과에서 상세를 연 책이다. 테마 범위는 도서관 안은 해당 도서관, 밖은 공통이다. E3의 기간·도서관별 제공 가능 여부는 구현 전 제공자 문서·실측으로 확인하며 현재 지원된다고 단정하지 않는다. 최근 도서의 별도 기간 만료 여부는 이번 답변으로 정하지 않았다.

## 6. 프로필·글쓰기·일정(F)

| 항목 | 확정 결정 |
| --- | --- |
| F1 | 사진·닉네임·한 줄 소개·프로필 편집 및 **팔로우 버튼** 허용. 팔로워 수·목록 표시 안 함 |
| F2 | 최초 화면은 **내 게시물**, 총 3탭을 **내 게시물 / 좋아요 / 북마크** 순서로 제공. 좋아요·북마크는 기존대로 비공개 수집 탭 |
| F3 | SNS 글쓰기 버튼의 위치·형태는 세부 명세에서 정함. **실제 시안 확인·사용자 검토 필수**. 헤더 오른쪽 연필 추천을 확정하지 않음 |
| F4 | 기존 M1 피드·검색·메뉴 변경은 해당 기능 명세부터 반영. 새 프로필 수집·북마크·모임은 별도 작업으로 일정·담당 배정. 기존 M1 전체 재편은 하지 않음 |

이전의 ‘팔로우 기능 추가 안 함’, ‘내 게시물은 별도 버튼·처음은 좋아요’ 안은 F1·F2로 대체한다. 팔로우 버튼의 사용자 대상·누른 뒤 효과는 §8에서 확인한다. 누가 자신을 팔로우했는지 보여 주는 수·목록을 만들지 않는다.

## 7. 검수와 구현 경계

- 필수 시안 관문: D3~D6, F3. 검토 전 화면을 승인 완료로 기록하거나 해당 화면 구현 단계로 넘기지 않는다. 나머지 화면도 기존 명세·시안 승인 절차를 따른다.
- 실제 앱·HTML 시안·알림·공유·팔로우·제한 기능은 미구현이다. 이 문서는 제품 결정이며 API 경로·DB 물리 스키마를 확정하지 않는다.
- 제한의 기간·범위·불참 판정은 사용자의 추가 결정 전 임의 구현하지 않는다.

## 8. 한 번에 확인할 남은 핵심 질문

> C-47(§9)로 3번의 패널티 단계는 정해졌고 나머지 질문은 세부 명세로 넘겼다. 아래는 당시 질문 원문이다.

1. 출석: ‘미참가인데 참가한 사람’은 신청 없이 실제 참석한 사람을 추가하는 의미인지, 신청 후 불참한 사람을 표시하는 의미인지(둘 다인지). 본인 참석 체크를 만든 사람이 최종 확인하는 방식인지.
2. 댓글 패널티: 참가·댓글 제한 기간은 며칠이며, 해당 모임의 연속 회차에만 적용할지 모든 모임에 적용할지. 제한 사유와 만료 시각을 본인에게 표시한다.
3. 불참 패널티: 몇 회부터 어떤 제한을 줄지, 만든 사람 확인만으로 적용할지 관리자 확인도 거칠지. 일정 변경·모임 취소는 불참 제재와 구별한다.
4. D1: 도서 미연결인지, 연결된 책의 도서관 소장/대출 불가인지. 구매 링크가 가리킬 책을 어떻게 특정하는지. 여러 저자 검색은 저자 선택으로 할지.
5. 팔로우: 다른 사용자의 공개 프로필 버튼인지. 누르면 그 사람의 글을 모아 보는 화면/필터를 제공할지, 새 글 알림까지 받을지.

## 9. 후속 결정(C-47, 2026-11-12)

| 항목 | 확정 결정 |
| --- | --- |
| G1 | 알림 내역을 모아 보는 **알림함**을 둔다. **홈 또는 내 정보 화면의 알림 아이콘**을 누르면 알림함이 열린다. C5의 "앱 안 알림 목록"을 이 알림함으로 확정한다 |
| G2 | **불참 패널티는 누적 횟수에 따라 단계적으로 올린다.** 1회 **3일**, 2회 **7일**, 3회 **30일**, 4회 **참가 불가** |
| G3 | 나머지 미결은 이 문서에서 더 묻지 않고 **각 기능의 세부 명세 작성 때 담당 주니어와 D가 정한다**(아래 표) |

- 알림함은 00 §2 "안 함"의 "알림함"을 사용자가 뒤집은 결정이다. 서버 푸시·기기 구독은 여전히 복원하지 않는다. 반납 기기 예약 알림(LOAN-3)을 알림함에 함께 보여 줄지는 세부 명세에서 정한다(서버에 저장하지 않는 로컬 알림이라 지난 내역을 남기려면 기기 저장이 필요하다). 홈과 내 정보 중 한 곳만 둘지 둘 다 둘지, 아이콘 모양·읽지 않음 표시·보관 기간은 시안과 세부 명세에서 정한다.
- 불참 패널티 단계(G2)는 사용자가 말한 숫자 그대로다. **회차를 세는 기준(누적인지 연속인지, 기간이 지나면 초기화되는지), 4회째 "참가 불가"의 기간과 해제 방법, 제한이 걸리는 범위(모든 모임인지 해당 모임인지, 댓글 제한 포함 여부)는 정하지 않았다.** 임의로 정하지 않는다.
- 아래는 §8에 남았던 질문 중 G2·G3 이후에도 닫히지 않은 것이며 **세부 명세로 넘긴다.**
