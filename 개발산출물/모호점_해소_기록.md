## 2026-11-13 계약 전 확인 답변 (AUTH-1·LIB-1·LIB-2, D 답변)

근거: D의 2026-11-13 답변, 정보나루 Open API 매뉴얼 v20260620, 네이버 책 검색 API 문서(D가 붙여 넣음). **계약서·02 본문에는 아직 옮기지 않았다**(채택은 D, 반영은 해당 Step 계약서·세부 명세 때). 표기: `가정`은 약관 해석 등 확인이 안 된 채로 진행하는 값.

**AUTH-1 (Q-15·Q-16)** — 아래 둘째·셋째 줄(자체 JWT HS256, 제공자 `id_token` 직접 검증)은 같은 날 **Q-52로 대체**됐다(Supabase Auth 경유). 첫째 줄(Google·Apple)은 그대로다.
- 소셜 로그인: Google, Apple.
- 자체 JWT는 단일 대칭키 HS256. 필수 검증은 `iss`·`exp`·커스텀 클레임 `token_type`(access/refresh) 3가지. 키 회전은 제외하고 환경변수 시크릿 교체만 둔다(교체하면 발급된 토큰이 모두 무효 → 전원 로그아웃, 임시 개발 단계라 감수, D 확인).
- Apple·Google `id_token` 검증은 상대 JWKS 공개키 캐싱과 `iss`·`aud`·`exp` 검증을 포함한다.

**LIB-1 (검색·표지·최근 본 도서)**
- 검색 결과는 20건씩 "더 보기" 버튼. 서지·표지 1순위는 네이버 책 검색(Q-39). 네이버 문서: 일 25,000건, `display` 최대 100, `start` 최대 1000, 정렬 `sim`·`date`, 응답에 `image`(섬네일)·`isbn`·`description`·`discount`. `isbn` 형식은 문서에 Integer로 되어 있어 실제 값(10·13자리 혼합 여부)은 실측한다. 이미지 저장·상업 이용 조건은 문서에 없어 미확인.
- 표지는 주소만 저장(이미지 복사 안 함). 없거나 깨지면 구글 Books API, 국립중앙도서관 API가 서브 출처(두 API는 아직 확인 안 함). 정보나루 `bookImageURL`은 "비영리 서비스의 화면 표시에 한해 이용, 복사·저장·재배포 금지"인데, D 확인으로 이 앱은 스토어 출시 계획이 아직 없고 영리 목적이 아니므로 화면 표시용으로 쓴다. `가정`: 캐시에는 URL 문자열만 둔다. 스토어 출시·수익화 계획이 생기면 RELEASE 전에 다시 확인한다. 정보나루 표지 주소는 `http://`가 섞여 있어 서버가 `https://`로 바꿔 내려준다.
- ISBN은 13자리 기준. 10자리는 서버에서 변환.
- 검색 진입 화면: 첨부 스크린샷([자료/참고_검색진입화면.jpg](자료/참고_검색진입화면.jpg))의 배치를 따른다(아이폰 17 기준 6.3인치, 2622×1206). **최근 본 도서가 스크린샷의 "최근 검색어" 자리**에 들어간다: 필 하나에 10글자를 넘으면 "…"로 줄이고 옆으로 밀어 본다, 최대 10개, 기기에만 저장(서버 부담 낮춤). → **02 LIB-01(C-46 E)의 "최근 20권·표지와 제목"과 값이 다르다. 02 반영 대기.** 스크린샷의 "인기 검색어" 자리와 광고 자리에는 검색어가 아니라 **인기 도서·테마 도서 제목**을 넣는다(검색어 집계·서버 집계 없음, 세부 배치는 시안에서 확정).
- 인기 도서: 전국은 하루 한 번 서버에 저장. 도서관별은 누가 열면 호출해 3일 캐시. 정보나루 도서관별 인기(`loanItemSrchByLib`)는 기간 지정이 가능하나 "최소 3개월 이상" 권장 문구가 있고, 통합(`extends/loanItemSrchByLib`)은 최근 30일 상위 20권 고정 — 어느 쪽을 쓸지는 LIB-2 계약서에서 정한다.
- 구매 링크는 LIB-1이 아니라 SNS 게시물 상세(LOCAL-04)에서 나온다. 02의 LOCAL-04·AC-FEED와 같다. Q-41 ②(예스24)는 LOCAL 명세 전으로 옮긴다.

**LIB-2 (도서관·소장·대출·휴관일)**
- 캐시는 DB 캐시 테이블. 소장·대출 조회는 같은 (ISBN, 도서관)을 당일 자정(KST)까지 보관. 호출 상한은 일 21,000건(정보나루 30,000건의 70%). 네이버는 별도로 일 25,000건. "알 수 없음" 처리는 응답 5초 초과이며, 도시 전체 검색에서 일부만 응답하면 응답한 곳만 보여 주고 나머지는 "알 수 없음".
- 도서관 정보는 DB에 저장하고 **매일 갱신**한다. 정보나루 `libSrch` 응답에는 변경일·수정일 필드가 없어(`libCode`·`libName`·`address`·`tel`·`fax`·`latitude`·`longitude`·`homepage`·`closed`·`operatingTime`·`BookCount`) "변동 여부만 확인"은 불가. **대안(기록)**: 전체를 받되(매뉴얼 예시 기준 1,309곳, `pageSize` 100이면 14회 안팎, 일 한도의 약 0.05%) 서버에서 해시를 비교해 달라진 곳만 DB에 반영한다. `pageSize` 최대치는 매뉴얼에 없어 키로 실측한다.
- 휴관일(Q-22): `closed`는 자유 문장(예: "매월 첫째주, 셋째주 월요일 / 법정공휴일 … 임시로 정하는 날")이다. 제공자 문구를 그대로 보여 주고, 휴관 일정을 볼 수 있도록 날짜 계산도 한다. 정기 규칙(요일, 몇째 주)과 법정공휴일은 계산하고, 임시 휴관이나 해석 실패는 단정하지 않고 원문과 "확인 필요"로 표시한다.
- 위치와 범위(Q-51): 도시 단위는 시군구(`dtl_region`). 위치를 거부하면 가장 작은 단위로 표시한다(시는 구, 구 안에 도서관이 없으면 시). 시·구는 코드가 계층이다(예: 수원시 31010 → 구 31011~31014). 세종은 29010 하나. 폐지 코드(인천 남구 23030, 군위 37310)는 쓰지 않는다. 반경은 직선거리, 지도 핀과 "내 주변 도서관" 목록에 같은 반경, 결과는 거리순.
- 도시 전체 검색: `libSrchByBook`(isbn13과 시·도 `region` 필수, 시군구 `dtl_region` 선택, 페이징)으로 소장 도서관 목록을 한 번에 받고(Q-51 ② 해소), 대출 가능은 도서관마다 `bookExist`(대출 가능은 전날 기준)로 조회한다. 호출 수는 1회 + 소장 도서관 수.
- 실시간 확인 주소표(Q-48): 시연용으로 **광주광역시 7곳 안팎 + 서울 3곳 안팎**만 만든다. 나머지 도서관은 `homepage`로 이동. 만들 도서관의 이름은 아직 정하지 않았다(대기). ISBN 검색 주소 규칙은 매뉴얼에 없어 도서관마다 직접 확인한다.
