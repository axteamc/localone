# 큐브 도서관 이름 규칙 v2 진행 (L6 후속)

상태: **N3 완료(검증 3개 반영 취합, 2026-11-19) → N4 시안 대기.** [취합](결과/큐브이름_3사검토/취합.md) §6: N4에서 물을 것 D-a~D-e(D-f는 D 결정으로 끝남), 기본값(Claude) 표. D 아이디어 "큰 글자+작은 글자" 2단 표기(D1·D3에도 적용, 글자 수는 큰 글자만, 작은 글자는 왼쪽 위 머리글자 — D 결정)도 검증 질문에 넣었다. 이름 위치·크기는 큐브 표시 별도 세션(Claude 판별: 규칙화 가능, [취합 §7](결과/큐브이름_3사검토/취합.md)) → [진행_홈큐브_디자인](진행_홈큐브_디자인.md)(이름 왼쪽 아래·크게·두 줄, 주변 큐브 배열, 색 12색). 2번 작업([진행_도서관_검색딥링크](진행_도서관_검색딥링크.md))보다 **먼저** 한다. 이유: 홈을 켜자마자 보이는 이상 표시라서(2번은 편의성 작업).

## 입력

- D 보고(2026-11-19): 홈 큐브에서 어떤 도서관은 `산수`·`사직`으로, 어떤 도서관은 `전남광주통합특별시교육청중앙`처럼 지역 이름까지 붙어서 나온다. 기준이 없어 보인다.
- 현재 규칙: [`mobile/src/features/library-visit/shortName.ts`](../mobile/src/features/library-visit/shortName.ts)(L6, 2026-11-19 D 결정 "핵심 이름만", 테스트 `__tests__/short-name.test.ts`). 정규식으로 앞말(지역·교육청·구립 등)과 끝말(도서관)을 뗀다.
- 이전에 다른 AI와 검토한 규칙안(D가 붙여 준 답변, 아래 "이전 검토안"). 그 AI는 **표기 방식을 정하지 못해 멈췄다.** 이번에도 막히는 지점이 같다.
- 실제 데이터: 광주 5개 구 29곳(2026-11-19 운영 DB 적재, 정보나루 `libSrch`). 아래 "현재 규칙 결과 표"가 기준 표다.

## 문제 진단 (현재 규칙을 29곳에 돌린 결과)

**10곳 정상 / 19곳 이상.** 원인 세 가지:

1. 지역 앞말을 정규식 모양(`{2,4}글자 + 특별시|광역시…`)으로 맞춘다. "전남광주통합특별시"(6글자)를 못 뗀다.
2. "구립"이 붙지 않은 구 이름(`광주 서구`·`광주남구`·`북구`)을 못 뗀다.
3. 기관 끝말을 `도서관`만 안다. `평생교육관`·`교육문화회관`·`기념회관`·`분관 ○○`는 그대로 남는다.

이전 검토안이 맞게 짚은 것: **정규식 대신 지역 이름 목록을 긴 것부터 뗀다.** 이 앱은 이미 시도·시군구 목록(`mobile/src/lib/regions.ts`)과 API의 `dtl_region_code`가 있어서, 도서관마다 자기 지역 이름을 정확히 안다(별도 공공데이터 불필요). 현재 코드에 이미 있는 것(범용어 `GENERIC` → 지역 붙이기, 빈 결과면 원래 이름, 겹치면 지역 붙이기)은 그대로 살린다.

이전 검토안만으로 부족한 것:
- 행정명 변경("전남광주통합특별시" = "광주광역시" = "광주")은 별칭 표가 필요하다.
- 교육청 기관·분관을 어떻게 표기할지는 **디자인 결정**이다(아래 "결정할 것").

## 결정할 것 (D, 시안으로)

화면에 제일 먼저 보이는 요소라 `CLAUDE.md` 시안 규칙의 **중심 요소**다. 말로 묻지 않고 **후보 3개를 HTML 시안**으로 나란히 보여 준다(후보마다 설명 2~3줄·실제 29곳 표기 결과·얻는 것/포기하는 것, 추천 하나).

| 결정 | 걸리는 예 | 후보가 갈리는 지점 |
| --- | --- | --- |
| 교육청 소속 기관 표기 | `전남광주통합특별시교육청중앙도서관` · `…광주학생교육문화회관` · `…금호평생교육관` | 기관 유형(평생교육관·회관)을 남길지 / 지역만 / 앞에 "교육청"을 짧게 붙일지 |
| 분관 표기 | `…중앙도서관 분관 최상준도서관` | 분관 고유명(`최상준`)만 / 본관명 포함(`중앙 최상준`) |
| 구 이름이 이름에 박힌 경우 | `광주 서구 상록도서관` · `광주남구푸른길도서관` | 구 이름 제거(`상록`) / 유지(`서구 상록`) |
| 범용어 | `중앙`·`어린이`·`시민` | 지금처럼 지역 붙이기 / 다른 방식 |

- 결정 값은 **D의 선택 그대로** 반영한다(이유를 되묻지 않는다 — D 메모리 `d-no-reason-asking`). 1순위 외 차선이 있으면 받아 시안·명세에 남긴다.

## 결정 방식: 3사 LLM 상호 검증 (D 결정 2026-11-19)

이 표기 문제는 정답이 하나가 아니라 **취향·일관성** 문제라, 한 AI의 단일 의견으로 정하지 않고 서로 다른 LLM 세 곳(Claude·GPT·Gemini 등 D가 쓰는 3사)이 서로의 안을 검증하게 해서 가장 좋은 안을 받은 뒤 D가 정한다. 이 방법은 **2번 작업에는 적용하지 않는다**(기술 확인이라 크롤링·실측으로 확정).

| 단계 | 하는 일 | 산출물 |
| --- | --- | --- |
| ① 입력 패킷 | 같은 입력을 3사에 똑같이 준다: 아래 "현재 규칙 결과 표" 29곳 + 현재 규칙 요약 + "이전 검토안" + "결정할 것" 표 + 제약(화면 글자 수 ≤ 큐브 윗면 폭, 접근성 이름·목록은 원래 이름 유지) | `개발산출물/결과/큐브이름_3사검토/입력패킷.md` |
| ② 독립 안 | 3사가 서로의 답을 보지 않고 각자 규칙안 + 29곳 적용 결과표를 낸다 | `…/안_<회사>.md` 3개(원문 그대로) |
| ③ 교차 검증 | 각 회사에게 **다른 두 회사의 안**을 주고: 29곳에서 어색한 결과, 다른 지역(서울·경기·세종·광주 광역시/경기 광주시 모호성)에서 깨질 지점, 규칙 단순성을 비평하게 한다 | `…/검증_<회사>.md` 3개 |
| ④ 취합 | Claude가 3안 + 검증을 대조표로 정리하고 **합의점 / 갈리는 점**을 나눈다. 새 아이디어를 임의로 섞지 않는다 | `…/취합.md` |
| ⑤ 시안 | 갈리는 점 중 "결정할 것" 표에 해당하는 것을 후보 3개 HTML 시안으로 만든다(시안 규칙 그대로, 명세 패널 포함) | `개발산출물/시안/큐브이름_시안.html` |
| ⑥ D 결정 | D가 고른다 → 기본 선택으로 반영하고 후보는 시안에 남긴다 | 명세·`DESIGN.md` 확정 |

- 규칙(`CLAUDE.md` 기획 단계): 3사의 안은 D가 채택하기 전에는 **제안**이다. 요구사항·계획·코드에 넣지 않고 `00_기획_원본.md` §3·§5에 "제안"으로만 적는다.
- 3사 답변 원문은 고치지 않고 그대로 저장한다(요약은 ④에만).
- 다른 지역 검증을 위해 ② 전에 **서울·세종·경기(광주시 포함) 몇 곳을 더 적재/조회**해 입력 패킷의 이름 표를 넓히는 걸 권장한다(2번 작업의 적재 도구 재사용, API 호출 수십 회).

>
> 날려야 할 말 세 종류: ① 지역 접두(광주·서울·강남구·수원시 — 시도·시군구 목록이 있어 규칙적) ② 설립주체(시립·구립·군립·도립·국립·공립·사립 — 닫힌 집합) ③ 유형 접미(도서관·작은도서관·어린이도서관·청소년도서관·정보도서관·○○분관 — 닫힌 집합에 가깝지만 변형 있음). 앞에서부터 벗기면 `시립산수도서관 → 산수`.
>
> 함정: 중앙이 고유명일 때(범용어 목록에 걸리면 지역명 되살려 `광주 중앙`) / "작은"은 "작은+도서관"이 붙어 있을 때만 유형 / 지역 접두 겹침(긴 것부터 매칭, 광주광역시 vs 경기 광주시) / 동명 도서관(표시할 때 지역을 따로) / 다 벗겨 빈 결과면 원본(안전장치).
>
> 가능하면 파싱 대신 구조화된 데이터(전국도서관표준데이터의 시도명·시군구명·도서관유형)를 쓴다.

**현재 코드와 대조:** 범용어 → 지역 붙이기·빈 결과면 원본·겹치면 지역 붙이기는 이미 구현돼 있다. 못 하는 것은 ①(정규식이라 새 행정명·구 이름에서 깨짐)과 ③의 기관 유형 확장이다.
