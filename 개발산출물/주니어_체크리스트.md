# 주니어 체크리스트 (리뷰 지적 누적)

PR을 올리기 전에 모든 항목으로 diff를 점검한다. 작은 판단이 필요할 때도 이 파일을 기준으로 삼는다.
새로운 프로젝트가 진행되며 PR 리뷰에서 지적받은 항목을 아래에 지속적으로 추가한다.

- **형식:** `- [ ] 규칙 — 출처(PR #n 리뷰 k번) — 확인 방법`
- 지적을 그대로 옮기지 않고, 다음 step에도 쓸 수 있게 **일반화**해서 적는다.
- 같은 종류의 지적이 다시 나오면 새 항목을 만들지 않고, 그 항목 앞에 **`중요`**를 붙이고 출처를 덧붙인다.

## API·호환성
- [ ] 기존 API의 응답·에러 형태를 임의로 변경하지 않는다. 신규 버전 API(`/v1` 등)와 기존 API의 격리를 확인한다.
- [ ] 없는 경로(404) 처리가 인증 인터셉터 뒤에 가려져 401이나 500으로 왜곡되지 않는지 확인한다.

## 인증·보안·데이터 수명
- [ ] 토큰 검증 시 서명뿐 아니라 발급자(iss), 대상(aud), 만료(exp), 알고리즘 고정을 검증한다.
- [ ] 사용자 A와 B 간의 데이터 격리(교차 접근 차단)가 보장되는지 쿼리 및 테스트로 검증한다.
- [ ] 공개 값과 비밀 값을 엄격히 분리하고, 비밀 키·토큰 원문이 로그나 API 응답, Git에 노출되지 않게 한다.

## 에러 처리·복원력
- [ ] 비동기 호출 실패 시 빈 catch나 에러 삼킴 없이 명확한 오류 응답이나 사용자 피드백을 제공한다.
- [ ] 외부 서비스(HTTP, JWKS 등) 호출 실패 시 매 요청마다 동기 재시도 폭주가 일어나지 않도록 백오프/캐시를 적용한다.
- [ ] 배열 또는 목록 데이터 파싱 시 항목 하나가 깨지더라도 전체 요청이 중단되지 않도록 단위별 격리 처리를 고려한다.

## 성능·동시성
- [ ] 블로킹 I/O(DB, 파일, 네트워크)를 비동기 루틴에서 호출할 때 전용 I/O 디스패처/풀에서 실행한다.
- [ ] 매 요청마다 불필요한 반복 쓰기(INSERT/UPDATE)가 발생하지 않도록 단건 조회 확인 후 변경 시에만 쓰기를 수행한다.

## 테스트
- [ ] 통과를 위한 단언 완화·기대값 끼워 맞추기·케이스 삭제·skip을 금지한다. 실패 원인은 구현·테스트·환경·데이터로 구분한다. 정당한 테스트 변경은 대상·기대 계약·사유·검증 결과를 기록한다(`docs/rules/testing-security.md` §1.1).
- [ ] 중요한 회귀는 수정 전 의도한 실패와 수정 후 통과를 확인한다. 실패 조건 설명·정적 가드↔단언 대조·실제 변이 검사 결과를 구분하고 미실행 범위를 남긴다.
- [ ] 테스트 실행 시 호스트의 외부/운영 환경변수나 원격 리소스에 절대 연결되지 않도록 격리(로컬 임시 컨테이너, 모의 객체 등)한다.

## 범위·검증·기록
- [ ] 새 로직 작성 전 기존 정의·호출부를 검색하고 핵심 재사용 심볼·경로·목적 또는 미재사용 사유를 기록한다.
- [ ] 참조는 실제 도구 출력과 대조한다. 줄 번호는 도구 확인값만 쓰고 핵심 계약의 시그니처·최소 원문을 확인한다. 생략·정규화와 미확인 범위를 표시하고 파일 변경·근거 유실 시 재조회한다.
- [ ] **중요** 완료 기준을 실제로 실행하지 않았으면 "완료"로 표시하지 않는다. 실행 로그/출력을 결과 파일에 첨부한다.
- [ ] 작업과 무관한 파일(개인 메모, 빌드 부산물, 미사용 DTO)을 커밋에 포함하지 않는다.
