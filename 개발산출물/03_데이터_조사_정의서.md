# 03. 데이터 조사·정의서

> 상태: **골격 — 미작성**. 담당: D. 선행: 제공자 확정(지도·서지, [모호점 Q-12·Q-13](모호점_해소_기록.md))과 키 발급 후 실측. 갱신 시점: LIB-1·LIB-2 명세 착수 전, 이후 제공자가 늘 때마다.
> 입력: [02 요구사항 §7](02_요구사항_정의서.md), [04 도메인 모델](04_도메인_모델_정의서.md).

## 작성할 내용

1. **데이터 목록 요약**: 데이터 ID, 출처, 갱신 주기, 저장 위치(05), 담당 Feature
2. **상세 정의** (제공자별): 호출 방법, 요청 파라미터, 응답 필드, 식별자(도서관 코드·ISBN), 단위·시간대, 갱신 시점, 오류·한도 동작
   - D1 도서관 소장·대출 가능(도서관 정보나루) — 현재까지 확인: 대출 가능은 조회 전날 기준으로 안내됨(02 §7). 쿼터·갱신 SLA는 **미확인**
   - D2 도서 서지·표지(네이버 책 검색 API, 사용자 지정) — 응답 필드·일일 한도·표지 사용 조건 **미확인**(Q-41)
   - 구매 연결(예스24 Open API) — Goods API 존재는 확인, 구매 링크 생성·제휴 요건 **미확인**(Q-41)
   - D3 지도·도서관 좌표(후보 미정) — 출시 지역·도서관 범위 **미결정**
   - D4 도서관 휴관일 — 출처 미정
3. **식별자 매핑**: 제공자 도서관 ID ↔ 내부 도서관 ID, ISBN10/13 정규화
4. **이용 조건**: 호출 한도·표기 의무·재배포 제한(README에도 명시)
5. **실측 결과**: 키 발급 후 샘플 호출 결과, 형식 변경 위험, 호출 상한 값(03에서 정한 값은 계약서로 이관)
6. **전처리 규칙**: 누락·중복·좌표 없음 처리(좌표 없으면 거리 계산 불가 표시)
