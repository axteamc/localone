## 0. 검토 방식 (2026-11-17 결정, 모든 묶음 세션이 따른다)

### 0.1 진행 순서

1. 검토 지도(파일·줄 수·커밋만): 끝남. 결과가 위 상태표다.
2. 묶음별 검토 ①→②→③→④를 **한 번씩** 한다. 커밋 순서로 읽지 않고 `git diff f0a98e1 1ee1bab -- <범위>`의 최종 결과만 읽는다. LIB-2·LIB-3은 `book-search/` 파일을 함께 고쳐서 한 묶음으로 묶었다.
3. ④ 통합은 기능 사이 연결만 본다(아래 §0.3).
4. 고성능 모델은 전체를 다시 읽지 않고 §0.4 목록만 맡는다. 독립 이중 검토보다 놓칠 수 있다는 점은 받아들인다.

### 0.2 묶음 세션 규칙

- 범위는 상태표 `범위` 칸에 있는 파일 + 판단에 필요한 호출부·계약·테스트까지만 읽는다. 무관한 파일, 이미 다른 절에서 본 파일, 저장소 전체 덤프는 읽지 않는다.
- 우선순위: 정확성 → 권한 → 데이터 무결성 → 비동기 상태 → 계약 위반.
- 결함은 `file:line`, 발생 조건, 사용자 영향, 근거로 적고 결함 표에 ID(`③-1` 등)로 추가한다.
- 절 끝에 "검토한 범위 / 안 본 범위"를 쓴다.
- 범위가 커지면 그때까지의 결과와 더 읽어야 하는 이유를 먼저 보고하고 묻는다.
- 시험: SHA가 고정돼 있으므로 **mobile jest는 다시 돌리지 않는다**(①·②에서 24 suites / 319 tests 통과). server pytest는 시험 DB(`localhost:5433`)가 없어 미실행이다. DB를 띄우는 것(`docker compose up -d --wait db` → `alembic upgrade head` → `pytest -W error`)은 사용자 승인이 필요하다. 승인을 받으면 한 번만 돌리고 결과를 §0.4에 적는다.
- 파일 수정(이 문서와 인수인계 메모 말고)·커밋·push·PR 코멘트는 하지 않는다.
- **고성능 모델 이관 알림:** §0.4 기준에 맞는 것을 찾으면 §0.4 표에 한 줄을 추가하고, 최종 보고 **첫 줄**에 `고성능 모델 이관 후보: <ID> — <한 줄>`로 알린다. 없으면 `고성능 모델 이관 후보: 없음`이라고 쓴다.

## 1. 묶음 ① LOCAL-2 (2026-11-17, mac)

### 1.1 테스트 (한 번만 실행)

- mobile jest: **24 suites / 319 tests 전부 통과.**

### 1.2 결함

**①-1 카드 메뉴 공감·북마크 동시 토글 덮어쓰기 (중간)**
- 위치: `mobile/src/features/local-feed/PostMenu.tsx:86-90`
- 발생 조건: 메뉴에서 ♡를 누르고 응답 전에 🔖를 누름. 연타 방지가 종류별(`busy.current[kind]`)이라 두 요청이 동시에 나간다.
- 사용자 영향: 서버는 둘 다 반영됐는데 화면은 북마크만 켜지고 공감이 "좋아요"로 되돌아감.
- 근거: `onChange({ ...post, ... })`가 누른 시점 렌더의 `post`를 캡처한다. 부모 `LibraryFeed.tsx:102`가 `changed[p.id] = p`로 객체 전체를 바꿔 늦은 응답이 앞선 응답을 덮는다.

**①-2 피드 메뉴 상태 고착 (중간)**
- 위치: `mobile/src/features/local-feed/LibraryFeed.tsx:65-72`
- 발생 조건: (a) 메뉴에서 공감 → 상세에서 취소 → 피드로 돌아옴: 메뉴는 "좋아요됨". (b) 메뉴에서 바꾼 뒤 피드를 다시 불러와도 `changed`가 서버 값을 덮음.
- 사용자 영향: 한 번 눌러도 변화가 없어 두 번 눌러야 원하는 상태가 됨. 서버는 `PUT`/`DELETE` 멱등(계약 H5·H6)이라 데이터 손상은 없음.
- 근거: 상세→피드 동기화는 철회(`emitPostWithdrawn`)만 있다. `changed`는 언마운트 전까지 비워지지 않는다.

### 3.4 확인했고 문제없는 것

- 방문 페이지 이동: 블록 누름 → `openLibrary`는 서버 `distance_m`(0 이상 안전한 정수일 때만)을 넘기고, 블록에 보이는 직선거리 대체값은 넘기지 않는다. V5·core K15와 같다. `+N곳 ↻`은 칸 안 전환만 하고 이동하지 않는다.
- 늦은 응답·연타: 조회 흐름(`useHomeLibraries`)은 바뀌지 않아 러너 하나로 앞 요청을 버린다(V14). 기준점이 바뀌면(`viewSeq`·`libraries`) 전환해 둔 칸을 처음으로 되돌린다.
- 오류·빈 결과·위치 거부: 예외 #1 문구 + `reloadHere(center)`, 예외 #2 + "더 넓게 찾기"(5km면 숨김), "위치 허용하기"와 "현재 위치로"는 함께 뜨지 않음(V7·V10). 불러오는 중 알약(V15), 로그인 없이 보임(V16). 검색창 본문과 "도서관 찾기"는 터치 영역이 따로(V6).
- 스파인 색: 휴관 우선 `pinClosed`, 영업 중 가장 가까운 곳 `fill1`, 나머지 `fill2`·`fill3` 교대 — 문서 85:10:5 규칙과 같다. `library-visit/`에 `#RRGGBB` 하드코딩 없음(P5 시험 규칙).
- 남은 참조: `LibraryList`·`LibraryMap`·`KakaoMap`을 `library-visit/`(시험 제외)·`mobile/app`에서 더 부르지 않는다. `deps.ts`는 `LatLng` 타입만 남겼고, `KakaoMap` 자체는 `lib/map`에 그대로라 book-search 쪽은 영향 없음.
