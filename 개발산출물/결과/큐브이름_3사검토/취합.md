작성: Claude (Opus 5.5), 2026-11-19, D 지시. 상태: **검증 3개 반영 완료. 4안 모두 제안(미채택).** D가 채택하기 전에는 요구사항·계획·코드에 넣지 않는다. 2단 표기(§7)는 D가 정한 방향이다.

- 대상 안 4개(같은 폴더 [입력패킷](입력패킷.md)을 보고 따로 씀): [안_claude](안_claude.md)(**C**) · [안_codex](안_codex.md)(**X**) · [안_gemini](안_gemini.md)(**G**, 코드를 읽고 씀) · [안_gemini_web_완전독립](안_gemini_web_완전독립.md)(**W**, 패킷만 보고 씀).
- 검증 3개: [검증_claude](검증_claude.md) · [검증_gemini](검증_gemini.md) · [검증_codex](검증_codex.md). 요청문은 [검증요청](검증요청.md)(50곳 비평 + 전국 실데이터 E01~E53 + 2단 표기 평가).
- 새 아이디어를 섞지 않았다. 칸마다 4안이나 검증 3개 가운데 하나 이상에 근거가 있다. 어느 안에도 없는 보강(§3.3)과 구현 전에 고정할 것(§6.2)은 **제안**으로만 적었다.
- [취합_gemini](취합_gemini.md)(Gemini가 따로 쓴 짧은 취합)는 근거로 쓰지 않았다.

### 3.5 세 검증의 추천과 취합 의견

| 검증 | 추천 | 이유 (검증의 말, 줄임) |
| --- | --- | --- |
| 검증_claude (C 못 봄) | **G**에 X의 판 전체 재그룹화를 합치고, X의 공백 경계 규칙을 G 3군에만 가져온다 | 실데이터 틀린 글자가 가장 적다 / G의 "기관 이름 보존"이 작은 글자로 그대로 옮겨진다 / `dtl_region_code`를 먼저 써서 E30·광주 주소 위험을 피한다 |

- **세 검증이 같은 것:** 판 전체 재검사가 필요하다. 낱말 경계 없이 구 이름을 떼면 안 된다. 글자 수는 화면처럼 공백을 포함해 센다. X·W는 기본 안으로 추천하지 않았다(Codex는 X를 평가하지 않음).
- **다른 것:** 기본 안. C와 G를 함께 본 Codex는 어느 쪽도 고르지 않았고, 두 안에 비슷한 무게의 보완 거리(S2)를 냈다. G 3건, C 2건이다.

**취합 의견(Claude):** 2단 표기를 넣으면 C·G의 화면 결과는 거의 같아진다(§3.4). 남는 차이는 구현 쪽이다.

| 구현 쪽 차이 | C | G |
| --- | --- | --- |
| 지역 입력 | 주소(둘째 낱말까지) → `area_label` | `dtl_region_code` → 주소 → `area_label` |
| 통합 행정명 | 광주가 아니면 전남으로 확정(C-2) | `canonicalSido: null`, 도서관의 시도를 따름 |

| 낱말 경계 버그 | E52 | E39·E52, G-1 |
| 공개 함수 | `regionOf` 반환형을 바꿈(C-1) | 기존 함수 유지, `REGIONS` 재수출 추가 |
| 정식 단계의 빈틈 | 분관 규칙이 문서 안에서 어긋남 | 지역 우선순위 반대(G-2), 동명 군·구 승격 없음(G-3) |

그래서 기본 안은 화면을 바꾸지 않는 구현 선택으로 보고 **기본값(Claude): G 기반**을 그대로 제안한다. Codex의 G 지적 세 건(G-1~G-3)은 §6.2에서 고정할 것으로 받는다. 이유는 코드 사실 세 가지다.

2. 공백 포함 글자 수가 이미 화면과 같다.
3. 공개 함수 `regionOf`를 바꾸지 않는다. C-1처럼 계약 C2 함수 줄을 흔들지 않는다.

단, 방문 모음(MY-3) 응답에는 `dtl_region_code`가 없다(§5). 그래서 주소로 대신 판정하는 단계를 지울 수 없다. C는 취합을 쓰는 Claude 회사의 안이라서 근거를 코드 사실로만 적었다. D가 C 기반을 원하면 말해 달라.

| `본관이름 ○○분관` | **14** | 상주도서관 **화령**분관, 안동도서관 **용상**·**풍산**분관, 부산광역시립중앙도서관 **수정**분관, 유성도서관 **엑스포**분관, 군산학생교육문화관 **대야**분관 | 전부 **동·읍·면 이름**(엑스포만 지역 명소) |

- **사람 이름은 16곳 중 1곳**, **숫자 분관(`제2분관` 등)은 0곳**이다. 사람 이름인지 지명인지는 규칙으로 가려낼 수 없지만(3글자 이름과 3글자 지명이 모양이 같다), **"분관" 글자의 위치만으로 고유명을 뽑을 수 있어서 가려낼 필요가 없다.**
- 같은 본관의 분관 둘(`안동 용상`·`안동 풍산`)도 큰 글자가 서로 달라 겹치지 않는다.
- 검증 뒤 덧붙임: 첫 모양(14곳)은 4안 모두에 규칙이 없다(§3.3 M1). E09처럼 공백 없이 붙은 이름(`마포평생학습관아현분관`)도 "분관" 위치로 `아현`은 뽑힌다. 본관 이름을 어디까지로 볼지는 D-e에 따라 필요할 때만 정한다.

### 7.4 화면 제약 (코드 사실, 지금 배치 기준)

- 주변 큐브는 큰 글자가 이미 약 12.5px이라, 작은 글자를 그보다 작게 하면 8px 안팎이 된다. 검증_claude는 걸친 큐브의 작은 글자가 6px 이하로 내려가면 사실상 안 읽힌다고 봤다(추측).
- 접근성 이름은 지금처럼 원래 이름 전체라 2단 표기와 무관하다. 검증_codex도 접근성 이름 유지를 공통 후보로 꼽았다.
- 검증_claude·검증_gemini가 공통으로 꼽은 화면 위험(추측, 실제 렌더 측정 필요):
  1. 큰 글자가 2줄(7자 이상)이면 윗줄과 왼쪽 위 작은 글자가 겹치거나 마름모 밖으로 나갈 수 있다.
  2. 작은 글자가 큰 글자보다 길면(`평생교육관` > `금호`) 머리글자처럼 보이지 않는다.

- (1차 취합에서 쓴 "작은 글자를 큰 글자 위/아래 줄에" 가정은 §7.6 D 그림으로 바뀌었다.)

### 7.5 D1~D3과의 관계 — D 결정 (2026-11-19)

- **D 결정: D1(교육청 기관 유형)·D3(경기 광주시)에도 2단 표기를 쓴다.** D의 말: "지금 방식대로 쓰면 적절한 글자 길이가 훨씬 길어져서 괜찮을 거 같아. `금호(큰글자) 평생교육관(작은글자)`처럼 쓰일텐데, 7글자나 되지만 실질적으로 바로 눈에 들어오는건 무게감의 차이 때문에 금호 2글자로 느껴질테니까."
- 따라서 **글자 수 제약은 큰 글자 기준**으로 본다. 작은 글자는 큰 글자 길이 판단에 넣지 않는다.

### 7.6 작은 글자 자리 — D가 그림으로 정함 (2026-11-19)

| 항목 | D의 그림 |
