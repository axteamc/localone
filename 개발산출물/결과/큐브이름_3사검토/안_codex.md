# 큐브 도서관 이름 규칙 v2 — Codex 독립안

작성일: 2026-11-19. 작성: Codex. 상태: **검토용 제안·미채택**.

입력: 같은 폴더의 `입력패킷.md` 전부. 다른 모델의 독립안은 열람하지 않았다. 아래는 이 응답의 원문이며, 제품 요구사항·계약 변경이나 구현 완료를 뜻하지 않는다.

## 1. 제안의 중심

**지역·설립주체·기관 유형은 확인되는 부분만 걷어 내고, 이용자가 기억할 이름은 남긴다.** 2~6자를 우선하되 7~8자를 허용한다. 글자 수를 맞추려고 고유명을 중간에서 자르거나 임의의 두문자어로 만들지 않는다. 잘못 줄이는 것보다 원래 이름이 길게 보이는 쪽을 안전장치로 택한다.

예를 들면 `광주 서구 상록도서관`은 `상록`, `금호평생교육관`은 `금호`, `운남어린이도서관`은 `운남어린이`다. `작은도서관`은 시설 유형으로 떼지만, `어린이`·`청소년`·`영어`·`정보문화`는 이름을 알아보는 데 필요한 말로 남긴다.

교육청 소속임을 모든 큐브에 반복해서 쓰지는 않는다. 분관은 독자적인 이름이 있으면 그 이름을 우선한다. `중앙`처럼 범용어만 남거나 지역명 자체가 모호하면 짧은 지역 표기를 붙인다.

현재 로컬 HEAD는 `e7e34355d0cfa368328cd4c5608d619da5ed995c`다. 구현 전제는 다음 소스를 직접 읽어 확인했다.

핵심적인 입력 제약이 있다. 패킷의 도서관 객체와 현재 `cubeNames` 인수는 `id`, `name`, `address`, `area_label`이며 **`dtl_region_code`는 포함되어 있지 않다**. 따라서 표의 정보나루 코드를 런타임에서 읽을 수 있다고 가정하면 안 된다. 주소의 행정구역을 `REGIONS`와 대조하고, 이름의 명확한 행정 접두를 보조로 사용해야 한다. 이 안은 필드를 추가하거나 별도 API를 부르는 것을 전제로 하지 않는다.

광주 29행에는 개별 주소·`area_label`이 제공되지 않았다. §5.1은 표에 기재된 시군구와 이름의 접두가 일치한다는 조건에서 도출한 예상 결과다. 실제 객체의 주소 품질까지 검증한 결과는 아니다. 타 지역 21행은 패킷에 있는 주소를 사용한다. 어느 표도 현재 코드 실행 결과가 아니다.

표시 문자열만 달라진다. 접근성 이름, 검색, 방문 페이지, 목록, 저장된 `name`은 원문을 사용한다. 순수 문자열 처리이므로 JWT·DB·트랜잭션·플랫폼 분기를 새로 도입할 이유가 없다.

## 3. 규칙 설계

### 3.1 필요한 데이터 구조

아래 이름은 설계상 제안이며 새 export나 구현 본문을 뜻하지 않는다.

| 구조 | 내용 | 사용 조건 |
| --- | --- | --- |
| 지역 색인 | `REGIONS`의 시도·시군구 조합, 정식명·짧은명, 중복되는 짧은명의 역색인 | 전국 지역명을 무조건 삭제하는 목록으로 쓰지 않는다. 입력 주소와 일치하는 후보로 좁힌다. |
| 행정 별칭 | 정식 지역과 대응하는 이름·주소용 표기 변형 | `서울`↔`서울특별시`, `경기`↔`경기도`, `세종시`↔`세종특별자치시`. 나머지 시도도 실제 `REGIONS`에서 대응시킨다. |
| 패킷 호환 별칭 | `전남광주통합특별시` → 패킷의 광주광역시 계열 | 이 패킷의 24010~24050 대응을 처리하기 위한 제한된 별칭이다. 실제 행정구역 개편 사실로 선언하지 않는다. 주소가 전라남도라는 이유만으로 광주로 바꾸지 않는다. |
| 설립·운영 접두 | `교육청`, `시립`, `구립`, `군립`, `도립`, `공립`, `사립` | 이름 맨 앞이나 확인된 행정 접두 직후에서만 제거한다. `국립`은 유지한다. |
| 기관 끝말 | 긴 순서로 `작은도서관`, `공공도서관`, `도서관`, `평생교육관`, `교육문화회관`, `기념회관`, `교육문화원`, `자료실` | 마지막 기관 유형 하나만 제거한다. 남는 이름이 2자 이상일 때만 채택한다. 일반 `회관`·`관`을 무차별 제거하지 않는다. |
| 분관 표식 | 독립 토큰 `분관`, 단독 괄호 `(분관)`·`[분관]` | 고유명과 표식을 구별한다. 임의의 괄호 속 단어를 버리지 않는다. |
| 범용어 | 기존 `중앙`, `어린이`, `청소년`, `작은`, `공공`, `시민`, `구민`, `평생학습`, `정보`, `기적의`, `본관`, `분관` + 제안 `학생`, `교육문화원`, `학습관`, `자료실` | 전체 핵심 이름과 정확히 같을 때만 지역을 보충한다. 포함 여부로 검사하지 않는다. |
| 내부 분석 결과 | 원문, 핵심명, 제거한 행정 접두의 단계, 실제 소재 지역, 분관명·본관명, 불확실성 | 제거한 지역을 잃지 않아야 범용어 복원과 충돌 해소가 가능하다. 외부 응답 필드로 추가하지 않는다. |

기관 끝말의 순서는 길이 내림차순을 기본으로 한다. 같은 길이의 우선순위는 고정한다. `어린이도서관`·`청소년도서관`·`영어도서관`·`정보문화도서관` 전체를 삭제할 접미사로 등록하지 않는다. 이들 이름에서는 마지막 `도서관`만 제거한다.

### 3.2 처리 순서

1. **정규화와 원문 보존.** 원문을 별도로 보관한다. 분석용 문자열에는 NFC 정규화와 앞뒤 공백 정리를 적용하고, 연속 공백은 하나로 합친다. 접두·접미 비교를 위해 공백을 무시하는 보조 표현을 쓰되 원래 토큰 경계와 원문 위치는 보존한다. 한글이 없는 이름은 원문을 반환한다.
2. **지역 확인.** 주소 시작 부분의 시도 → 시군구를 `REGIONS`의 계층과 대조한다. 도로명·건물명에서 `구`·`시`로 끝나는 말을 검색하지 않는다. `area_label`은 같은 지역에서 충돌을 좁힐 보조 값이며, 그것만으로 시도를 추정하지 않는다. 주소가 없으면 이름의 정식 행정 접두로 유일하게 확인되는 단계까지만 사용한다. `광주` 같은 중의적 짧은명만 있으면 특정 지역을 확정하지 않는다.
3. **별칭·접두 후보 분석.** 이름 왼쪽에서 확인된 지역의 별칭을 긴 것부터 매칭한다. 시도·시군구의 순서를 지키고, 설립·운영 접두를 사이에 허용한다. `광주광역시립`·`광산구립`·`광주시립`은 각각 해당 지역명과 `시립`·`구립`이 결합한 형태로 인식한다. `교육청` 뒤에 지역·설립 접두가 다시 나오는 `서울특별시교육청서울시립…`도 처리한다. 제거한 지역은 기록한다.
4. **분관·괄호 분석.** 토큰 경계가 보존된 문자열에서 `본관명 + 분관 + 분관 고유명`을 인식한다. 뒤쪽이 정상 기관명으로 분석되고 핵심이 2자 이상이면 분관 이름을 선택한다. 끝의 단독 `(분관)`·`[분관]`은 표식으로 분리한다. 다른 괄호, 짝이 안 맞는 괄호, 분관 구분이 여러 번 나오는 모호한 구조는 원문을 반환한다. 분관명 자체에 행정·설립 접두가 있으면 같은 제한 규칙을 적용한다.
5. **기관 끝말 제거.** 선택한 기관명 끝에서 가장 긴 유형 하나를 제거한다. `작은도서관`은 앞에 2자 이상의 이름이 있을 때 통째로 뗀다. `교육문화원 학습관자료실`에서는 마지막 `자료실`만 떼어 `교육문화원학습관`을 남긴다. 중간 `교육문화원`·`학습관`까지 재귀적으로 지우지 않는다.
6. **과잉 삭제 되돌리기.** 최종 핵심이 2자 미만이면 접두 제거 후보를 뒤에서부터 되돌려 유효한 이름을 찾는다. 단순히 중간 문자열이 2자 이상이라는 이유로 접두 제거를 확정하지 않는다. 예: `세종시립도서관`은 `세종`을 보존하고, `종로도서관`은 `종로`를 보존한다. 지역까지 되돌려도 의미 있는 이름이 없으면 원문이다. 도서관 없이 다른 유형만 있는 입력도 같은 안전장치를 쓴다.
7. **범용어·지역 모호성 보정.** 범용어만 남으면 제거했던 행정명 중 가장 구체적인 지역을 앞에 붙인다. 구 이름까지 제거했으면 `남구 청소년`, 교육청의 시도 접두만 있었으면 `광주 중앙`·`서울 어린이`다. 제거한 지역이 없으면 주소에서 확인한 구·군 또는 시를 쓴다. 지역 확인이 안 되면 범용어만 내보내지 않고 원문을 쓴다. 지역명 자체가 핵심인 경우도 역색인으로 모호성을 확인한다. 경기 광주시의 `광주`는 `경기광주`, 그곳의 `중앙`은 `경기광주 중앙`으로 쓴다.
8. **길이 확인.** 2~6자는 우선 목표, 7~8자는 허용 범위다. 그보다 길어도 고유명 임의 절단은 하지 않는다. 지역을 붙일 때는 한 칸을 쓰고, 핵심 내부의 분석용 공백은 합친다. 실제 렌더러와 맞춰 글자 수는 공백을 포함한 `[...label].length`로 센다.
9. **판별 충돌 해소.** 아래 §3.4대로 같은 판에 표시되는 이름 전체를 처리한다. 이후 생긴 긴 이름도 자르지 않는다.

지역 접두 제거는 단순한 `startsWith` 반복만으로 구현하면 안 된다. 주소와 맞는 지역이라도 `서울숲`·`광주학생`처럼 고유명과 이어질 수 있다. 정식 행정명·지역+설립표시는 명확한 근거이며, 짧은 지역명은 원래 공백 경계 또는 이미 확인된 행정/교육청 머리말 뒤에 있을 때만 제거한다. 이 규칙에 따라 `…교육청광주학생…`의 두 번째 `광주`는 제거할 수 있지만, 아무 접두 없는 `서울숲도서관`의 `서울`은 남긴다. 시군구의 정식명도 뒤에 기관 유형만 남는 경우에는 보존한다. 동·읍·면 이름은 자동 제거 대상이 아니다.

### 3.3 지역 표시 원칙

`광주`가 주소의 `광주광역시`인지 `경기도 광주시`인지는 주소에서 판단한다. 이름이 같다는 이유로 서로 합치지 않는다. 역색인에서 중복되는 짧은 지명은 상위 지역을 붙여 구분한다. 이 안은 광역시 쪽에 `광주`, 경기 시 쪽에 `경기광주`를 사용한다. 이는 패킷에 대한 표시 제안이지 행정명 변경 제안이 아니다.

`서구`·`남구`·`중구`처럼 짧게 줄이면 의미가 없어지는 구 이름은 그대로 둔다. `강남구`·`종로구`는 표시 시 `강남`·`종로`로 줄일 수 있다. 같은 판에 서로 다른 시도의 `서구`가 등장하면 `광주서구`·`대전서구`처럼 상위 지역을 보충한다.

지역 표시는 소속 기관의 관할과 실제 소재지를 구분한다. 이름의 교육청 지역과 주소가 명백하게 다르면 확인되지 않은 행정 접두를 억지로 지우지 않고 원문으로 돌아간다. 데이터 불일치를 자동으로 고쳐 쓰지 않는다.

### 3.4 `cubeNames` 충돌 해소

대상은 현재 판의 최대 7곳이다. 입력 순서나 정렬 순서로 이름이 달라지지 않게 한다.

1. 같은 `id`의 중복 항목은 하나의 기관으로 취급한다. 같은 `id`인데 이름·주소가 서로 다르면 입력 오류이며 임의로 다른 기관처럼 번호를 붙이지 않는다.
2. 기본 이름을 만든 뒤, NFC와 공백 정규화 기준으로 같은 이름을 묶는다.
3. 충돌하는 항목에만 실제 소재지의 구·군 또는 시를 붙인다. 이미 포함한 지역은 반복하지 않는다. `중앙`에 붙인 기본 지역이 너무 넓으면 지역 한정자를 더 구체적인 것으로 바꾼다.
4. 여전히 같으면 시도+시군구로 넓히고, 그다음 `area_label`을 추가한다. 값이 없거나 이미 포함됐으면 그 단계를 건너뛴다. 주소 전체나 도로명 일부를 이름으로 추측하지 않는다.
5. 분관이면 앞 단계에서 보존한 본관명을 한정자로 사용할 수 있다. 예: 같은 구의 두 `최상준`이 있을 때 서로 다른 본관명이 확인되면 `중앙 최상준`처럼 구분한다.
6. 그래도 같거나 안전한 한정자를 만들 수 없으면 원래 `name`을 사용한다. 모든 단계 뒤 **판 전체를 다시 그룹화**한다. 새로 붙인 이름이 원래부터 그 이름이었던 다른 항목과 충돌하는 경우도 처리해야 한다. 필요한 한정 수준을 올리기만 하므로 단계 수는 유한하다.
7. 원래 이름까지 같으면 현재 입력만으로 사람이 읽기 쉬운 고유 이름을 보장할 수 없다. 같은 원문을 유지하고 미해결 충돌로 남긴다. `id`나 표시 순번을 큐브 이름에 붙이는 정책은 이 안에 추가하지 않는다.

예: 광주 북구·경기 광주시의 `중앙`은 서로 다른 지역 표시가 붙는다. 서로 다른 구의 `상록`은 `서구 상록` 같은 형태로 바뀐다. 같은 구·같은 동·같은 이름이면 원문으로 돌아가도 충돌할 수 있다는 한계를 명시한다.

## 4. 네 가지 결정 쟁점에 대한 제안

| 쟁점 | 제안 | 이유·포기하는 것 |
| --- | --- | --- |
| 교육청 소속 기관 | 교육청 표시는 생략하고 확인된 기관 유형 끝말을 제거한다. `중앙`→`광주 중앙`, `광주학생교육문화회관`→`광주 학생`, `금호평생교육관`→`금호`, `학생독립운동기념회관`→`학생독립운동` | 큐브에서 장소를 찾는 데 집중한다. 운영 주체와 기관 유형은 큐브에서 사라지므로 방문 화면·접근성 원문으로 보완한다. 특히 `광주 학생`의 현지 인지도는 후속 시안에서 확인할 지점이다. |
| 분관 | 별도 고유명이 있으면 `최상준`. `(분관)`만 붙어 있으면 표식을 빼고 `논현문화마루` | 가까운 큐브에서 분관의 실제 이름을 빨리 찾는다. 본관과의 관계는 기본 표기에서 생략하며 충돌 시에만 복원한다. 고유명 없는 분관은 `분관`을 보존하고 지역을 붙이거나 원문을 쓴다. |
| 이름에 박힌 구 이름 | 주소와 일치하는 행정 접두이면 제거한다. `상록`·`푸른길`·`신용` | 같은 구의 도서관마다 행정명을 반복하지 않는다. 다만 `종로도서관`처럼 지역명 자체가 유효한 핵심이면 되돌려 보존한다. |
| 범용어·지역 모호성 | 범용어는 지역을 보충한다. 광역시 `광주 중앙`, 경기 시 `경기광주 중앙`, 경기 교육청 `광주도서관`은 `경기광주` | `중앙`만으로는 구분하기 어렵다. 전국 지명의 중복은 별도 상위 지역으로 해소하고, 고유명은 충돌할 때만 길게 만든다. |

`운남어린이`, `못골한옥어린이`, `일원라온영어`, `도곡정보문화`, `문화정보`는 수식어를 남긴다. 모든 형태를 기계적으로 가장 짧게 만드는 것보다 기존 명칭과의 연결을 우선한 선택이다.

## 6. 전국 확장의 엣지케이스와 방어

| 조건 | 위험 | 제안하는 방어·예상 동작 |
| --- | --- | --- |
| 이름에만 `광주`, 주소 없음 | 광역시와 경기 시 혼동 | 지역 확정 보류. 행정 접두를 지워 범용어만 남길 상황이면 원문 유지 |
| 주소가 `서울특별시 강남구…`인데 이름은 명백히 다른 시도 기관 | 잘못된 별칭·관할 추정 | 불일치 상태로 원문 유지. 자동 데이터 교정 금지 |
| `서울숲도서관`, `부산꿈나무도서관` | 짧은 시도명이 고유명 일부 | 경계 없는 짧은 지역명은 무조건 제거하지 않음 |
| `종로도서관`, `한솔동도서관`, `개포4동 작은도서관` | 장소명 자체가 이름 | 기관 유형 제거 뒤 남는 지명 보존. 동·읍·면은 삭제 목록에서 제외 |
| `국립중앙도서관` | 국립 제거 후 일반 중앙으로 오인 | `국립중앙` 유지. `국립`은 고유 식별 요소로 취급 |
| `작은도서관`, `어린이도서관`, `시립도서관` | 유형만 남거나 빈 문자열 | 긴 유형 제거가 실패하면 짧은 `도서관` 제거 후보를 검토. 범용어에는 확인된 지역 보충. 유효한 2자 핵심이 없으면 원문 |
| `꿈도서관` | 유효한 1자 이름을 억지로 보충 | 기존 최소 2자 안전장치대로 원문 `꿈도서관` 유지 |
| `작은숲도서관`, `작은도서관이야기도서관` | 이름 안의 작은·도서관 손실 | 문자열 끝의 유형 하나만 제거. 중간 낱말 삭제 금지 |
| `도서관(신관)`, `○○도서관(구 △△)` | 괄호에 구분 정보 존재 | 분관 표식 외 괄호는 원문 유지. 분관·신관을 같은 것으로 취급하지 않음 |
| `분관도서관`, `분관 분관 ○○도서관` | 고유명과 표식 혼동 | 독립 토큰·단일 구조가 아니면 분관 분리 보류 |
| `○○도서관 분관`, `○○도서관(분관)` | 독립 분관 고유명 없음 | 뒤에 붙은 독립 토큰 `분관`만 있고 분관명이 없으면 `○○ 분관`처럼 보존한다. 단독 괄호 표식은 §3.2대로 생략한다. 둘을 동일한 문법으로 추정하지 않는다. |
| 같은 구의 동명 분관 두 곳 | 지역을 붙여도 충돌 | area_label·본관명 → 원문. 입력으로 구분 불가능하면 충돌 미해결로 명시 |
| 영문·숫자·기호 혼합 이름 | 폭·문자 수 차이 | 한글 없는 이름은 원문 유지. 혼합명은 숫자·기호를 삭제하지 않고 기관 접미만 제한적으로 처리 |
| 새로운 행정명·폐지 코드·별칭 중복 | 오래된 사전의 오삭제 | 확인된 별칭만 등록. 모르는 행정명은 글자 수 정규식으로 잡지 않고 보수적으로 원문 유지 |
| 244개 행이 포괄하지 않는 주소 계층 | 이름만으로 행정구역 추정 | 목록이 확인해 주는 수준까지만 사용. 상위 지역 확인과 세부 지역 미확인을 구별 |
| 8자를 넘는 실제 고유명·충돌 해소명 | 무리한 절단으로 정체성 손실 | 원문 또는 긴 유효 이름 유지. 별도 표시 정책은 시안에서 결정 |
| 판의 도서관 구성이 바뀜 | 충돌 여부에 따라 이름이 길어졌다 짧아짐 | 기존 판 단위 정책의 결과로 명시. 기본 이름은 고정하고 한정자만 바뀌게 함 |

괄호형 분관은 그 앞 이름이 독립 고유명인지 입력 필드만으로 확정할 수 없다. 이 안은 구체적인 표기 정책으로 단독 `(분관)`·`[분관]`을 생략하는 쪽을 택한다. 본관과 같은 이름을 쓰는 기관이면 구분 정보가 줄어드는 대가가 있다. 같은 판에서는 충돌 해소로 원문까지 복원하고, 판 밖의 본관과의 관계는 원문을 표시하는 방문 화면·접근성 이름에서 확인하게 한다. 전국의 모든 분관이 고유명만으로 식별된다고 보장하지 않는다.

## 7. 채택 전 확인할 것과 현재 검증 범위

다음은 구현 단계에서 필요한 확인 항목이며 **이번에 실행한 테스트가 아니다**.

- 50행의 기본 이름과 공백 포함 글자 수를 고정한 뒤 주소가 있는 실제 객체로 대조한다. 광주 29행은 누락된 실제 주소와 별칭 적용 조건을 추가 확인한다.
- 행정명 내부 글자 수를 바꿔도 목록에 등록된 별칭이면 처리되고, 미등록 명칭은 임의 제거하지 않는지 확인한다.
- `종로`, `세종`, `국립중앙`, `서울숲`, `작은숲`, `꿈도서관` 보존을 확인한다.
- 서로 다른 시도의 `중앙`, 서로 다른 시도의 `서구`, 같은 동의 동명 기관, 한정자 때문에 새로 생기는 충돌, 입력 순서 변경·동일 id 중복을 확인한다.
- 분관 고유명과 본관명을 잃지 않는지, 이름만 같은 분관의 괄호 표식을 제거해도 되는지 확인한다.
- 주소 누락·중의적 지역·이름/주소 불일치·알 수 없는 괄호에서 안전하게 원문을 반환하는지 확인한다.
- 웹·Android·iOS 각각에서 7~8자·공백 포함 이름의 줄바꿈과 접근성 원문 유지를 확인한다. 이번 문서 작성으로 플랫폼 검증을 통과 처리하지 않는다.

현재 수행 범위는 입력패킷·관련 로컬 소스의 정적 열람과 독립 제안 작성이다. 운영 DB·정보나루를 새로 조회하지 않았으며 제품 코드·테스트·계약을 수정하지 않았다. 타 모델 교차 검토, HTML 후보 시안, 사용자 채택, 구현·제품 테스트·CI·Git 게시도 수행하지 않았다.

원문에 없는데 제안한 것: `학생` 등 범용어 확장, 마지막 기관 유형 하나만 제거하는 제한, `국립` 보존, 지역 역색인과 모호성 보정, 지역 제거의 최종 결과 검증·되돌리기, 충돌의 전체 재검사. 모두 검토 대상이다.

원문에서 뺀 산출물은 없다. 다만 표기 방식은 제안이며, 현재 객체에 지역 코드가 있다는 가정과 모든 괄호를 원문 유지하는 기존 정책은 각각 실제 입력 제약·알려진 분관 표식 예외로 구체화했다. 이 문서 밖의 기준 문서에는 반영하지 않았다.
