## 1. 판정과 검증 경계

**두 안 모두 50곳을 빠짐없이 다뤘고, 제안 표시는 43곳에서 같고 7곳에서 다르다. 어느 안도 그대로 구현 기준으로 확정하기에는 부족하다.** 기관 유형을 얼마나 남길지는 사용자 선택이다. 접두 오삭제, 지역 해석 실패, 함수 호환성, 충돌 재검사 문제는 그 선택과 별개로 먼저 보완해야 한다.

Gemini안은 기관 유형 보존과 공백 포함 글자 수 계산이 명확하다. 그러나 “소속 구가 맞으면 접두 제거 허용”이라는 조건은 고유명 보호에 충분하지 않고, 문서 본문·의사코드·엣지케이스의 일부 규칙이 서로 다르다.

Claude안은 기관 유형을 제거한 뒤 의미가 약해지면 복원하는 대안을 제시한다. 다만 `regionOf`의 반환형이 현재 코드와 달라지고, 통합명 해석 실패를 전라남도로 확정하는 규칙은 잘못된 지역을 만들 수 있다. 표의 글자 수는 선언한 “공백 제외” 기준에는 맞지만 현재 렌더러와는 다르다.

이번 검증은 **설계 문서의 정적 추적과 표 데이터 계산**이다. 두 모델의 제안 알고리즘 구현체가 제공된 것은 아니므로, 50행을 실제 제안 함수에 실행해 통과한 것으로 기록하지 않는다. 제품 코드·테스트·원 제안서는 수정하지 않았다. 운영 DB·외부 API·웹·Android·iOS·CI는 확인하지 않았다.

## 3. Gemini안 보완 사항

### G-1 / S2 — 소속 지역 일치만으로 고유명 접두를 보호할 수 없음

근거: `안_gemini.md:71`~`:76`, `:242`.

군3의 조건(a)는 소속 시군구가 일치하면 뒤에 공백·설립주체 등이 없어도 삭제를 허용한다. 문서의 “구로구에 있는 남구로…”는 불일치라 방어되지만, 그것이 일반적인 고유명 보호를 증명하지는 않는다.

반례는 검증용 가상 입력이며 실재 시설이라고 주장하지 않는다.

- `name = "남구로어린이도서관"`, 소속 `광주광역시 남구`.
- 접미 제거 후 `남구로어린이` → 소속 일치로 `남구` 삭제 → `로어린이`.
- 잔여는 4자라 최소 길이 가드를 통과하지만 고유명이 훼손된다.

보완안: 소속 일치 외에 설립 표기·공백 경계 등의 문법 조건을 요구한다. `광주남구푸른길…` 대응은 “확인된 상위 지역 직후”라는 별도 경로로 유지한다. “오제거 원천 차단”이라는 단정은 낮춘다.

### G-2 / S2 — 지역 정보 우선순위가 본문과 의사코드에서 반대

근거: `안_gemini.md:96`과 `:139`.

비범용어 지역 모호성 보정에서 본문은 `strippedSido ?? libRegion?.sidoShort`, 의사코드는 `libRegion?.sidoShort ?? strippedSido`를 쓴다. 이름과 메타데이터가 일치하는 50행에서는 드러나지 않지만 불일치 입력에서는 결과가 달라진다.

가상 반례: 이름 `경기도교육청광주도서관`, 코드 또는 주소는 `광주광역시`. 본문의 순서면 `경기광주`, 의사코드의 순서면 `광주`가 될 수 있다. 어느 쪽이 실제 소재지인지 확정할 근거도 없다.

보완안: 코드·주소·이름이 충돌할 때의 정책을 먼저 고정한다. 안전한 기본은 단축 중단·원문 복귀다. 코드가 non-null이어도 오래되거나 틀릴 수 있으므로 `:251`의 “실제 앱에서는 100% 정확”도 성립하지 않는다.

### G-3 / S2 — 동명 군·구의 상위 지역 승격이 정식 절차에 없음

근거: `안_gemini.md:98`~`:103`과 `:246`.

Step 7의 지역 부착은 `sigunguShort`가 다를 때만 수행한다. 그런데 엣지케이스5는 같은 `고성`을 `강원 고성` / `경남 고성`으로 자동 승격한다고 설명한다. 시군구 짧은명이 같고 `area_label`·분관/작은도서관 속성에도 차이가 없으면 정식 절차상 곧바로 원문으로 간다. 설명대로의 승격 단계가 빠졌다.

보완안: “같은 군·구 이름이면 상위 지역을 추가”하는 단계를 정식 절차에 넣거나, 해당 설명을 원문 복귀로 맞춘다. 동명 군·구별 기대값을 명시한다.

### G-4 / S3 — 내부 core와 최종 표시의 의미 통일

근거: `안_gemini.md:42` 부근의 분석 함수 설명과 `:138`~`:146`.

분석 결과 `core`가 지역 보정 전의 순수 핵심인지 지역을 붙인 최종 표시인지 명확히 한다. 후자라면 `cubeNames`가 이미 붙은 지역을 다시 붙이지 않도록 표시 문자열 외에 지역 단계도 보존해야 한다. 실행으로 중복 부착 버그를 확인했다는 뜻이 아니라 구현자에게 필요한 정의 보완이다.

## 4. Claude안 보완 사항

### C-1 / S2 — regionOf 반환형 변경을 기존 API와 분리

근거: `안_claude.md:85`~`:92`, `shortName.ts:30`, 기존 `short-name.test.ts:39`~`:44`.

현재 `string | null`에 비해 제안은 `{ sido, sigungu }`를 반환한다. 기존 호출·테스트를 그대로 둘 수 없다.

보완안: 기존 `regionOf`는 표시 문자열을 유지하고 내부 지역 분석 함수를 분리하거나, 반환형 변경·사용처·계약 영향을 명시한다. 기존 테스트의 기대 타입만 고쳐 끝내지 말고 공개 함수 변경의 이유를 먼저 확정한다.

### C-2 / S2 — 통합 별칭에서 “일치하지 않으면 전라남도”는 오확정

근거: `안_claude.md:90`~`:92`.

통합명 뒤의 시군구가 광주광역시 아래에 있으면 광주, 아니면 전라남도로 본다. 후자에는 모르는 토큰·누락·오타도 포함되어 전라남도로 확인된 경우와 구별되지 않는다.

가상 반례: `address = "전남광주통합특별시 알수없는구 어떤로 1"`. 현재 서술로는 미확인 시군구를 전라남도로 처리할 여지가 있다.

또한 주소 둘째 토큰만 대조하면 `경기도 수원시 영통구 ...`를 시까지만 처리해 구별 이름 제거·충돌 보정에 필요한 정보를 잃는다.

보완안: 광주와 전남 양쪽 목록을 확인하고 유일하게 해석되지 않으면 unknown으로 둔다. 여러 토큰으로 된 행정구역은 가장 긴 계층 일치로 판정한다. Gemini의 시+구 분해안은 참고할 수 있지만 상위 시를 버려 `남구`만 남기지는 않아야 한다.

### C-3 / S3 — 공백 제외 글자 수를 렌더러 기준과 구별

근거: `안_claude.md:4`, §3 전체 표, `:257`, `FacadeHome.tsx:100`~`:106`.

50행은 선언한 공백 제외 기준에 모두 맞는다. 단순 계산 오류로 판정하지 않는다. 다만 현재 구현은 공백도 세므로 다음 표를 함께 제시해야 한다.

| # | 표시 | Claude 기재: 공백 제외 | 현재 렌더러 기준 |
| --- | --- | ---: | ---: |
| 3 | 광주 중앙 | 4 | 5 |
| 13 | 남구 청소년 | 5 | 6 |
| 30 | 서울 어린이 | 5 | 6 |
| 48 | 광주시 중앙 | 5 | 6 |

이번 50행에서는 1줄/2줄 분류가 바뀌지 않지만 공백 제외 6자+공백 1자라면 실제 구현에서는 2줄이다. 또한 “9자 이상이면 글꼴이 크게 줄어든다”는 현재 hero 계산과 다르다. 9~10자는 `per=5`이므로 16px을 유지한다.

## 5. 두 안 공통의 위험과 채택 조건

| ID | 논점·근거 | 판정과 필요한 보완 |
| --- | --- | --- |
| X-1 / S2 | 최종 원문 복귀가 제3의 표시명과 충돌할 가능성. Gemini `:103`, Claude `:104` | 최종 맵 전체를 다시 묶어 확인한다. 최초 충돌 집합만 재검사하면 부족하다. 원문까지 같은 경우는 해결 불가로 명시하며 임의 id·순번을 붙이지 않는다 |
| X-2 / 선택+안전 조건 | Gemini `:54`, Claude `:22`, `:253`은 분관 외 말미 괄호도 넓게 삭제 | `(분관)` 생략과 `(어린이자료실)` 등 고유 정보 삭제를 분리한다. 닫힌 태그 집합 외에는 원문 보존을 추천한다. 넓게 삭제한다면 단독 표시에서의 식별 정보 손실을 명시한다 |
| X-3 / S2 | 원문 fallback의 정의 | Gemini는 `original` 생성 때 연속 공백을 줄인다. Claude는 분석에 전각→반각·공백 삭제를 쓴다. 보존용 원문과 분석 문자열을 분리하고 복귀 시 어느 것을 반환할지 고정한다 |
| X-4 / 증거 부족 | 두 안의 50행은 정적 기대표 | 광주29행에는 개별 주소가 없다. 코드 활용도 포함해 실제 객체와 미대조다. “29/29 정상”, “100% 정확”은 제안표 자기 판정으로 한정하고 실행 검증·전국 보장과 구별한다 |
| X-5 / 선택+미검증 | 7~10자를 허용하는 Gemini, 더 짧게 만드는 Claude | 패킷의 최대7~8자 “내외”는 목표이지 절대 상한으로 명시되지 않았다. 10자 유지안을 즉시 계약 위반으로 보지 않는다. 다만 글꼴 크기만으로 가독성이 증명되지는 않으므로 실제 화면에서 비교한다 |

X-1 반례는 외부 데이터 오염을 가정한 합성 입력이다. 같은 구의 서로 다른 id 두 건이 원명 `중앙도서관`, 제3건이 `중앙도서관도서관`이라고 하자. 앞 두 건의 기본명은 지역이 붙은 `중앙`, 제3건은 끝말 하나만 뗀 `중앙도서관`이다. 앞 두 건이 충돌해 원명으로 돌아가면 처음에는 충돌하지 않던 제3건과 표시가 같아진다. 실재 시설 사례가 아니라 최종 재검사 필요성을 보여 주는 반증 입력이다.

표시 계산의 정적 확인: hero에서 6자는 1줄·약14.33px, 7~10자는 2줄·16px, 11~12자는 2줄·약14.33px이다. 이는 `TOP_LINE=92`, `TOP_LS=1`, `want=16`의 산술 결과이며 실제 글자 폭·가독성 측정이 아니다. 또한 `FacadeHome.tsx:182` 부근은 `<Text numberOfLines={fs.lines}>`에 문자열을 전달한다. `per`는 폭 계산용 추정치이고 소스에 문자열을 절반으로 자르는 처리는 없다. Gemini `:250`의 “단순 글자 수 반분 줄바꿈”은 이 차이를 구별해 설명해야 한다.

## 7. 다음 단계에 전달할 제안

공통 채택 후보는 확인된 지역·설립주체 제거, `국립` 보존, 분관의 독립 고유명 우선, `어린이`·`영어` 등의 복합 고유명 보존, 빈/너무 짧은 결과의 원문 복귀, 접근성 등 원명 유지다. 모두 사용자 채택 전 제안이다.

구현 전 G-1~G-3, C-1~C-2, X-1·X-3의 결정 절차를 하나로 고정한다. S3의 글자 수·글꼴 설명도 보완하고 실행·미실행을 구별한다. 이후 위7행과 괄호 처리의 후보 시안을 비교한다. 현재 요청은 교차 검증 문서까지이므로 시안·코드·계약 변경으로 진행하지 않는다.

### 수행한 검증과 미실행

- 수행: 위 작업 위치에서 `git branch --show-current`, `git rev-parse HEAD`, `git status --short`, `git diff --stat`으로 시작 상태 확인.
- 수행: `Get-Content -Encoding UTF8`, `rg -n`으로 입력·두 안·실제 소스·기존 테스트의 정의와 호출 정적 대조.
- 수행: `$OutputEncoding = [System.Text.UTF8Encoding]::new($false)` 설정 후 `python -X utf8 -` 임시 스크립트로 표50행, 원명 순서, 표시 차이7행, 글자 수, 분포, SHA-256, 글꼴 산술 계산. 종료 코드0.
- 미실행: 제안 파서 구현·실행, 제품 단위/회귀 테스트, 변이 검사, DB/API 재조회, 화면·플랫폼 검증, CI, Git 게시, 외부 알림.

원문에 없는데 추가한 것은 이 문서의 반증 입력·보완 제안·Codex 자안 정정이다. 입력패킷·3사 안·요구사항·계획·계약 원문은 변경하지 않았다.
