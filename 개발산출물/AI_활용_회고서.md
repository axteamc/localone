# SDD·AI 활용 회고서

> 상태: **골격 — 미작성**. 담당: D + 전원(팀원별 한 절). 선행: 구현 진행 후(최소 M1 완료). 갱신·작성 시점: 마일스톤 종료 때, 최종 보고 전.
> 입력: [스펙 변경 이력](스펙_변경_이력.md), [모호점 해소 기록](모호점_해소_기록.md), 기능별 명세서의 충돌 확인 기록, PR 리뷰·`to:` 이슈 기록, [규칙 점검 결과](결과/SET-1b_규칙전환.md)

## 작성할 내용

1. 스펙 주도 개발(기획 → 명세서 → 계약서 → 구현) 흐름이 실제로 어땠는지: 병목, 되돌아간 단계(1b), 구현 중 명세 변경 횟수
2. AI(Claude) 활용 방식: 의도된 무지·낚시 질문이 팀원의 결정에 미친 영향(간파 vs 걸림 횟수), 쉬운 말 규칙의 체감
3. AI가 만든 코드의 설명 책임(이해 확인 질문) 결과: 이해 미확인 건수와 후속
4. AI의 실수 사례와 가드레일의 효과(담당 밖 수정·테스트 왜곡·거짓 완료 시도 등 실제 사례)
5. 플랫폼 공통 코드 방식에서 iOS 확인 단계가 잡은 문제
6. 규칙 개선 제안(team 레포 반영 항목)
