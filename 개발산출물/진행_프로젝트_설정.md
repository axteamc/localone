# 진행: libmarks 프로젝트 설정 및 초기화

새 세션은 **이 파일 하나 + 3절 표의 입력 파일**만 읽고 이어 갑니다. 대화 기록이 없어도 되게 씁니다.

## 1. 목표와 근거

- **목표:** libmarks 프로젝트 초기 환경 구축, 기술 스택 확정, 기본 빌드 및 실행 파이프라인 수립
- **근거 문서:**

  - `docs/문서_운영.md`: 문서 역할, 골디락스 Step 분할, 완료 판정
- **작업 규칙:** 저장소 루트 `GEMINI.md` / `CLAUDE.md` / `AGENTS.md` 및 `개발산출물/협업_시니어주니어.md` 준수

각 단계는 한 세션(약 1시간 이내, 명령 몇 개 + 확인 하나)에 끝낼 크기로 나눈다.

## 3.1 묶음과 관문 (골디락스 3~4 Step 원칙)

역할·명세 작성 규칙·리뷰 루프는 [협업_시니어주니어.md](협업_시니어주니어.md)를 따른다. 구현 step은 [주니어_체크리스트.md](주니어_체크리스트.md)도 읽는다.
작업은 대기능 단위(3개 이하 권장, 최대 4개 Step)로 진행하며, 각 대기능은 **시니어 명세(4단계 중 1단계)**로 시작하고, 세부 명세가 있어야만 구현을 시작한다.

- **명세 파일:** `개발산출물/명세/<step ID>_구현명세.md`
- **관문 규칙:**
  1. 구현 step을 시작할 때 `개발산출물/명세/<step ID>_구현명세.md`가 없으면 **코드를 쓰지 않고 멈춘다.**
     답변: `<step ID> 구현 명세가 없습니다. 다음 진행은 문서 보강 및 검토 후 진행이 필요합니다.`
  2. 명세 체크리스트를 모두 `[x]`로 채우지 못하면 완료 처리하지 않는다.
  3. 완료 시 `docs/문서_운영.md` §6의 규격에 맞춰 종료 보고 및 다음 세션 시작 멘트를 제공한다.

## 4. 세션 진행 방법 (공통)

1. `git checkout main && git pull`로 이전 PR 머지 확인.
2. 진행 파일과 해당 step 입력 파일(명세서 포함) 읽기.
3. 브랜치 `step/<step ID>` 생성 후 작업.
4. 테스트/검증 실제 실행 후 출력 결과 파일(`개발산출물/결과/<step ID>_<이름>.md`)에 첨부.
5. `진행_<작업>.md` 상태 갱신.
6. 커밋 → push → PR 생성 → `gh pr checks --watch`로 CI 대기.
7. 최신 리뷰 코멘트 대조 및 처리 근거 기록 후 종료 보고.
