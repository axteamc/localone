# 02. 요구사항 정의서 — 동네한권 (localone)

> 상태: **초안 — 사용자 검토 전**(2026-11-10 작성, 2026-11-11 요구사항 ID 부여, 2026-11-11 개정: 도서관 방문·커뮤니티 중심으로 재배치, 반납 비서 단순화 — [C-10·C-11](스펙_변경_이력.md), 같은 날 방문 페이지·피드·책장·디자인 방향 개정 — [C-13](스펙_변경_이력.md), 세부 결정 — [C-14](스펙_변경_이력.md)). 제품 동작·권한·데이터 경계·수용 기준(AC)의 기준 문서다. 현재 구현·API·DB 계약은 없으며 물리 스키마·경로·HTTP 상태·함수 시그니처를 확정하는 구현 명세가 아니다.

## 1. 핵심 경험과 범위

**동네한권은 지역 도서관을 앱에서 "방문"하는 느낌으로 쓰는 서비스다.** 도서관 단위로 작은 독서 커뮤니티가 모이고, 책을 빌리는 일은 그 곁에서 편리하게 돕는 기능이다. 대출·반납 관리는 보조이고, 중심 가치는 도서관을 고르고 → 그곳의 이웃 독서 기록·게시물을 만나고 → 다음 책을 찾는 순환이다.

| 구분 | 제품 동작 제안 |
| --- | --- |
| 홈 | 상단은 데포르메된 미니멀 지도. 집 또는 현재 위치 중심, 큰 랜드마크·도로 위주, 도서관 핀과 거리 표기. 지도는 길 안내 같은 동적 도구가 아니라 거리를 알려 주는 정적 안내다. 하단은 지역 인기글·내 최근 독서 기록·추천 서적 섹션 |
| 도서관 방문 | 핀을 누르면 그 도서관의 방문 페이지로 바뀐다(2026-11-11 사용자 결정 C-13: 시트가 아닌 페이지 전환, 장황한 연출 없이 바뀐 것을 알아볼 수 있게). 위쪽 광장 피드(게시물·방명록·모임·방문 기록 카드가 같은 모양으로 섞임) + 아래쪽 책장(오늘의 서가: 요즘 사람들이 읽은 책 / 인기 도서 / 운영자 테마 추천, 책장을 넘겨 봄). 그 도서관에 들어갔을 때 가장 큰 화면에서 모든 기능이 보이게 하며 특정 기능만 쓰는 사람이 없게 한다. 피드와 책장 사이는 얇은 블러 띠 + 그라데이션으로 나누고(사용자 확정, 피드가 책장 쪽으로 지나갈수록 블러가 점점 강해져 글자는 읽히지 않아도 형태·색은 알아볼 정도. 시안 기준 최대 약 6~7px 상당), 블러가 불가능하면 그라데이션 페이드만 쓴다. 기기별 블러 성능 확인은 향후 예정이다(Q-46). 전체 동네로 돌아갈 수 있음. 개인 데이터는 로그인 필요 |
| 광장 | 핀터레스트형 2열 메이슨리. 카드 종류는 게시물·방명록 글·모임·방문 기록이며 모양은 같다. 게시물은 이미지(사진·책 표지·단색, 글자 얹기) + 본문(감상·좋았던 문장, 선택 — 이미지만으로도 올릴 수 있음). 상세에서 대여(우선)·구매 연결, 같은 책의 다른 게시물로 이어 읽기, 공감 |
| 독서 기록 | 하단 바의 독서 기록 탭은 전체 기록·도서관 필터·기초 통계(원장 같은 구성). 내 발자취는 방문한 도서관별 기록을 보여 주는 별도 최상위 이동처(하단 탭 또는 사이드바)이다(두 화면은 느낌이 달라야 하며 구성은 시안에서 확정. 둘의 관계는 Q-44). 기록을 템플릿으로 꾸며 광장에 올릴 수 있음 |
| 책 확인 | 도서 검색, 도서관 위치·거리, 선택한 ISBN의 소장·대출 가능 조회, 빌릴 예정 저장. 지도 전체의 무조건적인 '대출 가능' 배지 금지 |
| 반납 비서(보조) | "빌릴 예정" → 실제로 빌린 뒤 "빌렸어요" → 그 시점부터 D-day 타이머와 D-3·D-1·당일 알림 → "반납했어요". 외부 조회 없이 날짜 계산만으로 동작 |
| 작은 모임 | 도서관 기반 독서 모임. 이번 달 책·모임 게시물 |
| 모바일 보조 | ISBN 스캔은 책 고르기 보조 |

디자인 방향(2026-11-11 사용자 결정, C-13): 전체는 모던하게 하고, 배경과 분위기는 콘크리트·회반죽 벽과 아치, 따뜻한 간접조명이 있는 공간 사진(사용자 레퍼런스 3·4번째)을 연상시키게 한다. Arne Vodder 가구(사이드보드)는 **곡률·배색·형태만** 앱의 틀에 참조하고 **나무색은 쓰지 않는다**. 이전에 적었던 미색·먹색·세이지 후보와 종이 질감·서가 그래픽·줌인 연출 후보는 이 방향으로 대체한다. 색감 있는 톤(복숭아·세이지 등)은 유지하고, 노랑은 겨자색보다 밝은 버터 톤으로, 흰 배경은 아주 조금 더 밝게 쓴다(2026-11-11 사용자 결정). 구체 색 값·서체·홈 비율·좁은 폭의 카드 열 수·토큰은 시안에서 확정한다(Q-29). 색상 대비·키보드 접근·시트 포커스·텍스트 확대를 함께 검수한다.

**데포르메 지도 구현 방식은 미정이다(Q-12·Q-30).** 후보: (가) 지도 제공자의 스타일 설정으로 단순화, (나) 동네별로 직접 그린 도식 지도, (다) 도서관 좌표와 중심 기준의 도식(실제 도로 없이 거리 고리 + 랜드마크). 어느 쪽이든 길 안내는 하지 않고, 지도가 안 뜰 때는 도서관 목록으로 같은 방문 여정을 제공한다.

- 사용자 ID는 요청 본문을 신뢰하지 않고 인증 주체에서 얻는다. 조회·수정·삭제·다운로드 모두 소유자를 확인한다. A의 식별자로 B의 데이터를 찾는 fallback을 금지한다.
- FastAPI 경유 접근을 추천한다. SQLAlchemy의 소유자 조건과 DB 권한을 별도로 설계한다. Supabase 사용만으로 RLS가 적용된다고 가정하지 않는다. 브라우저에 DB 관리자/서비스 비밀키를 전달하지 않는다.
- 기기에 예약된 알림은 서버에 저장하지 않는다. 대출 데이터가 원본이며, 앱이 열릴 때 대출 목록과 예약을 맞춘다.
- 탈퇴 시 개인 대출·예정·기록·스탬프 삭제, 공개 게시물·방명록 글 철회, 기기 예약 알림 해제를 제안한다. 백업 잔존 기간·신고 증거 보관 기간·삭제 완료 기한은 운영 정책 승인 전 미확정이며 출시 관문이다.
- 정확한 위치·집 주소는 기본 영구 저장하지 않는다. 위치는 사용자 동의 후 거리 계산에만 사용하고 EXIF 위치는 공개 이미지에서 제거한다. 거부 시 지역 선택으로 탐색한다. "집" 기준 지도는 사용자가 직접 고른 동네 단위로 하고 상세 주소를 저장하지 않는 안을 기본으로 한다(후속 명세에서 확정).

## 4. 데이터 흐름과 경계

1. 앱 → FastAPI → 도서관/서지/지도 제공자. 공공 정보는 출처·관측 시각과 캐시 상태를 함께 표시한다. 제공자 비밀키는 서버 설정에 둔다. 지도 클라이언트용 키는 허용 도메인·앱 제한을 적용한다.
2. 인증 사용자 → 빌릴 예정 → "빌렸어요"(서버가 서울 날짜로 대출 기록) → 앱이 D-3·D-1·당일 알림을 기기에 예약 → 사용자의 "반납했어요"로 예약 해제. **공공 API는 이 흐름에 관여하지 않으며 개인 대출 원장도 아니다.** 상태 변화 관측으로 대출·반납을 추정하는 기능은 만들지 않는다(C-11).
3. 사용자 → 게시물 작성(이미지·본문·도서관·도서 선택) → 명시적 올리기 → 광장 노출 → 상세에서 도서 소장 조회(대여 우선)·외부 구매 링크·같은 책 이어 읽기. 철회·운영 숨김 직후 피드·상세 접근을 막고 공개 캐시를 무효화한다.
4. 독서 기록 → 템플릿 선택 → 게시물 작성 화면으로 공개용 내용만 옮김 → 올리기(기록 원본은 비공개로 남음).
5. 책 표지: 네이버 책 검색 API(사용자 지정, Q-39)로 ISBN을 조회해 가져오고, 없으면 제목·저자 표지를 만들거나 사진·단색으로 대신한다. 표지 이미지의 복사 저장 여부와 이용 조건은 확인 전 미정이다(Q-41).
6. 외부 이미지 업로드는 DB 트랜잭션 밖에서 처리한다. DB 확정 실패 시 정리, 커밋 이후 취소 시 참조 파일 보존을 구별한다. 공공 API 대기는 DB 트랜잭션 밖에서 수행한다.
7. 도서관/사용자 전환 시 이전 요청 취소와 응답 세대 검사를 적용한다. 사용자 A 로그아웃 후 B 로그인에서 A의 캐시·진행 요청·**기기 예약 알림**이 남지 않아야 한다.
8. 홈의 인기글·추천 서적은 공개 게시물(공감·언급 수)에서 계산한다. 외부 AI·LLM 추천은 쓰지 않는다. 집계 기준은 후속 명세에서 확정한다(Q-31).
9. 책장(오늘의 서가)은 두 데이터를 모두 쓴다(2026-11-11 사용자 확정). (가) "요즘 사람들이 읽은 책": 동의한 이용자가 "반납했어요"를 누르면 그 책을 **도서관-책 단위로만** 쌓는다(user id·개인 대출 원장과 연결해 저장하지 않음. 도서관 정보가 없는 대출은 집계하지 않음. 동의 문구·철회·이용자가 적을 때 재식별을 막는 최소 건수 규칙은 Q-49). (나) "인기 도서": 공공 데이터(정보나루)의 도서관별 인기대출도서 조회(API 존재 확인, 기간·갱신 주기·쿼터는 Q-42). 정해졌다가 폐기한 안: "최근 빌려 간 책"(빌릴 수 없는 책이 메인에 뜸), 공공 데이터 상태 변화로 반납 추정(00 §2 "안 함" 계열). 광장 피드를 대출 이력에 묶지 않는 규칙(R11)과 별개이다. 테마 추천 도서는 운영자가 구성한다(Q-43 해소, 범위·입력 방식은 Q-47).

| AC-UNKNOWN | 제공자 시간 초과/오류/미지원 도서관 | 불가/미소장으로 단정하지 않고 알 수 없음·재시도 제공. 오래된 캐시는 시각과 함께 구별 |

| AC-LOAN | "빌렸어요"를 연타하거나 반납 예정일 수정 | 본인 대출 한 건만 저장. 예정일은 대출일 이전 불가, 수정 가능한 오류 안내 |

| AC-COVER | 표지가 있는 책 / 없는 책 / 제공자 오류 | 있으면 표지 사용, 없으면 제목·저자 표지 또는 사진·단색 선택. 오류를 빈 성공으로 삼키지 않고 대체 경로 제시 |
| AC-FEED | 광장 피드 열기, 정렬 전환, 상세에서 대여·구매·이어 읽기·공감 | 철회·숨김 게시물 미노출. 대여 경로가 구매보다 먼저. 구매는 외부 이동임을 표시. 공감은 사용자당 한 번, 취소 가능. 빈 광장은 안내만(가짜 게시물 없음) |
| AC-VISIT | 지도에서 도서관 핀 선택 → 방문 페이지 → 전체 동네 복귀, 위치 거부·지도 실패 | 페이지가 바뀐 것을 알아볼 수 있고 피드(게시물·방명록·모임·방문 기록 카드)와 책장이 한 화면에 보임. 거부·실패 시 집(동네) 기준·목록으로 같은 여정. 홈 하단·서가·방명록은 공개 데이터만 사용하고 개인 데이터는 로그인 시에만 |

| AC-UI | 로딩/빈/성공/실패/비로그인, iOS·Android 앱과 웹(좁은 창·넓은 창) | 시트·탭·카드 조작과 포커스 복귀 가능, 넘침·가림 없음(상태줄·홈 막대·키보드 포함). 앱이 기준이고 웹은 같은 코드의 부연 출력. 열 수/정렬 약속과 플랫폼 분기는 화면 명세·계약서 §3.3에서 고정 |

알림 시각(예: 오전 몇 시)·사용자 시간대 변경 규칙·텍스트 길이·페이지 크기·미디어 용량·스탬프 하루 기준·방명록 글자 수·모임 정원은 해당 구현 직전 명세에서 수치로 고정해야 하며 임의 구현할 수 없다.

## 6. 예외 및 오류 계약 준비

아래는 제품 오류 분류다. 공개 API 경로·요청/응답 전 필드·HTTP 상태 코드·오류 코드 문자열은 해당 Step 명세에서 조건별로 하나씩 확정한다. 현재 `/api/v1` 또는 레거시 계약이 존재한다고 가정하지 않는다.

| 조건 | 사용자에게 보일 결과/서버 방어 |
| --- | --- |
| 미인증·세션 만료 | 로그인 필요, 입력 보존 범위를 정하고 저장 성공으로 표시하지 않음 |
| 타인 소유/존재하지 않는 개인 리소스 | 존재 여부 누설 없이 동일한 거부 정책. 데이터 변경 없음 |
| 날짜 역전·필수값 누락·잘못된 ISBN | 해당 필드 오류, 저장 없음 |
| 중복 클릭·네트워크 재시도·동시 수정 | 중복 생성 방지, 충돌 안내 후 최신 상태 재조회 |
| 제공자 제한·시간 초과·포맷 변경 | 알 수 없음/지연 안내, 호출 상한·백오프 적용. 예외를 빈 성공 응답으로 삼키지 않음 |
| 지도 실패·위치 거부 | 집(동네) 기준 또는 도서관 목록으로 같은 방문 여정, 타인 위치로 fallback 금지 |
| 알림 권한 거부·기기 변경 | 앱 안의 D-day로 확인, 앱을 열 때 예약 재동기화. 알림 도착 약속 없음 |
| 공개 철회·운영 숨김·삭제 게시물 링크 | 더 이상 공개되지 않음 안내, 비공개 원문 반환 금지 |
| 이미지 업로드·표지 가져오기 실패 | 업로드 취소·재시도, 사진·단색·제목 표지로 대체, 미완료 파일 정리 |
| 외부 구매 링크 실패·미지원 | 링크가 열리지 않아도 대여 경로는 그대로. 구매 가능 여부를 단정하지 않음 |
| 방명록·게시물 도배·부적절 글 | 신고·숨김 경로. 자동 삭제 규칙은 상세 명세 전 약속하지 않음 |
| 취소·앱 종료 | 취소 전파·트랜잭션 롤백, 대출 데이터가 원본이므로 앱 재실행 때 예약 복구 |

## 7. 초안에서 수정한 가정과 외부 근거

공식 문서 확인일: 2026-11-10(예스24 개발자센터는 2026-11-11). 제공자의 현재 운영 조건은 키 발급/실측 전 미검증이다.

- **실시간성:** [정보나루 공지](https://data4library.kr/noticeV?cn=129)는 `loanAvailable`을 조회 전날 상태로 설명한다. [현행 활용 안내](https://data4library.kr/apiUtilization)를 함께 확인했지만 실제 갱신 SLA·쿼터는 미확정이다. '실시간', '방금 반납'을 제품 보장으로 쓰지 않는다.
- **인기대출도서:** [정보나루 활용 안내](https://data4library.kr/apiUtilization)에서 도서관별 인기대출도서 조회(`loanItemSrchByLib`, 도서관 코드 또는 지역 코드로 순위·도서명·ISBN·대출횟수 제공)와 통합 조회가 있음을 확인했다(2026-11-11). 기간 지정 파라미터·갱신 주기·쿼터는 이번에 읽은 페이지에서 확인하지 못했다 → Q-42, Q-18. 같은 페이지의 소장여부 조회(`bookExist`)는 설명에 대출가능 값이 없어, 대출 가능 필드는 키 발급 후 실측으로 확인한다.
- **알림(기기 예약 알림):** 서버 푸시 대신 앱이 기기에 직접 알림을 예약한다. 서버 푸시 인증서(APNs 등)가 필요 없다는 판단은 **이번 세션에서 Expo 공식 문서로 확인하지 않았다.** LOAN-3 명세 전에 Expo 알림 문서와 실기기(iOS·Android 13 이상 권한, 절전 모드 지연)로 확인한다. 기기를 바꾸거나 앱을 지우면 예약이 사라지는 한계가 있고(AC-NOTIFY가 복구 방식을 정함), 웹에서는 지원되지 않을 수 있다.
- **표지·서지:** 사용자가 지정한 [네이버 책 검색 API](https://developers.naver.com/docs/serviceapi/search/book/book.md)를 쓴다. 이번 세션에서는 이 문서에 접속하지 못해(도구 제한) **응답 필드·일일 호출 한도·표지 이미지 이용 조건을 직접 확인하지 못했다.** 검색 결과로는 ISBN·이미지 필드가 있다는 간접 근거만 있고 한도(일 25,000회라는 외부 자료)는 공식 확인 전이다. 키 발급 후 확인한다(Q-41). 카카오·알라딘은 대체 후보이다. 지도·폰트·인용문 사용 권한과 비용도 미확인이다.
- **예스24:** [예스24 개발자센터](https://developers.yes24.com/docs)에서 **Open API(REST·JSON)가 제공됨을 확인했다**(2026-11-11). Goods API(`/v1/goods`)로 상품 검색·상세·목차를 제공하고, Category API로 베스트셀러·신상품을 제공하며, API Key를 요청 헤더에 넣는 방식이다. 키 등급별 한도는 기본키 일 20,000회·초당 10회, 제휴키 일 100,000회·초당 20회이고 초과하면 429이다. **문서 본문에서 확인하지 못한 것:** 구매 링크 생성 방법, 제휴키 요건, 이용 약관(링크 표시·수수료), 키 발급 절차의 세부. → Q-41. (같은 날 앞서 한 일반 검색에서는 공식 API를 찾지 못해 "미확인"이라고 적었으나, 사용자가 준 주소로 바로잡았다.)
- **데포르메 지도:** 지도 제공자가 상세 단순화·랜드마크 강조를 얼마나 허용하는지 미확인이다. 불가하면 직접 그린 도식 지도로 대체한다(Q-30).

## 8. 상세 명세 진입 조건과 근거

- D2 및 제품 초안 검토 후 기능별로 명세서(담당 주니어, `specs/<기능>/명세서.md`) → 계약서(D, `../team/contracts/<기능>.md`) 순으로 상세화한다. 계약서에는 요청/응답 전 필드·타입·필수성·오류/HTTP 상태, 소유권·삭제·동시성·취소·외부 I/O·검증 단언을 전수 기재한다.
- 중요한 실패별로 프로덕션 가드와 테스트 단언을 연결한다. 특히 A↔B 격리(예약 알림 포함), 늦은 응답 폐기, 반납 후 예약 해제, 철회 후 공개 차단, 중복 등록을 검증 대상으로 고정한다. 이번 세션에서는 실행하지 않았다.
- 실제 저장소는 문서만 존재한다(`README.md:1`, `개발산출물/결과/SET-0_규칙초기화.md:8`). 기존 Kotlin 구현·CSS 토큰·검사기가 있다고 가정하지 않는다.
- 문서 근거: `../team/docs/문서_운영.md` §2(완료 판정), `../team/templates/계약.md`(필드·에러 전수, 테스트 표), `../team/prompts/3_구현.md`(화면 5대 점검·테스트 무결성). 기능별 화면 동작·예외 문구는 담당 주니어의 `specs/<기능>/명세서.md`에서 정한다.
