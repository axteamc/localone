# 도서관 "실시간 확인" 검색 딥링크 진행 (O-30·Q-48)

상태: **폐기(2026-11-20 D 결정).** 검색 딥링크는 불가능해 "실시간 확인"은 기존처럼 `homepage`로 연결한다. 아래 "D 눈 확인 결과" 참고. [큐브 이름 규칙 v2](완료/진행_큐브이름규칙.md) 다음에 한다. 이유: 편의성 작업(지금도 도서관 홈페이지로는 간다). 3사 LLM 상호 검증은 **쓰지 않는다**(기술 확인이라 크롤링·실측으로 확정).

## 입력

- D 요청(2026-11-19): 딥링크를 누르면 해당 도서관 메인 페이지로만 간다. "해당 책 이름으로 검색창에 검색한 화면"까지 가게 개선하고, DB에 저장된 도서관별 주소를 자동으로 훑어 검색 기능을 확인하는 크롤링과 "검색어를 주소에 덧붙이는" 방식이 가능한지 검토.
- 원문 근거: [00 O-30](00_기획_원본.md) "실시간 확인" 버튼 — 해당 도서관 자체 홈페이지에서 해당 책 검색 결과로 이동(딥링크). 채택·확정, **링크 확보 방법·검증은 Q-48**.
- DB: [05 §3.1](05_ERD_및_DB설계서.md) `libraries.isbn_search_url_template` — NULL 허용, "없으면 `homepage`로", `미확인(임시)` Q-48. 서버는 이 칸을 건드리지 않는다(`provider_engine.py` `_store_libraries`). 현재 운영 DB 29곳 모두 비어 있다.

## 사전 조사 결과 (2026-11-19, 광주 29곳)

도서관 홈페이지는 **8개 시스템**으로 묶인다(도서관 수보다 시스템 수가 훨씬 적다).

| 시스템 | 해당 | 검색 주소(검색어 `{q}`) | 실측 |
| :--- | :--- | :--- | :--- |
| 동구 | 2곳(계림꿈나무·책정원) | `https://lib.donggu.kr/BookSearch?query={q}` | 검색어가 결과 화면에 나옴(8회) |
| 북구 | 6곳 | `https://lib.bukgu.gwangju.kr/main/bookSearch.do?PID=0301&searchText={q}` | 검색어가 화면에 나옴 |
| 교육청 | 6곳 | `https://lib.jge.go.kr/<관>/site/search/bookSearch.do?manage_code=MD&search_txt={q}`(관: `jungang`·`gecs`·`student`·`geumho`·`seokbong`·`songjung`) | 검색어가 화면에 나옴 |
| 시립(전남광주통합특별시립) | 3곳 | 메인이 JS 인트로 | **미확인**(브라우저로 열어야 함) |
| 서구 | 4곳 | 메인이 JS | 미확인 |
| 남구 | 5곳 | 메인이 JS | 미확인 |
| 광산구 | 6곳 | 메인이 JS | 미확인 |

- **저장된 홈페이지 주소가 이미 깨진 곳이 있다.** 교육청 6곳의 `homepage`는 `lib.gen.go.kr`인데 지금은 `lib.jge.go.kr`로 이전돼 이전 주소는 404다(리다이렉트 뒤). 딥링크 이전에 홈페이지부터 바로잡아야 한다.
- "검색어가 화면에 나온다"는 **결과 화면이라는 보장이 아니다**(검색창에 되돌려 써 준 것일 수 있다). 시스템마다 한 번은 눈으로 확인한다.
- 한계: 사이트 개편 시 규칙이 깨진다 → **실패하면 `homepage`로 되돌아가는 안전장치**와 주기 재확인이 필요하다.

## K1·K2 실측 결과 (2026-11-20 mac)

- **광주 지역 코드는 `24`**(`29`는 세종). 정보나루 `libSrch region=24`로 29곳 확보. 시스템 수는 동구 2·북구 **5**(6 아님)·교육청 6·시립 3·서구 4·남구 4·광산구 5 = 29.
- **K1 홈페이지:** 교육청 6곳 `lib.gen.go.kr/<관>`은 5곳 404·1곳(`songjung`) 302 → 전부 `https://lib.jge.go.kr/<관>`으로 바로잡아야 한다. 시립 3곳 `https://gjlib.jeonnam-gwangju.go.kr`는 루트가 "전남도서관/광주도서관 고르기" 인트로(`lib.jeonnam-gwangju.go.kr`)로 가서 **`https://gjlib.jeonnam-gwangju.go.kr/main`**이 맞다. 나머지는 http→https 리다이렉트뿐.
- **robots.txt (이번 작업의 결정적 발견):** 북구·시립·남구는 `User-agent: *`에 `/main/bookSearch*`를 막았고, 교육청(`lib.jge.go.kr`)은 네이버·다음·빙 외에 `Disallow: /`, 서구는 `/search/`·`/findeepSearch*`를 막았다. 동구·광산구는 웹방화벽이 robots.txt 요청까지 차단한다. → **검색 결과 화면을 자동으로 열어 보는 검증·Playwright로 검색 폼을 제출하는 탐지는 하지 않는다.** 허용된 메인 페이지 HTML만 시립·남구·서구에서 1회씩 읽었다. (2026-11-19 사전 조사에서 동구·북구·교육청 검색 주소를 몇 번 열어 본 것은 이 확인 이전이었고, 이번엔 반복하지 않았다.)
- **시립 검색 폼:** 메인 `#mainSearchForm`이 `POST /main/bookSearch/keyword`(입력칸 `searchText`)라서 GET 딥링크가 되는지는 사람이 눌러 봐야 안다. 남구·서구 메인은 JS 이동 껍데기, 광산구는 방화벽이라 탐지 못 함.
- **자리표시자 불일치:** 서버 `live_check_link`(`provider_engine.py`)와 계약 `core.md`는 `{isbn13}`(ISBN 치환)인데 이 문서·D 요청은 책 이름 `{q}`다. 사람이 눈으로 확인할 때 제목·ISBN 둘 다 눌러 보고, 되는 쪽(또는 시스템별로 다른 쪽)을 K4에서 정한다. 제목을 쓰려면 서버가 `title`을 넘겨야 한다(K5).
- 확인표: [결과/검색딥링크_확인표.html](결과/검색딥링크_확인표.html) — 기준 책 「채식주의자」「소년이 온다」, 시스템당 링크.

## D 눈 확인 결과 (2026-11-20, 확인표로)

- 남구 `https://lib.namgu.gwangju.kr/main/bookSearch`·광산구 `https://lib.gwangsan.go.kr/main/bookSearch`: 검색해도 주소가 안 바뀜(POST) → 주소로 못 만든다. 서구: 주소가 `library/index.9is` 하나뿐. 북구도 검색창 주소 `bookSearch.do?PID=0301`까지만(검색어가 주소에 안 실림). **ISBN 검색이 되는 곳 없음.**
- 결론: 29곳 중 URL로 책 검색 화면에 보낼 수 있는 시스템이 없음(검증 가능했던 것 포함) → **O-30 딥링크 폐기, 홈페이지 연결 유지.** 05 §3.1·Q-48 확정(칸은 NULL 유지), 00 O-30 추적표 한 줄 반영. K4·K5·K6 하지 않음.
- **남은 별도 일(작게):** 저장된 `homepage` 바로잡기 — 교육청 6곳 `lib.gen.go.kr/<관>`(404) → `lib.jge.go.kr/<관>`, 시립 3곳 → `https://gjlib.jeonnam-gwangju.go.kr/main`. 다음 `sync-libraries`가 정보나루 값으로 덮어쓰므로 서버 쪽 보정 표가 필요 → D가 원하면 별도 작은 작업.

## 방식 (폐기 — 참고용)

1. **수집:** 정보나루 `libSrch`로 받은 `homepage`를 호스트 기준으로 묶는다(리다이렉트 따라가 최종 주소 기록).
2. **탐지(자동):** HTML에서 `<form action>`·검색 입력칸 이름(`query`·`searchText`·`search_txt` 등)을 찾는다. JS로 그리는 사이트는 Playwright(헤드리스 브라우저)로 연다. 후보 주소 템플릿 `...?<입력칸>={q}`를 만든다.
3. **검증(자동 + 눈):** 기준 책 두 권(예: 제목이 흔한 책·드문 책)으로 템플릿을 열어 응답 200, 결과 화면에 제목이 나오는지 본다. 시스템마다 스크린샷 한 장을 눈으로 확인(D 또는 Claude)한다.
4. **저장:** 도서관별 `isbn_search_url_template`에 `{q}` 자리표시자를 넣어 저장한다. 앱은 `{q}`에 책 제목을 `encodeURIComponent`해서 열고, 칸이 비면 `homepage`로 간다(현재 동작 유지).
5. **관리:** 시스템별 규칙 표(JSON 또는 마이그레이션 시드)를 레포에 두고, 재확인 스크립트(주 1회 수동 실행)가 깨진 규칙을 알려 준다. 전국으로 넓혀도 확인 대상은 시스템 수다.

- 계약: Q-48(대상 도서관·주소 규칙)을 `확정`으로 바꾸는 **계약 갱신**이 필요하다(05 §3.1 해당 칸, `../team/contracts/` 해당 기능). 도서관 규칙은 D가 요구한 변경이라 계약 수정은 확인 없이 하고 보고에 한 줄(D 메모리 `contract-edit-free-for-d-requests`).
- 이 앱은 출시하지 않고 교육 기관 제출용이다. 외부 도서관 사이트에 요청을 보내는 크롤링은 **도서관 수만큼 적게**(시스템당 몇 번) 하고 `robots.txt`를 확인하며 호출 사이에 지연을 둔다.
