## 입력 (D 원문 요지, 2026-11-19)

참고 이미지: [`시안/참고_홈큐브_2026-11-19/`](시안/참고_홈큐브_2026-11-19/)

| 파일 | 무엇 |
| --- | --- |
| `배포화면_캡처.png` | 지금 운영 배포 홈(주인공 `산수` + 걸친 큐브 6곳) — 고칠 대상 |
| `cube_re.png` | 원하는 이름 표기: 작은 글자(`어린이`) + 큰 글자(`사직`) 두 줄 |
| `box.jpg` | 원하는 **밀도감**: 같은 크기 상자가 화면 밖으로 크게 잘려 이어짐, 이름이 윗면을 꽉 채움 |
| `fontsizePerBox.png` | 원하는 **이름 크기**: 상자 윗면 대비 `ewm` 글자 크기 |

1. **이름 위치·크기**: 도서관 이름은 윗면 **왼쪽 아래**, 지금보다 **훨씬 크게**. 화면의 무게중심(색·비주얼)이 "큐브"에서 "큐브 안의 이름(줄인 이름)"으로 옮겨 가게. 크기는 `fontsizePerBox.png` 수준 ~ 아주 조금 더 작게.
2. **두 줄 표기**: [큐브 이름 규칙 v2](진행_큐브이름규칙.md)가 끝나면 이름을 두 줄(작은 글자 + 큰 글자)로 쓴다(`cube_re.png`). 규칙 쪽 결정(취합 §6.1 D-a~D-f, §7.6 작은 글자 자리)을 따른다.
3. **배열과 "가장자리 보임"** (시안을 가장 많이 볼 부분):
   - 메인(주인공) 큐브를 더 키울 수 있어 보인다.
   - 그와 별개로 **주변 큐브는 훨씬 크게, 보이는 수는 줄인다.** 원한 것은 끄트머리가 살짝 보이는 **"공간의 연속성"**이다.
   - 위치 정보(모든 도서관의 방향)는 **내 위치(기점)를 눌러 전체 보기**에서 보이면 된다.
   - 지금은 "방향을 추상화해 달라"를 "주변 모든 도서관을 큐브로 그리고 방향이 반드시 보이게 전부 표시"로 처리한 느낌 — **원한 방향이 전혀 아니다.** 주변 큐브가 너무 작아 곁다리 돌멩이처럼 보인다. `box.jpg` 밀도의 절반도 안 된다.
4. **색**: 큐브와 SNS 피드 게시물 색이 너무 적다. **최소 12색.** 계획의 **마지막 단계**에 반드시 넣는다.

## 시안에서 볼 것 (중심 요소, 하나하나 따로)

`CLAUDE.md` 시안 규칙대로 후보 3개 HTML, 연속값은 기준 + 3단계. 위치: `개발산출물/시안/홈_큐브_개편_시안.html`(H1에서 만든다). 실제 광주 29곳·390×844/375×667 기준으로 그린다.

| 순서 | 중심 요소 | 이미 정해진 것(D) | 시안에서 고를 것 |
| --- | --- | --- | --- |
| E1 | **주변 큐브 배열** (가장 많이 봄) | 주변은 훨씬 크게·수는 적게, 끄트머리만 보이는 연속성, 정확한 방향은 전체 보기에서 | 후보 3개 예: ① 거의 같은 크기 이웃 2~3곳이 화면 밖으로 크게 잘림(`box.jpg` 격자) ② 주인공 중심 등각 격자에 이웃이 칸을 채움(방향은 사분면 정도만) ③ 주인공 최대 + 모서리 1~2곳만. 각 후보에 이웃 크기 배율·보이는 수·잘리는 비율·방향 반영 정도를 값으로 적음 |
| E2 | **주인공 크기** | 더 키울 수 있으면 키운다 | 기준(지금) + 3단계(예: 판 폭 대비 +10/+20/+30%). 기점 받침 자리를 어떻게 둘지(겹침 허용·위치 이동)를 단계마다 보여 줌 |
| E3 | **이름 크기** | 왼쪽 아래, `fontsizePerBox.png` 수준 ~ 조금 작게 | 기준 = `ewm` 비율(윗면 폭 대비 글자 폭·높이) + 3단계(-5/-10/-15%). 실제 px로 적음. 큰 글자 한 줄·작은 글자 + 큰 글자 두 줄 둘 다 그려 봄 |

- 시안 안의 `기본값(Claude)`: 옆면 글자(주소·TODAY·BEARING)의 크기·흐림, 걸친 큐브 옆면 글자 노출 여부, 큰 이름이 윗면을 넘칠 때 줄이는 규칙, 휴관 색.
- E1이 정해지면 계약 V3의 "가까운 7곳"·"0.45~0.62배"·"실제 방향 가장자리"·"이름 판 안 24px"가 바뀐다. D가 요구한 변경이라 계약서는 확인 없이 같이 고친다(D 메모리 `contract-edit-free-for-d-requests`), 보고에 한 줄.

- 한 단계가 파일 10개를 넘거나 계약서 밖 변경(DB 스키마 등)이 필요하면 멈추고 D에게 묻는다.
- 바꾸지 않는 것: 전체 보기(`ringScene`)의 "모든 도서관 방향 표시" 역할, 접근성 이름·찾기 창·하단 창의 원래 이름(`name`), 끌어서 주인공 바꾸기(`pickByDrag`) 동작 자체(배열이 바뀌면 끄는 방향 판정만 맞춤).
