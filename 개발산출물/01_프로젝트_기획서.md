# 01. 프로젝트 기획서

> 상태: **M1 범위를 요약한 부분은 승인된 02·계획(기준선 B0)을 따르고, 나머지는 초안**. 이 문서는 요약(파생) 문서라 [기준선](기준선.md)에 따로 싣지 않으며, 02·계획과 다르면 그쪽이 이긴다. 승인의 효력은 [기준선](기준선.md) §0에 선언일·승인자가 적힌 때부터이고, 그 전에는 전체가 초안이다. 이력(2026-11-11, 같은 날 개정: 도서관 방문·커뮤니티 중심으로 재배치). 원본 기획 자료와 [계획](../계획/상용_서비스_계획.md)·[요구사항](02_요구사항_정의서.md)을 요약한 문서다. 제품 동작의 기준은 02, 순서의 기준은 계획이다. 문제·기대 효과의 수치는 파일럿 전까지 검증되지 않은 가설이다.

## 1. 프로젝트명

**동네한권 (localone)** — 지역 도서관을 앱에서 "방문"하는 느낌으로 만나는 서비스. 지도에서 동네 도서관을 골라 들어가 이웃의 독서 기록과 핀터레스트형 게시물을 보며 다음 책을 찾고, 빌리는 책은 "빌렸어요" 한 번으로 반납 알림까지 받는다(iOS·Android 앱 중심, 웹은 같은 코드의 부연 출력). 저장소 `axteamc/localone`.

## 2. 배경

- 동네 도서관은 책을 빌리는 곳이지만, 같은 도서관을 쓰는 이웃이 무엇을 읽고 어떻게 느꼈는지는 보이지 않는다. 읽은 기록과 감상은 개인 메모·서비스에 흩어져 있다.
- 공공도서관의 소장·대출 가능 정보는 도서관·제공자마다 흩어져 있고, 책을 정한 뒤 어느 도서관에 가야 하는지 확인하는 과정이 번거롭다.
- 반납일은 기억에 의존해 반납 누락이 생긴다. 다만 이 서비스에서 반납 관리는 부담 없는 보조 기능이어야 한다.

## 3. 문제 정의

| # | 문제(가설) | 해결 방향 | 관련 요구사항 |
| --- | --- | --- | --- |
| P1 | 같은 동네 도서관을 쓰는 이웃의 독서 감상에서 다음 책을 찾기 어렵다 | 도서관을 "방문"하면 그곳의 광장(핀터레스트형 게시물)·방명록·오늘의 서가를 본다. 게시물의 책에서 대여 경로(우선)·구매로 이어진다 | VISIT-01~06, LOCAL-01~06 |
| P2 | 독서 모임·동네 독서 친구를 만나기 어렵다 | 도서관 기반 작은 모임과 이번 달 책 | CLUB-01~02 |
| P3 | 읽은 책 기록이 분산되고 도서관 단위로 돌아보기 어렵다 | 비공개 기록을 도서관별·전체로 모아 보고, 템플릿으로 꾸며 광장에 올릴 수 있다 | READ-01~02, LOCAL-07 |
| P4 | 책이 어느 도서관에 있고 빌릴 수 있는지 한 번에 알기 어렵다 | 책 검색 → 도서관 위치·거리 → 고른 책의 소장·대출 가능 조회. 상태·조회 시각·출처를 구분해 보여 준다 | LIB-01~05 |
| P5 | 반납일을 놓친다 | "빌렸어요"를 누르면 D-day 타이머가 돌고 D-3·D-1·당일에 기기 알림이 온다 | LOAN-01~05 |
| P6 | 공공 데이터는 개인 대출 원장이 아니고 갱신이 하루 단위일 수 있다 | '실시간'·개인 대출 자동 확정을 약속하지 않고 사용자 확인 + 출처·시각 표기 | 02 §7 |

## 4. 목적

1. **지역 도서관을 기반으로 한 소규모 독서 커뮤니티**를 앱에서 "방문"하는 경험으로 제공한다. 도서 탐색과 대출 관리는 이 경험을 돕는 기능으로 둔다(계획 §1 핵심 가치).
2. 사용자 A와 B의 데이터가 섞이지 않고, 공개·철회·삭제가 지켜지는 서비스를 만든다(02 §2~§3).
3. 자연스러운 움직임·조작감을 갖춘 앱을 iOS·Android·웹에서 공통 코드 한 벌로 만든다(D2-2).
4. 기획 → 명세서 → 계약서 → 구현 → 검증의 팀 작업 방식(`../team`)을 실제 산출물로 남긴다.

## 5. 대상 사용자

| 로그인 사용자 | 동네 도서관을 이용하는 독자. 게시물·방명록·모임 참여, 기록·빌릴 예정·대출 관리 | 02 §2 |

## 6. 주요 기능

| 기능 | 담당 | 설명 | 단계 |
| --- | --- | --- | --- |
| 도서 탐색 (LIB) | A | 도서 검색·상세, 도서관 위치·거리, 소장·대출 가능 조회, 빌릴 예정 | M1 |

| 작은 모임 (CLUB) | 미배정 | 도서관 기반 모임, 이번 달 책, 모임 게시물 | M2 |

| 앱 (MOBILE) | D + 미배정 | 설치·로그인 복귀, ISBN 스캔 | M3 |

## 8. 기대 효과 (가설)

- 책을 고르는 순간 이웃의 감상과 가까운 도서관의 소장 정보를 함께 만난다.
- 도서관별 독서 커뮤니티의 재방문과 게시물에서 도서 탐색으로 이어지는 전환(정량 목표는 파일럿 후 확정, 계획 §1).
- 반납 누락 감소(파일럿 기준선 수집 후 측정 지표 확정).

## 9. 개발 환경

| 영역 | 결정(D2, 2026-11-11) |
| --- | --- |
| 프론트·앱 | React Native + Expo + TypeScript, 웹은 `react-native-web` |
| 백엔드 | Python + FastAPI, SQLAlchemy |

| 알림 | 앱이 기기에 직접 예약하는 알림(서버 푸시 없음, C-11) |
| 협업 | 기획 → 명세서 → 계약서 → 구현 → PR 리뷰. 규칙은 비공개 `axteamc/team` |
| 일정 | 미결정(계획 §3) |

세부 버전·도구는 SET-1 명세에서 확정한다(미확정 항목은 [모호점 해소 기록](모호점_해소_기록.md)).
