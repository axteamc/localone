# 01. 프로젝트 기획서

> 상태: **초안 — 사용자 검토 전**(2026-11-11). 원본 기획 자료와 [계획](../계획/상용_서비스_계획.md)·[요구사항](02_요구사항_정의서.md)을 요약한 문서다. 제품 동작의 기준은 02, 순서의 기준은 계획이다. 문제·기대 효과의 수치는 파일럿 전까지 검증되지 않은 가설이다.

## 1. 프로젝트명

**동네한권 (localone)** — 동네 도서관에서 책을 찾고, 내가 확인한 대출과 반납 일정을 관리하고, 독서 기록과 이웃의 독서 카드로 다음 책을 찾는 서비스(iOS·Android 앱 중심, 웹은 같은 코드의 부연 출력). 저장소 `axteamc/localone`.

## 2. 배경

- 공공도서관의 소장·대출 가능 정보는 도서관·제공자마다 흩어져 있고, 책을 정한 뒤 어느 도서관에 가야 하는지 확인하는 과정이 번거롭다.
- 대출은 도서관 시스템에 있고 반납일은 기억에 의존해, 연체나 반납 누락이 생긴다.
- 읽은 기록과 감상은 개인 메모·서비스에 흩어져 있고, 같은 동네 도서관을 쓰는 이웃의 감상에서 다음 책을 발견하기 어렵다.

## 3. 문제 정의

| # | 문제(가설) | 해결 방향 | 관련 요구사항 |
| --- | --- | --- | --- |
| P1 | 책이 어느 도서관에 있고 빌릴 수 있는지 한 번에 알기 어렵다 | 책 검색 → 도서관 위치·거리 → 고른 책의 소장·대출 가능 조회. 상태·조회 시각·출처를 구분해 보여 준다 | LIB-01~04 |
| P2 | 반납일을 놓친다 | 사용자가 확인한 대출을 등록하고 D-3·D-1·당일 알림함·푸시로 알린다 | LOAN-01~05 |
| P3 | 읽은 책 기록이 분산되고 도서관 단위로 돌아보기 어렵다 | 비공개 기록을 도서관별·전체 서재로 모아 본다 | READ-01~02 |
| P4 | 이웃의 감상에서 다음 책을 찾기 어렵다 | 선택한 기록만 도서관 광장에 카드로 공개하고, 카드의 도서에서 소장 조회로 돌아온다 | LOCAL-01~03 |
| P5 | 공공 데이터는 개인 대출 원장이 아니고 갱신이 하루 단위일 수 있다 | '실시간'·개인 대출 자동 확정을 약속하지 않고 사용자 확인 + 출처·시각 표기 | 02 §7 |

## 4. 목적

1. 도서 탐색 → 대출·반납 관리 → 독서 기록 → 지역 공유가 이어지는 하나의 순환 여정을 앱으로 제공한다(계획 §1 핵심 가치).
2. 사용자 A와 B의 데이터가 섞이지 않고, 공개·철회·삭제가 지켜지는 서비스를 만든다(02 §2~§3).
3. 자연스러운 움직임·조작감을 갖춘 앱을 iOS·Android·웹에서 공통 코드 한 벌로 만든다(D2-2).
4. 기획 → 명세서 → 계약서 → 구현 → 검증의 팀 작업 방식(`../team`)을 실제 산출물로 남긴다.

| 로그인 사용자 | 동네 도서관을 이용하는 독자. 빌릴 예정·대출·기록·공개 카드 관리 | 02 §2 |

## 6. 주요 기능

| 기능 | 담당 | 설명 | 단계 |
| --- | --- | --- | --- |
| 도서 탐색 (LIB) | A | 도서 검색·상세, 지도·도서관 선택, 소장·대출 가능 조회, 빌릴 예정 | M1 |
| 반납 비서 (LOAN) | B | 대출 등록, 기한 수정·반납, 알림함·푸시 | M1 |
| 독서 기록 (READ) | C | 비공개 기록, 도서관별·전체 서재, 기초 통계 | M2 |
| 지역 독서 카드 (LOCAL) | C(예정) | 카드 공개·철회, 도서관 피드, 신고·운영자 숨김 | M2 |
| 기반·계정·엔진 (INIT·AUTH·RELEASE) | D | 실행 뼈대, 로그인, 공공 데이터 조회 엔진, 알림 작업자, 출시 관문 | M0~M3 |
| 앱 (MOBILE) | D + 미배정 | 설치·로그인 복귀, ISBN 스캔, 푸시 진입 | M3 |

## 8. 기대 효과 (가설)

- 책을 정한 뒤 도서관을 고르는 시간 단축.
- 반납 누락 감소(파일럿 기준선 수집 후 측정 지표 확정).
- 독서 기록의 재방문과 지역 카드에서 도서 탐색으로 이어지는 전환(정량 목표는 파일럿 후 확정, 계획 §1).
