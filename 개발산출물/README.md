# 개발산출물 목록

> 담당: D. 이 폴더는 **제품·프로젝트 차원의 산출물과 D의 작업 기록**이다. 기능별 명세서·시안·검증(`specs/<기능>/`)은 팀원이, 계약서(`../team/contracts/`)와 팀 규칙은 team 레포(비공개)에 있다. 문서 역할 기준은 `../team/docs/문서_운영.md`.
> 상태: **작성됨**(내용 있음, 사용자 검토 전) / **골격**(구조·선행·시점만 있음, 내용은 선행 조건 후) / **운영**(계속 갱신).

**상태 읽는 법(공통 6단계).** 문서마다 쓰는 낱말은 그대로 두고 아래 단계에 대응시킨다. 파일이 `main`에 있다는 것과 승인됐다는 것은 다르다: `specs/`·`../team/contracts/`는 머지 = 승인이고, 이 폴더와 `계획/`의 제품 문서는 [기준선](기준선.md)에 실려 선언된 범위만 승인이다.

| 공통 단계 | 뜻 | 계약으로 취급 | 기존 낱말과의 대응 |
| --- | --- | --- | --- |
| 초안 | 내용은 있으나 승인자가 보지 않았다 | 아니오 | 이 목록의 `작성됨`, 명세서 `작성 중`, Draft PR. `골격`은 초안 이전 |
| 검토 요청 | 승인자에게 넘겼다 | 아니오 | PR Ready(수정 요청 중 포함) |
| 승인(기준선) | 승인자가 승인했고 기준선 문서에 실렸다 | **예** | 명세서 `승인(머지됨)`, 추적표 `명세`·`계약`, 제품 문서 머리말의 `확정(기준선 B0)`(= M1 기준선 확정, C-53) |
| 구현 중 | 승인된 계약으로 파트가 진행 중 | 예 | 추적표 `구현`, 계획 `진행` |
| 검증됨 | 완료 판정 증거가 있다(`../team/docs/문서_운영.md` §2) | 예 | 추적표 `검증`, 계획 `완료` |
| 대체됨 | 더 새로운 결정이 이 내용을 이긴다 | 아니오(무엇이 대체했는지 링크) | 모호점 `→ Q-n`, 명세서 `이전 버전` |

`운영`은 단계가 아니라 계속 갱신하는 기록 문서라는 뜻이다.

## 3. 작업 기록 (D)

`인수인계_메모.md`(PC·세션 간 현재 상태), `진행_<작업>.md`(진행 중 작업), `명세/`(Step 구현 명세, 필요할 때), `결과/`(실행·검증 결과), `완료/`(끝난 진행 파일·옛 문서). 일일 개발 로그는 [작업일지](작업일지.md)가 맡고(git·PR에서 뽑아 작업자별로 정리), 일정과 도달 여부는 [일정 및 도달 점검](일정_및_도달점검.md)에서 본다. 기능별 상세는 기능 명세서의 `구현 진행 상태`에 있다.
