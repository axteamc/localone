# 병렬 작업 — 페이지 디자인 홈 기준 맞추기

만든 날: 2026-11-18 (win, D). **임시 폴더다.** 일이 다 끝나면 이 폴더의 파일을 모아 `개발산출물/완료/병렬작업_페이지디자인_결과.md` 하나로 합치고 **이 폴더는 삭제한다**(아래 "끝낼 때").

배경: 페이지 디자인 1차(`../진행_페이지디자인.md`, 기준 `../../DESIGN.md` "원칙 (확정)"·"페이지 적용 레시피")에서 할 일이 많이 남아, 여러 AI 세션이 동시에 나눠 한다. 같은 파일을 여러 세션이 고치면 충돌하므로 **레인마다 자기 진행 파일 하나만** 쓴다.

## 지킬 규칙

1. **내 레인 파일만 고친다.** 이 폴더의 `진행_<레인>.md`는 그 레인 담당 세션만 쓴다. 다른 레인 파일은 읽기만.
2. **공용 파일은 D 세션만 고친다.** `DESIGN.md`, `개발산출물/디자인_기준.md`, `개발산출물/진행_페이지디자인.md`, `개발산출물/인수인계_메모.md`, `개발산출물/00_기획_원본.md` 이력, `README.md`(이 파일의 표). 레인 세션은 이 파일들을 **고치지 않고**, 자기 진행 파일의 "D 세션에 넘길 것" 절과 PR 본문 `📝 검토 메모`에 적는다. D 세션이 모아서 반영한다.
3. **`mobile/src/theme/`는 L1만 고친다.** 다른 레인이 새 헬퍼나 토큰이 필요하면 `진행_<레인>.md`에 적고 L1에 넘긴다(직접 고치지 않는다).
4. **계약서(`../team/contracts/`)는 D(또는 D 요청을 받은 D 세션)만 고친다.** 레인 세션이 계약과 어긋나는 걸 발견하면 멈추고 D에게 묻는다. D가 직접 요구한 수정에 필요한 계약 변경은 확인 없이 바로, 보고에 한 줄.
5. **브랜치는 `design/<이름>`, PR은 레인(또는 페이지) 하나에 하나.** 파일이 10개를 넘으면 먼저 D에게 묻는다. 머지는 D만 한다.
6. **시작 전에** 내 레인 파일의 "선행 조건"을 확인한다. 선행이 아직이면 시작하지 않고 D에게 알린다.
7. **끝나면** 내 레인 파일 맨 위 "상태" 줄과 "진행 기록"을 실제와 맞춘다. 이력은 git에 있으니 기록은 짧게.
8. 시안은 HTML 파일 하나(외부 이미지·글꼴 연결 없음), 중심 요소만 후보 3개, 추천 하나, 명세 패널, 브라우저로 열어 보여 주고 질문으로 끝낸다(루트 `CLAUDE.md` "시안 규칙"). **D에게는 선택 이유를 묻지 않는다**(메모리 `d-no-reason-asking`).
9. 이미 정해진 기준은 다시 묻지 않는다: 홈 큐브 파사드(C2) · 글자 2단계 · 곡률 위계(판 3 · 카드·입력 9 · 18은 게시물·모임 카드만) · 주 버튼은 무광 판(`panelLit` + 줄눈 + 아래 2px 받침) · 보조 버튼은 평평한 회색 판 · 검정 + 노랑은 **로고에만** 피함.

## 공통 환경 (win)

- gh: 기본 `choise-hun`. `axteamc` 레포 작업에서만 `Hunseokc`로 바꾸고 끝나면 `choise-hun`으로 복구.
- 웹 확인은 `mobile`에서 `EXPO_PUBLIC_API_URL=http://localhost:8000 npx expo start --web`(`.env`의 주소는 핫스팟 IP). 시험은 `npx tsc --noEmit`, `npx jest`, `npm run e2e:web`.
- 이 PC의 로컬 DB는 시험 데이터라 visit·compose·detail 화면은 웹 검사에서 데이터 없음으로 실패한다(디자인과 무관). 그 화면은 스크린샷을 직접 본다.
- 세션이 시작되면 `git pull`로 최신 main을 받고, 이 폴더가 있는 브랜치(문서 PR 머지 뒤 main)에서 시작한다.

## 진행 순서

1. **D(L0):** 문서 브랜치 `design/page-pass-1` push → PR → D가 머지. 로고 선택(로고 시안 G1~G6·I1~I9).
2. **동시에 시작:** L1, L2, L3a·L3b·L3c. 서로 파일이 겹치지 않는다(L1 = `theme/`, L2 = `library-visit/`, L3 = 시안 HTML만). D 결정이 병목이니 L3는 한 번에 2~3개까지만.
3. **L1 머지 뒤:** L3에서 결정이 난 페이지부터 L4를 하나씩 시작. 로고가 정해졌으면 L5도 시작.
4. **머지 순서:** L1 → (L2, L4 페이지들, 순서 무관) → L5 → L6. 각 브랜치는 직전 머지된 main에서 pull한 뒤 시작.
5. 이 사이 L0(D 세션)가 공용 문서를 합쳐 갱신한다.

L2 + L4가 같은 파일을 만질 수 있는 곳: 홈의 "도서관 찾기" 버튼은 L2(`HomeScreen.tsx`)가 맡는다. L4는 홈 파일을 건드리지 않는다.

## 끝낼 때 (D 세션)

1. 모든 레인의 "상태"가 완료(또는 D가 접기로 한 것)인지 확인.
2. 레인 파일들의 "진행 기록"·"D 세션에 넘길 것"을 모아 `DESIGN.md`(결정 기록·레시피)·`디자인_기준.md`·`진행_페이지디자인.md`·`인수인계_메모.md`·`00_기획_원본.md` 이력에 반영.
3. 이 폴더 파일을 한 문서 `개발산출물/완료/병렬작업_페이지디자인_결과.md`로 모은다(레인별 한 절, 결과·검증·남은 것). 이 README의 규칙·표는 맨 위 한 절로 요약.
4. **이 폴더를 삭제**하고 `진행_페이지디자인.md`의 링크를 완료 문서로 바꾼다. 커밋.
