# 계약 제안 (`contracts/`)

세부 기능(Step)의 기술 계약 **검토 전 제안**을 두는 곳이다. 여기 있는 문서는 구현 기준이 아니다.

## 위치와 상태

| 무엇 | 경로 | 상태 |
| :--- | :--- | :--- |
| 제안 양식 | `contracts/제안_양식.md` | 양식 |
| Step별 제안 | `contracts/proposals/<기능>/<STEP>.md` | `검토 전·구현 착수 불가` |

- 제안 하나는 Step 하나만 다룬다. 다른 Step·다른 기능의 계약 내용을 복제하지 않는다.
- 제안은 별도 브랜치 `contract/<역할>-<STEP>`에서 `main`으로 PR을 연다. PR 제목은 `[계약 제안] <STEP>`이다.
- 같은 Step의 기획 PR(`specs/<기능>/세부/<STEP>.md`)과 서로 링크한다.
- 시니어 검토·승인 뒤 승인된 내용이 발행 계약에 반영된다. 승인·발행 전에는 이 제안을 근거로 구현하지 않는다.

## 고정된 것과 채우는 것

- 1차 계약 기준선에서 정한 경로·메서드·인증·성공 상태·필드/타입·오류 코드·기기 저장 키·테이블·플랫폼 분기·의존/가짜 값·담당 파일·파트·선행 관계는 **바꾸지 않는다**.
- 기준선에서 "세부 명세에서 정할 것"으로 열어 둔 동작·배치·문구·길이·기본값만 세부 명세의 결정·예외로 채운다.
- 열린 칸 밖에서 필요한 변경은 본문을 고치지 않고 PR의 `D 판단 쟁점`에 `[계약 보완 필요]` 또는 `[기준 충돌]`로 근거·영향·추천안을 적는다.
- `05_ERD_및_DB설계서.md`·`06_기능_API_정의서.md`·`02_요구사항_정의서.md`가 원본이다. 제안에서 먼저 바꾸지 않는다.

## 넣지 않는 것

- 토큰·비밀값·개인 정보·내부 대화 기록
- 아직 없는 코드를 있는 것처럼 쓴 `file:line`
- 실행하지 않은 테스트의 통과 결과(테스트는 설계만 적는다)
