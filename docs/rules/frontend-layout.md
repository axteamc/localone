# 프론트엔드 반응형 정렬 규격 및 레이아웃 검사 가이드 (Layout Specification)

화면을 만들거나 고칠 때 **배치 약속(`data-align-group`)을 먼저 선언하고 → 화면 검사(`layout.spec.js`) 통과 → 4개 폭 스크린샷 검토**로 완성도를 보장하는 프론트엔드 품질 가이드입니다.

자동 검사는 "기하학적 깨짐"을 잡고, 사람이 정한 배치 약속과 스크린샷 검토가 "디자인 위계와 자연스러움"을 보증합니다.

| 층 | 무엇을 잡나 | 어디에 있나 |
| --- | --- | --- |
| **① 공통 검사 G0~G8** | 넘침·형제 겹침·글자 잘림·가로 스크롤·금지 색·처짐·터치 크기(WCAG 2.5.8)·간격 | `guardrails/layout/layout-check.js` (화면과 무관한 DOM 기하학 검사) |
| **② 배치 약속 A1** | "이 컴포넌트와 저 컴포넌트는 윗선·아랫선·높이를 맞춘다" | 마크업 속성 `data-align-group` (컴포넌트 코드 안) |
| **③ 스크린샷 검토** | 여백 균형·시각적 위계·빈 상태 자연스러움 | 4개 폭(390·768·1150·1280) 전체 캡처 + 9대 질문 목록 |

---

## 1. 작업 순서 (새 화면 개발 및 배치 변경 시)

1. **배치 약속을 먼저 정의한다**:
   - 폭별 열 구성: 모바일(390) 1열, 태블릿(768), 데스크톱(1150·1280) 다열 구성 확정
   - 맞춤 그룹: 나란히 배치되는 카드 간의 윗선·아랫선, 본문 내 텍스트와 버튼의 시작선 등
2. **spec을 먼저 작성하고 실패를 확인한다**:
   - `test/e2e/layout/<화면>.spec.js`를 만들고 실행하여, 미구현 상태이거나 기존 깨짐이 실패 문구로 출력되는지 확인한다.
3. **구현한다**:
   - HTML 마크업에 `data-align-group` 속성을 함께 선언한다.
4. **검사를 통과시킨다**:
   - `npx playwright test test/e2e/layout/<화면>.spec.js` 실행 시 실패 0건(Pass) 확인.
5. **스크린샷을 검토한다**:
   - `LAYOUT_SHOTS=1` 옵션으로 4개 폭 스크린샷을 저장하고, §6의 질문 목록으로 이상 유무를 점검한다.
6. **불가피한 예외는 사유를 명시한다**:
   - `data-layout-ignore="<규칙ID>: <명확한 사유>"` 형태로 코드에 기록한다.

## 2. 배치 약속 선언 (`data-align-group`)

### 형식
```html
data-align-group="<그룹이름>:<맞출선>[,<맞출선>...][@<최소폭>]"
<!-- 여러 그룹에 속할 경우 세미콜론(;)으로 연결 -->
data-align-group="row1:top,bottom@821; buttons:height"
```

| 맞출 선 | 판정 기준 (오차 허용 1px) |
| --- | --- |
| `top` · `bottom` | 윗선·아랫선 Y 좌표가 일치하는가 |
| `left` · `right` | 왼쪽선·오른쪽선 X 좌표가 일치하는가 |
| `height` · `width` | 높이·폭이 일치하는가 |
| `center-x` · `center-y` | 가로·세로 중심선이 일치하는가 (예: 컨테이너와 버튼의 중심 일치) |

- **그룹 이름**: 화면 내에서 고유한 식별자 (`topCardRow`, `actionBtns` 등).
- **반응형 자동 무시**: `top`, `bottom`, `height` 등은 요소들이 **옆으로 나란히 있을 때만** 판정하며, 모바일 폭(390px 등)에서 세로 1열로 떨어지면 자동으로 비교를 생략합니다.
- **`@<최소폭>` (선택)**: "이 폭 이상에서는 반드시 1열로 무너지지 않고 나란해야 한다"를 강제할 때 붙입니다 (예: `@769`는 769px 이상에서 세로로 쌓이면 실패로 판정).

### 예시
```tsx
<div className="grid">
  {/* 두 카드의 윗선과 아랫선은 나란할 때 항상 같아야 함 */}
  <section className="card" data-align-group="mainCards:top,bottom">
    <div data-align-group="cardContent:top">...</div>
  </section>
  <section className="card" data-align-group="mainCards:top,bottom">
    <div data-align-group="cardContent:top">...</div>
  </section>
</div>
```

## 3. 예외 표기 (`data-layout-ignore`)

디자인상 의도된 넘침이나 말줄임에는 예외를 명시합니다:
```html
data-layout-ignore="<규칙 ID>: <사유>"
<!-- 예: 말줄임이 의도된 경우 -->
<p className="truncate" data-layout-ignore="G3: 한 줄 고정 말줄임 레이아웃">제목...</p>
```
> **주의:** 사유가 누락되었거나 없는 규칙 ID를 쓰면 G0 실패로 간주됩니다.

## 4. 공통 검사 규칙 (G0 ~ G8)

Playwright 테스트 실행 시 `layout-check.js`가 브라우저 DOM을 순회하며 다음 규칙을 자동 검출합니다:

| ID | 규칙명 | 검사 내용 | 판정 기준 |
| --- | --- | --- | --- |
| **G0** | 표기 문법 오류 | `data-align-group`이나 `data-layout-ignore`의 형식 오류 또는 미존재 규칙 ID 검출 | 형식 오류 시 실패 |
| **G1** | 카드 밖 넘침 | 자식 요소가 부모 카드 바깥으로 삐져나갔는지 검사 | 오차 > 0.5px 실패 |
| **G2** | 형제 요소 겹침 | 같은 부모 아래 나란한 형제 요소끼리 시각적 렌더링 영역이 포개지는지 검사 | 겹침 > 0.5px 실패 |
| **G3** | 텍스트 잘림 | 텍스트를 가진 요소의 `scrollWidth > clientWidth` 또는 세로 줄바꿈 잘림 발생 여부 | 1px 초과 시 실패 |
| **G4** | 가로 스크롤 | 페이지 전체에서 의도치 않은 가로 스크롤(`document.scrollWidth > clientWidth`) 발생 여부 | 0px 초과 시 실패 |
| **G5a** | 금지 색상 사용 | 화면 옵션(`forbidColors`)으로 지정된 특정 색상 토큰(예: 브랜드 외 파란색 등) 검출 | RGB 일치 시 실패 |
| **G5b** | 팔레트 밖 색상 | 테마 토큰(`tokens.css`) 팔레트에 없는 임의의 RGB 색상 사용 검출 | 경고 (Warning) |
| **G6** | 카드 내용 처짐 | 카드 안에서 첫째 자식과 둘째 자식 간 간격이 과도하게 벌어져 아래로 처지는 현상 | 간격 > 24px 실패 |
| **G7a** | 터치 영역 최소 | 버튼/링크/인풋의 터치 타깃이 24×24px 미만인지 검사 (WCAG 2.5.8 간격 예외 적용) | < 24px 실패 |
| **G7b** | 모바일 터치 권장 | 모바일(390·768px) 폭에서 인터랙션 요소 높이가 44px 미만인지 검사 (iOS 권장치) | < 44px 경고 |
| **G8** | 간격 스케일 불균일 | 8pt/4pt 디자인 그리드 스케일(`0, 2, 4, 8, 12, 16, 24, 32, 48...`)을 벗어난 임의 마진/패딩 검출 | 경고 |

## 5. 자주 발생하는 레이아웃 결함 패턴과 처방

1. **카드의 `justify-content: space-between` 남용**:
   - 증상: 내용이 카드 바닥으로 과도하게 처져 G6 실패 발생.
   - 처방: `flex-start`를 기본으로 하고, 바닥에 고정할 요소만 `margin-top: auto` 적용.
2. **그리드 칸보다 넓은 자식 고정폭 (`width: 120px`)**:
   - 증상: 좁은 화면에서 옆 칸 자식과 겹쳐 G2 실패 발생.
   - 처방: 고정폭 대신 `width: 100%` + `max-width` 및 `minmax(0, 1fr)` 사용.
3. **`align-items: center`로 인한 윗선 어긋남**:
   - 증상: 썸네일 이미지와 옆 텍스트의 윗선이 몇 픽셀 어긋남.
   - 처방: 시작선 정렬 시 `align-items: flex-start` 적용.
4. **단추/링크 텍스트 한 줄 넘침**:
   - 증상: 모바일 390px에서 버튼 텍스트가 두 줄로 꺾여 덩어리가 됨.
   - 처방: 텍스트를 간결화하거나 폰트 크기/패딩을 반응형 변수로 조절.

## 6. 스크린샷 9대 질문 검토 (인간 및 멀티모달 점검)

`LAYOUT_SHOTS=1`로 캡처된 4개 폭(390, 768, 1150, 1280) 스크린샷을 다음 질문으로 점검합니다:

- **Q1 (주목도):** 첫눈에 가장 중요한 주 행동(Primary CTA) 버튼 하나가 뚜렷이 보이는가?
- **Q2 (균형):** 동일한 위계의 카드/칸 사이 여백이 균등한가? 한쪽에만 큰 빈 공간이 덩어리져 있지 않은가?
- **Q3 (기준선):** 제목선, 본문 시작선, 버튼 줄이 눈에 띄게 어긋나 있지 않은가?
- **Q4 (시각 위계):** 크기·굵기·명도(검정·회색)로 정보 위계가 분리되어 있는가? (색상에만 의존하지 않는가?)
- **Q5 (빈 상태):** 데이터가 없는 빈 상태(Empty state)가 고장난 화면처럼 보이지 않고 명확한 유도 안내를 제공하는가?
- **Q6 (반응형 흐름):** 390px에서 세로로 떨어졌을 때 정보의 읽기 순서가 자연스러운가? 768px에서 어색한 빈 여백이 없는가?
- **Q7 (색상 절제):** 불필요한 유채색 남발 없이 브랜드 포인트 색상이 절제되어 쓰였는가?
- **Q8 (스타일 통일):** 컨트롤(버튼/입력창)과 컨테이너(카드/패널)의 모서리 곡률(Border-radius) 컨벤션이 일관된가?
- **Q9 (다크모드):** 다크 모드에서 컨테이너 경계와 글자 명도 대비가 충분히 확보되는가?
