## 1. 프로젝트 개요와 목표

- 서비스명(초안): **동네한권 (localone)**. 저장소는 `axteamc/localone`.
- 동네 도서관에서 책을 발견하고, 자신의 대출·독서 기록을 관리하며, 이웃의 독서 감상을 통해 다음 책을 찾는 서비스다.
- 핵심 가치: 도서관별 도서 탐색 → 본인이 확인한 대출과 반납 일정 관리 → 선택적으로 공개한 독서 카드에서 다시 도서 탐색으로 이어지는 순환.
- 앱 중심(React Native + Expo, D2-2 확정)이며 웹은 같은 코드의 부연 출력이다. 실행 뼈대(INIT)는 처음부터 앱 기준으로 만들고, MOBILE Feature는 설치·스토어·카메라 스캔·푸시를 맡는다.
- 기존 북마크 수집·태그·확장 프로그램 계획은 초기 템플릿이다. 새 도서관 서비스 요구로 대체하며 별도 북마크 제품은 만들지 않는다. README의 기존 설명은 이번 범위 밖으로 남아 있다.
- 성공 판정 초안: 사용자가 도서·도서관을 찾고, 반납일을 직접 확인한 대출을 등록하고, 반납 처리까지 마친다. 이후 공개 독서 카드에서 해당 책을 탐색할 수 있다. 정량 전환율·유지율·비용 목표는 파일럿 기준선 수집 후 확정한다.

## 2. 대기능 로드맵

상태는 `대기 / 진행 / 완료`. 아래 Step은 **예상 경계**이며 파일·diff 산정 전 구현 확정으로 간주하지 않는다. 담당 역할은 `../team/기능_배정.md` 기준이다.

| Feature ID | 독립된 완료 가치 | 예상 Step | 담당 | 선행 | 단계/상태 |
| --- | --- | --- | --- | --- | --- |
| INIT | 개발자가 재현 가능한 실행 환경을 얻는 기술 기반(제품 Feature의 예외) | 3: SET-0 규칙(완료), SET-1 기획·D2·명세, SET-2 스캐폴딩·CI | D | 없음 | 기반 / 진행 |
| AUTH | 가입·로그인 후 자신의 계정을 안전하게 사용하고 종료한다 | 3: AUTH-1 가입·로그인, AUTH-2 세션 갱신·로그아웃, AUTH-3 탈퇴·데이터 처리 | D | INIT | 파일럿 / 대기 |
| LIB | 도서 검색부터 주변 도서관의 소장·대출 가능 정보 확인까지 마친다 | 3: LIB-1 도서 검색·상세, LIB-2 지도·도서관 선택·상태 조회, LIB-3 빌릴 예정 저장·조회 | A (조회 엔진 D) | INIT; 개인 저장은 AUTH | 파일럿 / 대기 |
| LOAN | 대출을 등록하고 반납 예정 알림을 받아 반납까지 관리한다 | 3: LOAN-1 수동 대출 등록, LOAN-2 기한 수정·반납 처리, LOAN-3 알림함·반납 알림 | B (알림 작업자 D) | AUTH, LIB | 파일럿 / 대기 |
| READ | 개인 독서 기록을 남기고 도서관별·전체 서재에서 다시 찾는다 | 2: READ-1 비공개 기록 작성·조회, READ-2 도서관별/전체 필터·기초 통계 | C | AUTH, LIB; 대출 연결은 LOAN | 공개 베타 / 대기 |
| LOCAL | 도서관 이웃에게 독서 카드를 공개하고 다음 읽을 책을 발견한다 | 3: LOCAL-1 카드 작성·공개·철회, LOCAL-2 도서관 피드·상세·도서 연결, LOCAL-3 신고·운영자 숨김 | C (예정, 운영자 기능 D) | READ, LIB, AUTH | 공개 베타 / 대기 |
| MOBILE | iPhone에서 설치한 앱으로 도서관 이용 흐름을 완료한다 | 3: MOBILE-1 설치·로그인 복귀, MOBILE-2 ISBN 촬영 등록, MOBILE-3 네이티브 반납 푸시·알림 진입 | D(iOS 서명·푸시) + 미배정 | LIB, LOAN, INIT의 Expo 뼈대; 스토어 출시는 RELEASE | 앱 후보 / 대기 |
| RELEASE | 이용자가 장애 대응·삭제·신고 경로를 갖춘 서비스를 지속 이용한다 | 3: RELEASE-1 운영 배포·복구 리허설, RELEASE-2 제한 파일럿·관측, RELEASE-3 공개 출시 검수 | D | AUTH, LIB, LOAN; 공개 SNS는 LOCAL, 앱은 MOBILE 추가 | 상용 관문 / 대기 |

AUTH·INIT·RELEASE는 여러 제품 여정의 공통 기반이며 이를 임의의 UI/DB/서버 Feature로 더 쪼개지 않는다. READ는 비공개 기록 회고, LOCAL은 공개 발견·교류라는 별도 완료 가치를 가진다. 지도·바텀 시트·API·알림함은 각 여정 내부 구성이고 별도 Feature가 아니다.

### Step 크기 점검과 착수 관문

- 8개 대기능 모두 예상 Step 2~3개, 최대 4개를 넘지 않는다.
- 각 Step은 화면 또는 하나의 E2E로 확인 가능한 사용자 행동 하나를 담는다. DTO·CSS·DB만의 별도 Step을 만들지 않는다.
- 기능 명세서(주니어)가 승인되면 D가 계약서에서 Step을 파트(PR 하나)로 나눈다. 파트 크기는 `../team/docs/문서_운영.md` §3(파일 ≤7개, 예상 변경 ≤600~700줄, 독립 확인 가능)을 따른다. 현재 소스가 없어 실제 규모는 미산정이다.
- 상한을 넘으면 우선 부가 기능을 대기로 돌리거나 인접 경계를 재조정한다. 여전히 넘으면 최대 4개 안에서 재설계하며, 독립 사용자 가치가 입증되지 않은 Feature 분할은 금지한다. 숫자만 충족한 상태로 구현을 승인하지 않는다.
- 화면 공통 디자인·접근성은 각 Step의 완료 조건으로 포함한다. 여러 화면 완성을 단일 UI Step으로 묶지 않는다.
- D는 소유권·늦은 응답·외부 I/O·오류 경계를 계약서로 정하고 공통 엔진(조회·알림 작업자)·AUTH를 맡는다. 기능 내부 동작은 담당 주니어의 명세서로 정한다.

## 3. 마일스톤과 출시 관문

1. **M0 기반:** SET-0 완료 확인 → 이번 SET-1 기획 검토 → D2 선택 → SET-1 세부 명세 승인 → SET-2. 기획 초안만으로 스캐폴딩을 시작하지 않는다.
2. **M1 제한 파일럿:** AUTH + LIB + LOAN. 지도/서지 제공자의 데이터 범위·갱신 주기·사용 조건을 확인하고, 사용자 A↔B 격리 및 대출→알림→반납 여정을 검수한다. RELEASE-1/2로 제한 운영한다.
3. **M2 공개 베타:** READ + LOCAL. 비공개 기본값·공개 철회·신고 처리를 검수한 뒤 공개 커뮤니티를 연다. 홈의 두 탭 경험도 여기서 완성된다.
4. **M3 상용 공개/앱:** RELEASE-3는 백업 복구, 비밀값·권한, 삭제 정책, 외부 서비스 비용 상한, 장애 안내·신고 대응 담당 확인 후 진행한다. 앱을 함께 출시할 경우 MOBILE 실기기 검수·심사 준비를 추가 선행으로 둔다. 웹 출시와 앱 출시는 각각 판정한다.

날짜·유료화·출시 지역/도서관 범위는 미결정이다. 모바일 개발은 D2 선택에 따라 M2와 병행할 수 있으나 별도 실행 승인이 필요하다.
